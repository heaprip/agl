# Казус: закон всемирного тяготения из истории с яблоком

**Черновик. Не принято.** Одноразовая нотация. Цель — проверить, хватает ли
метаядра-кандидата, а не записать физику красиво. Всё, что пришлось добавить,
записано в журнал нагрузки в конце.

## Метаядро-кандидат на входе

| # | Примитив | Смысл |
| --- | --- | --- |
| K1 | отношение | `R` — тип отношения |
| K2 | роль | у `R` есть роль `r` |
| K3 | тождество | `same(a, b)` |
| K4 | эпистемический статус | миф, свидетельство, измерение, теория… |
| K5 | плоскость | размытая область; между плоскостями отношения RCC-8 |

Сортов нет: сорт выводится из того, какие роли занимает сущность.

Нотация: `id: R(роль: значение, …)`. Идентификатор есть у каждого факта, поэтому
на факт можно сослаться из другого факта (реификация).

## 1. Рассказ

```
a1: fall(object: apple₁, from: tree₁, toward: earth)
a2: notice(agent: newton, content: a1)
a3: ask(agent: newton, content: q1)
q1: why(about: a1, aspect: direction)      # «почему перпендикулярно к земле, а не вбок»
```

Первая нагрузка. Пишем `a1` — и тем самым утверждаем, что яблоко упало?
Нет: это рассказ. Значит, **голых утверждений быть не должно.** Любой факт
действует только в плоскости и только с каким-то статусом:

```
holds(claim: a1, plane: P_narr, status: anecdote)
holds(claim: a2, plane: P_narr, status: anecdote)
src1: told(teller: newton, hearer: stukeley, when: 1726)
src2: published(work: stukeley_memoirs, when: 1752, contains: a1)
provenance(claim: a1, source: src1)
provenance(claim: a1, source: src2)
```

`apple₁` — яблоко из рассказа. `same(apple₁, x)` нет ни для какого реального `x`,
и это **неизвестность, а не «различны»**. Тождество работает в открытом мире:
то, чего нет в базе, неизвестно, а не ложно.

## 2. Сущности без сортов

```
b1: mass_of(body: newton, value: q_m_newton)
b2: discover(agent: newton, claim: L1, when: 1687, via: principia)
```

`newton` занимает роль `agent` в `discover` и роль `body` в `mass_of`. Сорт
«человек» нигде не объявлен. Он выводится как «то, что занимает роль `agent`
в отношениях познания». Ньютон при этом сам попадает под собственный закон —
и это не требует ничего особенного.

То, что лежит под «человеком» (организм, клетки, вещество), — это цепочки
`part_of` и `composed_of`. Это обычные данные, в ядро они ничего не добавляют.

## 3. Идеализация

```
m1: models(model: pm_apple, target: apple₁, plane: P_newton)   # яблоко как точечная масса
m2: models(model: pm_earth, target: earth,  plane: P_newton)   # Земля как точка в центре
s1: shell_theorem(body: earth, justifies: m2)
```

Вторая нагрузка. `pm_apple` **не тождественно** `apple₁`, поэтому K3 тут не
подходит. Нужно «представляет в плоскости», и это обычное отношение. Но сразу
встаёт вопрос: что из верного для `pm_apple` переносится на `apple₁`? Ответ:
только внутри `P_newton` и только по правилу. **А правил в метаядре нет.**

## 4. Закон как отношение

```
L1: gravity(m1: ?a, m2: ?b, r: ?r, force: ?f)
    ⇐ ?f = G · ?a · ?b / ?r²
holds(claim: L1, plane: P_newton, status: theory)
```

Третья нагрузка, сразу тройная:

- **правило с переменными** («для всех тел») — без него закон не записать;
- **числа и арифметика** — ядро их не знает;
- **размерности** — в `[кг·м/с²]` должно получаться `[кг·м/с²]`. Это жёсткая
  проверка ствола того же рода, что баланс масс.

Плюс relation-first здесь виден буквально. `gravity` — отношение, а не функция:
по силе и массам оно даёт расстояние так же, как по расстоянию даёт силу.

## 5. Проверка на Луне — то, что Ньютон сделал на самом деле

```
d1: measured(quantity: g_surface,  value: 9.81 м/с²)
d2: measured(quantity: r_moon,     value: 60.3 R_earth)
d3: measured(quantity: T_moon,     value: 27.32 сут)
holds(claim: d1, plane: P_lab,   status: measurement)
holds(claim: d2, plane: P_solar, status: measurement)
holds(claim: d3, plane: P_solar, status: measurement)

pred: a_moon = g / 60.3²      = 2.70·10⁻³ м/с²     # из L1
obs:  a_moon = 4π²·r / T²     = 2.72·10⁻³ м/с²     # из d2, d3
```

Расхождение — около 1%. **Совпадает ли это?** Ответ зависит от того, какой
точности требует вопрос. Ни K4, ни K5 этого не говорят.

## 6. Плоскости

```
P_newton  — слабое поле, v ≪ c
P_GR      — общая теория относительности
P_cosmo   — ΛCDM
P_narr    — биографический рассказ

ntpp(P_newton, P_GR)      # Ньютон — предел ОТО, строго внутри
po(P_newton, P_cosmo)     # ньютоновские N-body внутри горизонта
ntpp(P_lab, P_newton)
ntpp(P_solar, P_newton)   # …почти — см. Меркурий
```

Четвёртая нагрузка. **Как соотносятся `P_narr` и `P_newton`?** Ни одно отношение
RCC-8 тут не подходит. Это не «не пересекаются», а **разные оси**: масштаб и
режим против рода речи. RCC работает внутри одного пространства. Значит,
плоскость — область в произведении нескольких осей (те самые гиперсферы),
а RCC считается по каждой оси или в произведении.

Пятая нагрузка — Меркурий:

```
d4: measured(quantity: mercury_perihelion_anomaly, value: 43″/век)
holds(claim: d4, plane: P_solar, status: measurement)
pred_newton: 0″/век сверх возмущений от планет
```

Для Меркурия `GM/(r·c²) ≈ 2.5·10⁻⁸` — поле крайне слабое, формально мы глубоко
внутри `P_newton`. И всё же противоречие реальное. **Граница плоскости зависит
не только от режима, но и от точности, которую требует вопрос.** При точности
в угловые секунды за век Меркурий выходит за `P_newton`, при точности в
проценты — нет. Допуск — часть плоскости вопроса.

## 7. Время

`when: 1687` — это просто роль. Но «закон верен с 1687-го» — бессмыслица: закон
**известен** с 1687-го, а действует всегда, в своей плоскости. Получается два
времени:

- время действия — это ось плоскости, наряду с масштабом;
- время знания — это провенанс (`discover`, `published`).

Это та же битемпоральность из §5 исходных заметок. Только здесь она не
объявлена отдельно, а получилась сама из `holds` и `provenance`.

## Итог казуса

Вошло пять примитивов. Вышло:

- **ядро:** отношение, роль, тождество (открытый мир), `holds` (плоскость и
  статус вместе), правило; допуск — под вопросом;
- **встроенное:** числа с арифметикой, размерности.

Пять → пять или шесть плюс два встроенных. Самая крупная находка — правило.
Набор из пяти описывал факты, но не вывод. Лучший итог — слияние статуса и
плоскости в `holds`: ядро стало меньше в том месте, где ожидался рост.

Следующий казус (шаг гликолиза) проверит, растёт ли список дальше, или биология
укладывается в то, что вышло отсюда.
