# Векторы понятий из открытой LLM против меток WordNet (H62), 2026-10-25

Вопрос автора: нельзя ли получить вектор понятия из LLM. Опыт объявлен до
прогона (H62, коммит 98f7747); после 0.5B добавлен пустой контроль и
поправка критерия, объявленная до прогона 1.5B–72B (коммит cbecc66). Здесь
вход и выход; цифры пересчитываются офлайн.

## Вход

- Модели Qwen2.5 (0.5B, 1.5B, 7B, 32B — Apache 2.0; 72B — лицензия Qwen),
  ревизии закреплены в `tools/llm_geometry.py`. Модель **не запускалась**:
  загрузчик берёт запросами диапазона только матрицу выхода (у 0.5B и
  1.5B — общую со входом, у остальных — `lm_head` из последнего куска),
  6,1 ГБ на пять моделей. Куски — в `data/cache/llm/` (вне git), хеши —
  `data/llm/MANIFEST`. Токенизатор у всех пяти одинаковый (один хеш).
- Open English WordNet 2025-plus, существительные (`data/onto/raw`).
- Метод Park и др. (ICLR 2025, arXiv 2406.01506 [сверено]): отбеливание по
  словарю, вектор понятия ℓ̄ = (g̃ᵀ E g) g̃, g̃ ∝ Cov⁻¹ E g с усадкой
  Ледуа — Вольфа. Слова понятия — леммы синсета и всех потомков, одним
  токеном с пробелом впереди. Отбор (≥ 50 слов) дал **540 понятий, 15 980
  слов**, одинаково для всех моделей.
- **Контроль «шум»** (добавлен после 0.5B): словарь 0.5B, строки матрицы —
  гауссов шум от seed 0. Показывает, что даёт сама процедура без модели.

```sh
python3 tools/llm_geometry.py fetch                                     # ~6 ГБ, один раз
uv run --python 3.12 --with numpy==2.2.6 tools/llm_geometry.py run      # ~5 мин, пик 7,8 ГБ (72B)
uv run --python 3.12 --with numpy==2.2.6 tools/llm_geometry.py run noise
```

Полные распределения (10-й / 50-й / 90-й перцентиль) — `data/llm/results.json`.

## Толкование помощника

1. **Объявленная проверка ортогональности почти целиком — свойство
   процедуры, а не модели.** Слова вида входят в слова рода; для средних
   по любым векторам μ_род · μ_вид ≈ |μ_род|², а это и есть «род ⟂ вид −
   род». Независимые подвыборки по 70 % это не снимают. Без пустого
   контроля опыт «повторил бы статью» и был бы неверно прочитан. Это не
   опровергает Park и др. целиком: их другие проверки здесь не повторялись.
2. **Собственный вклад модели есть, но небольшой.** Если род оценить по
   словам «братьев», без слов вида, шум падает до уровня случайности
   (0,49), а модели остаются выше (0,57–0,65), при обоих seed. Общее
   направление рода у видов в модели есть; оно слабее, чем выглядело.
3. **С ростом модели оба сигнала слабеют монотонно**: и «понятие — одно
   направление» (1), и вклад в 2b. Возможные причины не проверены:
   у большой модели больше измерений, и слово несёт больше своего, помимо
   рода; или она делит слова по признакам тоньше узлов WordNet. Обратного
   («больше модель — чище иерархия») здесь не видно.
4. **Два рода (3)**: в плоскости обоих родов вида больше, чем в
   направлении каждого, а случайное понятие не добавляет ничего. Но шум
   даёт ту же картину (0,67 против 0,48–0,54) — по той же причине,
   вложенности слов, а синсетов всего 15. Вывода нет.
5. **Для H61** («номера, в которых уже есть порядки и вложенности»):
   векторы LLM — это не метки, из которых читается вложенность. Иерархия
   в них есть как слабый статистический след, а точную вложенность дают
   отношения (ядро, WordNet). Вектор из LLM годится как *подсказка*
   («похоже на род X»), которую проверяет третья плита (H63).

## Чего опыт не показывает

- Только матрица выхода и только однотокенные слова (15 980 из словаря
  WordNet); многословные понятия и внутренние слои не смотрелись.
- Один род моделей (Qwen2.5) и одна онтология.
- Контроль и проверка 2b придуманы после 0.5B; для 0.5B они задним числом,
  для остальных четырёх — объявлены заранее.
- «Доля ближе к ⟂» — один способ сравнения; порогов значимости нет, есть
  два seed и шум как ориентир.
- Вычисления на BLAS в параллель; последние знаки могут плавать, таблицы
  округлены.
