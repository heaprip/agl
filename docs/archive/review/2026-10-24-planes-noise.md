# Тысячи плоскостей: ложные находки и скорость (H52), 2026-10-24

Вопрос автора: что с чем связано, когда плоскостей тысячи. Опыт на синтетике:
`examples/planes_noise.rs`.

```sh
cargo run --release --example planes_noise -- N K [seed]
```

## Постановка

N плоскостей (значения одной оси `group`), в каждой K индивидов. Признаки `a`
и `b` — независимые монеты. В 5% плоскостей посажена связь `a → b`: каждому с
`a` дан и `b`. Таблица строится ядром: `extent::table` обходит все контексты
так же, как `--implications`. Вопрос — в каких плоскостях «здесь `a → b`
верно».

- **Наивно:** в плоскости нет исключения (у всех с `a` есть `b`).
- **С поправкой** Бенджамини — Хохберга (1995), доля ложных открытий q = 0.1.
  p-значение плоскости — p0^n: шанс, что n индивидов с `a` все имеют `b`,
  если `b` сопутствует `a` не чаще, чем в целом (p0 — общая доля). Это грубая
  оценка: p0 считается по всем данным, вместе с посаженными.

Ожидалось до прогона: без поправки случайные находки растут с N; при малом K
плоскость не отличить от случая; с поправкой ложные близки к нулю ценой
части настоящих.

## Результаты (seed 1)

| N | K | посажено | наивно: верно / случайно | BH: верно / случайно |
| ---: | ---: | ---: | ---: | ---: |
| 100 | 6 | 3 | 3 / 20 | 0 / 0 |
| 100 | 20 | 3 | 3 / 1 | 3 / 0 |
| 1000 | 6 | 53 | 53 / 149 | 0 / 0 |
| 1000 | 20 | 53 | 53 / 2 | 39 / 0 |
| 3000 | 20 | 148 | 148 / 5 | 118 / 0 |
| 5000 | 20 | 241 | 241 / 12 | 171 / 0 |
| 10000 | 20 | 508 | 508 / 26 | 373 / 3 |

Ожидание подтвердилось.

1. **Без поправки ложные находки растут с N** линейно: при K = 20 около 0.5%
   плоскостей проходят случайно (шанс 0.5^≈10). При K = 6 случайных втрое
   больше, чем настоящих.
2. **При малом K ничего не отличить.** В плоскости с шестью индивидами у
   троих с `a` все с `b` в одном случае из восьми; поправка честно отвечает
   «нечего утверждать». Мало данных на плоскость — не лечится статистикой.
3. **Поправка держит ложные около нуля** (3 из 376 при N = 10000, в пределах
   q = 0.1) и теряет около четверти настоящих: тех, где с `a` мало индивидов.

Вывод для agl: «нет исключений в плоскости» на тысячах плоскостей — не
закономерность, а шум. Отчёт о почти-импликациях по плоскостям должен
называть число проверок и поправку; без этого он будет вводить в заблуждение
пропорционально числу плоскостей.

## Скорость

Время всего прогона (K = 20):

| N | до | после |
| ---: | ---: | ---: |
| 1000 | 1.7 с | 0.6 с |
| 3000 | 21 с | 2.8 с |
| 5000 | 67 с | 4.2 с |
| 10000 | — | 17 с |

Что сделано, вывод не изменился (все казусы и разборы байт в байт, `cargo test
--release`, sim 20 000 seed, эталон 50 000 seed):

- `eval::Visibility`: какие факты и правила видны в плоскости — считается один
  раз на программу, а не на каждый контекст;
- `value_within` идёт по цепочке родителей без выделения памяти;
- `plane_meet` сначала пересекает общие оси и ничего не копирует, если
  плоскости не пересекаются; `value_meet` быстро отказывает двум простым
  значениям, ни одно из которых не внутри другого и чьё перекрытие не
  объявлено.

Остаток — квадратичный обход пар в замыкании пересечений (`check::contexts`):
каждая плоскость сверяется с каждой. На 10 000 плоскостей это 10⁸ проверок.
Индекс по осям убрал бы квадрат, но для реальных казусов (десятки плоскостей)
не нужен; отложено до задачи, где плоскостей действительно тысячи.

Предел `MAX_CONTEXTS = 4096` ограничивает только новые пересечения: исходные
плоскости программы учитываются все, поэтому прогон на 10 000 полон.
