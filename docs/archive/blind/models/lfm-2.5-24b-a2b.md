**1. Итоговый набор примитивов и семантических правил (кратко)**  

| Примитив | Назначение |
|----------|------------|
| **Entity** | Абстрактный объект (любой элемент модели). |
| **Ship** | Подкласс Entity, обозначающий корабль. |
| **Property** | Имя свойства (material, form, continuity, ownership, ritual). |
| **HasProperty(e, p, v)** | Присваивает свойство p объекту e значение v. |
| **Event(e, act, t)** | Событие (замена, сборка) в момент t. |
| **Identity(e₁, e₂)** | Равенство/соподобие объектов (тот же корабль). |
| **Criterion** | Метка критерия (material, form, continuity, ownership, ritual). |
| **Answer(case, q, ship, basis)** | Ответ на вопрос q: какой корабль ship, справа basis — список критериев, по которым дан ответ. |
| **Ground(a, [p₁,…,pₙ])** | Обоснование ответа a: перечисление предпосылок (свойства, события). |
| **Contradiction(a₁, a₂)** | Флаг, что ответы a₁ и a₂ противоречат друг другу. |
| **RealContradiction(a₁, a₂)** | Пометка реального (не кажущегося) противоречия. |
| **Operation** | Обозначение медицинской процедуры (в данном контексте — аборт). |
| **Speaker** | Персонаж (Jig, Man). |
| **Utterance** | Фраза в диалоге. |
| **Proposition** | Содержание фразы. |
| **Desire(s, obj)** | Желание персонажа s относительно obj. |
| **Ambiguity(Utterance, reason)** | Маркер неоднозначного высказывания. |
| **Decision(s, act)** | Решение персонажа. |
| **Resolution** | Итог истории. |

**Семантические правила**

1. **R1** – `HasProperty` связывает объект со свойством.  
2. **R2** – `Event` изменяет свойства, порождая новые состояния.  
3. **R3** – `Identity` определяется непрерывностью свойств и событиями замещения.  
4. **R4** – `Answer` обязателен содержать `ship` + `basis`.  
5. **R5** – `Ground` связывает ответ с конкретными `Property`/`Event`.  
6. **R6** – `Contradiction` ставится, когда два ответа противоречат друг другу **по одному и тому же критерию**.  
7. **R7** – `RealContradiction` используется, когда противоречие неразрешимо в рамках выбранных критериев.

**Казус 2. Ответы (в уже существующей нотации, с новыми примитивами)**  

| Примитив, введённый для этого казуса | Назначение |

**Вопросы и ответы**

1. **Операция** – какая?  
   - **Ответ:** *Operation* = **abortion** (аборт).  
   - **Ground:** В диалоге фигурирует фраза *«the only operation»*. Текст не называет её иначе, поэтому читатель выводит, что речь о медицинской процедуре выкидывания беременности.  

2. **Кто чего хочет**  
   - **Женщина (Jane):** хочет **сохранить ребёнка** (не прерывать беременность).  
   - **Мужчина (Speaker):** хочет **прервать беременность** (считает это единственным решением).  
   - **Ground:** Прямая речь: *«I don’t want to talk about the operation»* (мужчина) и *«It’s the only thing that matters»* (женщина).  

3. **Искренность фразы «I don’t want to talk about it»**  
   - **Ответ:** Фраза **искренняя** – мужчина явно высказывает своё желание избежать обсуждения аборта, а дальше продолжает настаивать на процедуре.  
   - **Ground:** Прямая речь + желание (Desire) мужчины: *«I want to get rid of it»* – подтверждает искренность.  

4. **Что решено в конце**  
   - **Resolution:** Пара **решает пройти аборт**; оба соглашаются, что это единственный путь.  
   - **Ground:** Финальная реплика женщины *«It’s the only thing that matters»* и её улыбка.  

**Разделение «текст говорит / читатель выводит»**  

| Утверждение | Текст говорит | Что выводит читатель |
|-------------|---------------|----------------------|
| Операция = аборт | Да (фраза *the only operation*) | Читатель сам соединяет слово *operation* с медицинским смыслом. |
| Желания персонажей | Да (прямая речь) | Читатель понимает, кто за что отвечает. |
| Искренность мужского утверждения | Да (прямая речь) | Читатель видит мотивы, без дополнительных предположений. |

### 1. Новые примитивы (внесённые в журнал)

| Примитив | Обозначение | Назначение |
|----------|-------------|------------|
| **Killer** | Subclass Entity | Лицо, осуществляющее убийство. |
| **Victim** | Subclass Entity | Цель убийства. |
| **Goal** | Property | Цель, стоящая за действием Killer. |
| **Intent** | Property | Намерение Killer (что он собирается сделать). |
| **AbsenceInfo** | Property | Информация, которой в тексте нет (не выражено). |
| **Silence(e, P)** | Property | Состояние, когда proposition P не высказывается в событии e. |

**Правила семантики (R8‑R10)**  

- **R8** – `Killer` является Entity и имеет `Goal` (цель — убийство).  
- **R9** – `Intent(Killer, Goal)` связывает убийцу с его целью.  
- **R10** – `AbsenceInfo(e, P)` фиксирует, что proposition P отсутствует в тексте; `Silence(e, P)` – конкретный случай отсутствия.

### 4. Что не выразилось или выразилось натяжкой

- **Точный список «за что»** (кто хочет убить Ника) – полностью **не выражено**; в нотации это `AbsenceInfo(Nick, target=unknown)`.  
- **Эмоциональная реакция Оле** – в тексте нет прямых эмоций; мы можем лишь констатировать его действие («не бежит»).  
- **Полный контекст «operation»** в рассказе Хемингуэя – известен из литературных исследований, но в самом тексте он не назван; мы **не включаем** внешние источники, только отмечаем, что это **внешнее знание**, а не внутритекстовое.  
- **Искренность фразы «I don’t want to talk about it»** – в «The Killers» такой фразы нет, поэтому мы не оцениваем её искренность, а лишь отмечаем отсутствие.

### 5. Оценка фундаментальности примитивов

| Примитив | Фундаментальность | Можно ли свести к другим |
|----------|-------------------|--------------------------|
| **Entity** | **Фундаментален** – основа любой модели объектов. | Нет; без него невозможно различать корабли, людей, корабли. |
| **Ship** | Специфичен для задачи 1, но обобщается как **Object**; можно заменить на `Entity` + `IsShip`‑флаг. | Частично сводим к `Entity`. |
| **Property / HasProperty** | Фундаментален для атрибуции характеристик (материал, форма). | Можно заменить на **Attribute**‑примитив, но суть та же. |
| **Event** | Фундаментален для отслеживания изменений (замена досок, убийство). | Можно объединить с `Change`, но событие – естественный способ. |
| **Identity / Continuity** | Ключевой для «Тесея» и «Убийцы» (непрерывное существование). | Можно выразить через `HasProperty` с изменяющимися свойствами, но удобнее отдельный примитив. |
| **Operation** | **Специфичен** для казуса 2; без него невозможно описать «операцию». | Можно назвать `Procedure`, но название не меняет сути. |
| **Killer / Victim / Goal / Intent** | **Фундаментальны** для задачи 3 (моделирование убийства). | Можно заменить на `Agent`, `Target`, `Motivation`, но в нашей нотации удобнее. |
| **AbsenceInfo / Silence** | **Полезны** для фиксации несказанного; без них теряется информация о пробелах. | Можно было бы вести отдельный журнал, но примитив упрощает нотацию. |
| **Decision / Resolution** | Фундаментальны для ответа/итога. | Можно объединить, но удобно разделять. |

**Итого:** базовый набор **Entity, Property, Event, Identity, Decision, Resolution** – минимальный фундамент. Остальные примитивы (Operation, Killer, Victim, Goal, Intent, AbsenceInfo, Silence) вводятся **только** когда требуется моделировать конкретный казус, и их можно считать **сводимыми** к более общим (Agent, Procedure, Target, Motivation, Missing information).

### 1. Новые примитивы (внесённые в журнал)

| Примитив | Назначение |
|----------|------------|
| **Story** | Объект‑текст, «история», записанная в нотации. |
| **SixWord** | Факт: длина текста ровно 6 слов (`SixWord(Story, 6)`). |
| **InferredStory** | Производное существо: смысл‑инференс, полученный из `Story`. |
| **Attribution** | Отношение «story ←→ author» (`Attribution(Story, Author, Status)`). |
| **AttributionStatus** | Дисплеирует, насколько известен автор: `Known`, `Uncertain`, `Unknown`. |
| **SymbolicMeaning** | Примитив‑ярлык для вывода‑символики (например, «потеря», «нереализованный потенциал»). |

**Правила семантики (R11‑R13)**  

- **R11** – `SixWord(Story, n)` ⇔ `Story` состоит ровно из *n* токенов.  
- **R12** – `InferredStory(Story, M)` ⇔ если `Story` указывает на конкретный объект и условие (например, «never worn»), то можно вывести `M` (потеря ребёнка, недоисполненная надежда).  
- **R13** – `Attribution(Story, A, S)` фиксирует, кто автор; `S∈{Known, Uncertain, Unknown}` отражает достоверность.

### 2. Текст, вывод и статус авторства (ответы на вопросы)

| Вопрос | Ответ (в нотации) |
|--------|-------------------|
| **Текст** | `Story = {text: "For sale: baby shoes, never worn"}` |
| **История, которую выводит читатель** | `InferredStory = {loss: "родитель продал обувь, которую ребёнок никогда не носил; это метафора утраченных возможностей, нежеланного ребёнка"}` |
| **Статус приписывания** | `Attribution(Story, Hemingway, AttributionStatus=Uncertain)` |

- **R12** использует факт `never worn` → позволяет вывести тему потери/нереализованного.  
- **R13** фиксирует, что традиционно эта строка приписывается Э. Хемингуэю, но литературные исследования не дают однозначного подтверждения → `Uncertain`.

| Казус | Введённые примитивы | Почему нужен |
|-------|-------------------|--------------|
| 1 | Entity, Ship, Property, … (базовый набор) | Определение объектов и свойств. |

- **Story** и **SixWord** – минимальны для фиксированной формы текста.

### 4. Что не выразилось или выразилось натяжкой

- **Эмоциональная окраска** «потери ребёнка» – текст не содержит прямого эмоционального маркера; мы **вынуждены** добавить `SymbolicMeaning` как интерпретацию, что является натяжкой.  
- **Конкретная причина, почему обувь «не была носена»** – отсутствует; фиксируем лишь факт `never worn`.  
- **Точный авторский замысел** – `AttributionStatus=Uncertain` отражает, что документально подтверждённый автор неизвестен; любое утверждение «это Хемингуэй» – **натяжка**.

### 5. Оценка фундаментальности примитивов

| Примитив | Фундаментален? | Можно ли свести к другим? |
|----------|----------------|---------------------------|
| **Story** | **Фундаментален** – базовый контейнер любого текста. |
| **SixWord** | Специфичен, но выражается через `Proposition` с ограничением длины; при желании можно заменить. |

| **AttributionStatus** | **Не фундаментален** – это значение истинности/ложности `author`. |
| **SymbolicMeaning** | **Не фундаментален** – это просто метка для интерпретации; можно хранить в `Proposition`. |

**Итого:** базовый набор (Entity, Property, Event, Identity, Decision, Resolution) остаётся ядром. Примитивы для казуса 4 вводятся только тогда, когда требуется работа с коротким текстом, его выводом и вопросом авторства; они полезны, но сводимы к стандартным логическим конструкциям.

## 1. Итоговый набор примитивов и семантических правил  

### Примитивы  

| Примитив | Краткое назначение |
|---|---|
| **Entity** | Абстрактный объект (любой элемент модели). |
| **Ship** | Специальный подкласс Entity – корабль. |
| **Property** | Имя свойства (material, form, continuity, ownership, ritual). |

| **Event(e, act, t)** | Событие (замена, сборка, убийство и т.п.). |

| **Criterion** | Метка критерия (material, form, continuity, ownership, ritual). |
| **Answer(case, q, ship, basis)** | Ответ на вопрос q: какой корабль/объект ship, на чём основано basis. |
| **Ground(a, [p₁…pₙ])** | Обоснование ответа a: список предпосылок. |
| **Contradiction(a₁, a₂)** | Флаг, что ответы противоречат друг другу. |
| **RealContradiction(a₁, a₂)** | Флаг реального (неразрешимого) противоречия. |
| **Operation** | Обозначение медицинской/процедуры (в задаче – аборт). |
| **Speaker / Utterance / Proposition** | Субъект, высказывание, смысл высказывания. |
| **Desire(s, obj)** | Желание персонажа s относительно obj. |
| **Ambiguity(Utterance, reason)** | Указатель на двусмысленность. |
| **Decision / Resolution** | Принятое решение / итоговая история. |
| **Killer / Victim / Goal / Intent** | Агенты и их мотивация (для «Убийц»). |
| **AbsenceInfo / Silence(e, P)** | Фиксируют отсутствие информации о proposition P. |
| **Story** | Текст‑запись (юридический объект). |
| **SixWord** | Факт: текст состоит ровно из 6 слов. |
| **InferredStory(Story, M)** | Инференс, выводимый из Story (например, «потеря»). |
| **Attribution(Story, Author, S)** | Приписывание текста автору; S – Known/Uncertain/Unknown. |
| **AttributionStatus** | Дисплей достоверности приписывания. |
| **SymbolicMeaning** | Метка для символического прочтения (потеря, недоисполненный потенциал). |

### Семантические правила  

| № | Правило | Суть |
|---|---|---|
| **R1** | `HasProperty` связывает объект со свойством. |
| **R2** | `Event` меняет свойства, порождая новое состояние. |
| **R3** | `Identity` определяется непрерывностью свойств и событиями замещения. |
| **R4** | `Answer` обязателен содержит `ship` + `basis`. |
| **R5** | `Ground` связывает ответ с конкретными `Property`/`Event`. |
| **R6** | `Contradiction` ставится, когда два ответа противоречат друг другу **по одному критерию**. |
| **R7** | `RealContradiction` – неразрешимое противоречие в рамках выбранных критериев. |
| **R8** | `Killer` является Entity и имеет `Goal` (убийство). |
| **R9** | `Intent(Killer, Goal)` связывает убийцу с целью. |
| **R10** | `AbsenceInfo` фиксирует отсутствие `P`. |
| **R11** | `SixWord(Story, n)` ⇔ `Story` состоит ровно из n слов. |
| **R12** | `InferredStory(Story, M)` ⇔ из текста выводим M. |
| **R13** | `Attribution(Story, A, S)` + `AttributionStatus`. |

## 2. Казусы 1‑4: ответы и обоснования  

### Казус 1. Корабль Тесея  
| Вопрос | Ответ | Ground (основание) |
|---|---|---|
| Какой корабль — Тесея? | **A₁** – оригинальный; **A₂** – построенный из новых досок. | `HasProperty(S_orig, material, original_wood)`, `Continuity(S_orig, t)`; `Form(S_new, f)`, `Continuity(S_new, t)`, `Event(Replace, …, t_i)`. |
| Зависит от критерия? | A₁ – material + continuity; A₂ – form + continuity. | Критерии выделены в Ground. |
| Момент «перестал быть» тем же? | Нет фиксированного момента; непрерывность оценивается событием замены. | `Identity` через `Continuity` + `Event`. |
| Противоречие разных критериев? | Да: A₁ и A₂ противоречат друг другу при критерии **material** (один материал, другой – новый). | `Contradiction(A₁, A₂)`. |

### Казус 2. Хемингуэй, «Холмы как белые слоны»  
| Вопрос | Ответ | Ground |
|---|---|---|
| О какой «операции» идёт речь? | **Operation** = *abortion* (медицинская процедура). | Упоминание *the only operation* → связь с `Operation`. |
| Чего хочет каждый персонаж? | Женщина – **сохранить ребёнка**; мужчина – **прервать беременность**. | Прямая речь: *«I’m just watching»* (мужчина) и *«It’s the only thing that matters»* (женщина). |
| Искренна ли фраза мужчины о том, что он не хочет, чтобы она делала то, чего не хочет? | **Да** – мужчина открыто заявляет о своём желании избежать обсуждения аборта. | `Desire(male, abortion)`. |
| Что решено в конце? | Принято **прервать беременность**; оба соглашаются. | Финальная реплика женщины *«It’s the only thing that matters»*. |

### Казус 3. Хемингуэй, «Убийцы»  
| Вопрос | Ответ | Ground |
|---|---|---|
| Почему Оле Андрессон не бежит? | Оле **наблюдает**, а не участвует. | Диалог: *«I’m just watching»*. |
| Что понял Ник и почему уезжает? | Ник понимает, что **он целевой объект**; уезжает, чтобы избежать убийства. | `Goal(Nick, be killed)`, `Intent(Killer, …)`. |
| Чего текст не говорит (за что его хотят убить)? | Не указано, кто хочет убить Ника. | `AbsenceInfo(Nick, target=unknown)`. |
| Искренность фразы о нежелании делать «то, чего не хочет»? | В тексте такой фразы нет → **не оценивается**. | Отсутствие высказывания → `Ambiguity`. |
| Что решено в конце? | **Открыто**: убийца уходит, жертва уезжает, ясного финала нет. | Последняя строка *«He left the bar, the rain was falling»*. |

### Казус 4. «For sale: baby shoes, never worn»  
| Вопрос | Ответ | Ground |
|---|---|---|
| Текст | `Story = "For sale: baby shoes, never worn"` (6 слов). | `SixWord(Story, 6)` – проверка. |
| История, которую выводит читатель | `InferredStory = {loss: "родитель продал обувь, которую ребёнок никогда не носил; метафора утраченных возможностей}"`. | Факт `never worn` → вывод о потере/нереализованном. |
| Статус приписывания | `Attribution(Story, Hemingway, AttributionStatus=Uncertain)`. | Исторически приписывают Хемингуэю, но документально подтверждено неизвестно. |

## 3. Журнал введения примитивов (кривая роста)

| Казус | Введённые примитивы | Комментарий (можно ли было обойтись?) |
|---|---|---|
| **1** (Тесея) | Entity, Ship, Property, HasProperty, Event, Identity, Criterion, Answer, Ground, Contradiction, RealContradiction | Необходимы для моделирования замены частей и критериев. |
| **2** (Холмы) | Operation, Speaker, Utterance, Proposition, Desire, Ambiguity, Decision, Resolution | `Operation` – единственный способ назвать действие; остальные – стандартные лингвистические примитивы. |
| **3** (Убийцы) | Killer, Victim, Goal, Intent, AbsenceInfo, Silence, Decision, Resolution | `Killer`/`Victim` – без них невозможно выразить убийство; `Goal`/`Intent` – мотивация. |
| **4** (Шесть слов) | Story, SixWord, InferredStory, Attribution, AttributionStatus, SymbolicMeaning | `Story`/`SixWord` – фиксируют форму текста; `InferredStory`/`Attribution` – вывод/авторство. |

*Все примитивы вводятся только тогда, когда задача требует работы с конкретным объектом (корабль, диалог, убийство, короткий текст). Без них задачи решаемы, но без чёткой модели «что есть объект»/«что выводится».*

## 4. Что не выразилось или выразилось натяжкой  

| Пункт | Причина / Как выражено |
|---|---|
| **Эмоциональная реакция** (например, печаль от «baby shoes») | Текст не содержит эмоционального маркера; мы **добавляем** `SymbolicMeaning` как интерпретацию – это натяжка. |
| **Конкретная причина «never worn»** | Факт есть, но причины (почему не надевали) неизвестны – фиксируем лишь `never worn`. |
| **Точный авторский замысел** | `AttributionStatus=Uncertain` отражает, что доказательство авторства отсутствует; любые утверждения «это Хемингуэй» – натяжка. |
| **Личные мотивы Оле (в «Убийцах»)** | В диалоге Оле не высказывает мотивации, только действие «наблюдать». |
| **Объективный факт «кто хотел убить Ника»** | Отсутствует в тексте → `AbsenceInfo(Nick, target=unknown)`. |

## 5. Оценка фундаментальности примитивов  

| Примитив | Фундаментален? | Можно ли свести к другим? |
|---|---|---|
| **Entity** | **Да** – базовый «объект». |
| **Ship** | Сводим к `Entity` + флаг «это корабль». |
| **Property / HasProperty** | Фундаментален для атрибуции свойств. |
| **Event** | Фундаментален: фиксирует изменения. |
| **Identity / Continuity** | Полезен, но может быть выражен через `HasProperty` + `Event`. |
| **Criterion** | Специфичен для задачи о критериях, но при необходимости заменяется обычным `Property`. |
| **Answer / Ground** | Необходимы для структурирования ответов. |
| **Contradiction / RealContradiction** | Фундаментальны для логической проверки. |
| **Operation** | Специфичен для «операции» (кейс 2), но в общем случае – обычный `Procedure`. |
| **Speaker / Utterance / Proposition** | Стандартные элементы диалога. |
| **Desire / Ambiguity** | Полезны, но сводимы к обычным `Proposition` + атрибутам. |
| **Decision / Resolution** | Фундаментальны для фиксирования исхода. |
| **Killer / Victim / Goal / Intent** | Фундаментальны для модели убийства (кейс 3). |
| **AbsenceInfo / Silence** | Удобные, но полностью заменяемы `Proposition` + `TruthValue`. |
| **Story / SixWord / InferredStory** | Сводим к обычному `Proposition` + ограничениям; полезны как маркеры формы. |
| **Attribution / AttributionStatus** | Не фундаментальны; можно выразить как `Story author = Hemingway ∧ True/False`. |
| **SymbolicMeaning** | Чистый маркер интерпретации; не нужен в строгой логической модели, но удобен для «чтения» текста. |

**Вывод:**  
- **Базовый ядро** – `Entity`, `Property`, `HasProperty`, `Event`, `Identity`, `Answer`/`Ground`, `Contradiction`, `Decision`/`Resolution`.  
- **Вспомогательные примитивы** (`Ship`, `Operation`, `Killer`, `Victim`, `Goal`, `Intent`, `Story`, `SixWord`, `InferredStory`, `Attribution`, `SymbolicMeaning`) вводятся **только** когда задача требует специфического анализа (корабль, медицинская процедура, убийство, короткий текст). Они легко заменяются стандартными логическими конструкциями, но делают нотацию более читаемой и структурированной.
