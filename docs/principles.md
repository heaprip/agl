# Принципы

Проект строит **новый** формальный способ вычисления, а не собирает его из
известных. Агенты раз за разом съезжали на знакомый путь: λ-исчисление,
учебная физика, перебор, «готовый список свойств», отложенный «как
оптимизация» точный вектор. Академические работы — сверка терминов и
границ, не источник операций ядра. Ниже — поправки автора, которые уже
нарушались. Каждое предложение и каждый шаг сверяются с этим списком.

1. **Вектор — точная запись, не приближение.** «Вектор» не значит
   эмбеддинг. Сумма точная.
2. **Геометрия — вид, не вход.** Выбора представления быть не должно:
   представление — проекция найденной структуры; много реализаций — повод
   к дистилляции.
3. **Свойства выводятся из примитивов, а не даются данными**:
   переместительность, делители нуля, изоморфизм и т. п.
4. **Известные понятия — только звёзды для сверки.** Они не выбирают ни
   шаг, ни набор законов, ни критерий. Цель «по памяти» (знаю, что ответ —
   группа порядка 12) — та же ошибка.
5. **λ-исчисление и таблицы — звёзды, не язык ядра.** Язык ядра —
   отношения, склейка, плоскости.
6. **Отобранные руками данные в «чистом мире» — псевдо-закрепление.**
   Брать неотобранные миры.
7. **С нуля, путём Бурбаки, через закрепление**: не начинать с
   кватернионов; псевдо-закрепления убрать.
8. **Параллельность — не оптимизация**: один поток. Оптимизировать по
   сложившейся структуре, а перед дорогим шагом — мерить то, что уже
   образовалось.
9. **Не «решать тебе»**: помощник даёт позицию, помечает её [помощник],
   решение остаётся за автором.
10. **Цитаты и мотивы автора — не в репозиторий**: здесь только безличные
    формулировки (решение 30).
11. **Код прошлого не используется.** Код до чистого листа (метка
    `legacy-v0`) не служит ни материалом, ни эталоном для сверки; приёмка —
    из спецификации, записанной до кода.
