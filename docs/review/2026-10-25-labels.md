# Метки вложенности, шаг 1 прототипа H61, 2026-10-25

Критерий объявлен до кода (H61, коммит cc3f310). Здесь вход и выход.

## Вход

- `src/label.rs`: по рёбрам «вид → род» — остовное дерево (род — первый
  по имени), номера в обратном порядке обхода (дети по имени), у узла —
  слитые интервалы его и всех потомков по графу (Agrawal, Borgida,
  Jagadish, SIGMOD 1989 [сверено по DBLP]). «A внутри B» — номер A в
  интервале B. Цикл — ошибка. Метки пока **не связаны с выводом** ядра.
- `tests/label.rs`: случайные графы от seed против замыкания обходом.
- `examples/labels.rs` на рёбрах из `tools/onto_stats.py edges` (ChEBI 200,
  244, 255; WordNet 2021, 2025).
- `examples/census.rs`: сколько атомов казусов приходится на вложенность.

```sh
AGL_SIM_SEEDS=20000 cargo test --release --test label
python3 tools/onto_stats.py edges chebi 255 > target/scratch/chebi255.tsv
cargo run --release --example labels -- target/scratch/chebi255.tsv
cargo run --release --example census -- cases/kinship.agl cases/trunk/oxygen.agl
```

## Толкование помощника

1. **Метки работают и дёшевы.** Замыкание ChEBI, которое в ядре заняло бы
   5 млн атомов (около 25 ГБ при нынешних 5 КБ на атом), читается из
   462 тыс. интервалов, построенных за 0,2 с.
2. **Сплошной номер — не имя.** Смысл меняется у 1–3 % понятий, а номер —
   почти у всех: любая вставка сдвигает обратный порядок обхода. Это
   подтверждает разделение H61: ссылаться только на неизменное имя, номер
   — пересчитываемое положение.
3. **Промежутки пока не нужны.** Полный пересчёт стоит 0,2 с, поэтому
   метку дешевле построить заново, чем хранить и править. Промежутки
   (или ORDPATH) понадобятся, только если метки будут храниться или
   передаваться между системами.
4. **Для нынешних казусов выигрыша нет**: вложенность там — десятки
   атомов. Выигрыш — на масштабе онтологий (H64).

## Чего шаг не показывает

- Метки не подключены к выводу: ядро по-прежнему выводит `ancestor` и
  `member` правилами. Это шаг 2.
- Рёбра берутся без плоскостей и без отменяемости: у ядра рёбра могут
  быть разными в разных плоскостях и могут быть отменены. Как строить
  метки по плоскостям — вопрос шага 2.
- Одна ось (род). Вторая ось (роли, «часть чего») не размечалась.
- Цепочка вывода «почему A внутри B» из метки не читается; её придётся
  восстанавливать по рёбрам.

## Шаг 2а: `nesting` в ядре

Критерий объявлен до кода (H61, коммит b2368af). Автор выбрал: метки
строятся заново в каждой плоскости из видимых в ней рёбер.

- `nesting ID: N(a, b) by E(x, y)` разворачивается при разборе в два
  строгих правила `ID_base` и `ID_step`; понятия, рефлексия, обучение
  видят обычные правила. Вывод не крутит их по кругу: после правил своего
  слоя он строит метки по рёбрам и выдаёт атомы N с теми же выводами, что
  дали бы правила, и повторяет, если правила слоя добавили рёбра.
- Метки теперь принимают циклы: компоненты сильной связности (Тарьян),
  внутри компоненты все вложены друг в друга. Шаг 1 считал цикл ошибкой —
  это снято, иначе `forbid own_ancestor` в родстве перестал бы работать.
- Атомы N из фактов и других правил — последний шаг пути (ребро к
  «свежей копии» рода без выходящих рёбер).
- Если атом N проиграл спор и заблокирован — эта вложенность в этом
  контексте выводится правилами, как раньше.

| Критерий | Итог |
| --- | --- |
| (а) 20 000 случайных программ: отчёт и все замыкания (атомы, выводы, посылки, строгость, доверие, споры) с `nesting` побайтно равны версии с двумя правилами | да; метками выведено 6844 замыкания из 7056 (97 %), правилами — 212, где атом N проиграл спор |
| (б) `cases/kinship.agl` через `nesting` | да |
| (в) sim (20 000), oracle (50 000), все тесты, clippy | да |

От противного: тест падает, если `nest` ничего не добавляет; если
забыть данные атомы N как посылки; если пускать к «свежей копии» без
ребра.

Цепочка из 400 звеньев (80 тыс. атомов N), `target/release/agl`:

| | время | пик памяти |
| --- | --- | --- |
| два правила | 33,6 с | 713 МБ |
| `nesting` | 9,3 с | 152 МБ |

Атомов столько же; память падает, потому что правилам нужно 400 кругов,
и на каждом перестраивается индекс. Оставшиеся 9 с — разбор доверия и
споров по посылкам (`settle`, `decide`), он от меток не зависит.

**Не показывает:** экономии атомов (все атомы N создаются) — это шаг 2б;
`--where`, `--concepts` и остальные модули не проверялись на `nesting`
отдельно (они видят те же два правила).

## Шаг 2б: ленивые атомы

Объявлено до кода (H61, коммит c1f6a87). `nesting ... lazy`: атом N(x, y)
создаётся, только когда его спрашивает тело правила, вместе с «конусом» —
всеми N(z, y) на путях от x к y, — с выводами шага 2а. Ленивость явная:
модули вне вывода (`--where`, обучение, рефлексия) иначе молча увидели бы
неполное замыкание. Ядро проверяет условия и при их нарушении строит
замыкание целиком: N читают только тела правил (не запросы, запреты,
единственность, сравнения, агрегаты), нет отрицаний N, рёбра — факты.

| Критерий | Итог |
| --- | --- |
| (а) 20 000 программ, где N читают только правила: отчёт побайтно равен 2а; созданные атомы равны атомам 2а | да; создано 236 891 атом N против 377 912 |
| (б) программы, где N читают запросы, — как в 2а | да (прежние тесты `nesting` и `seminaive`) |
| (в) замер на настоящих данных | ниже |

От противного: тест падает, если создавать только спрошенный атом без
конуса.

```sh
python3 tools/onto_stats.py probe wordnet 2025 lazy > target/scratch/wn_lazy.agl
cargo run --release -- target/scratch/wn_lazy.agl
```

(да) и 10 без вложенности (неизвестно: мир ядра открыт):

| --- | --- | --- |
| верных ответов | 30 из 30 | 10 из 30 |
| атомов замыкания | 104 | обрыв на 100 000 (нужно 742 396) |
| время | 0,7 с | 8,4 с |
| пик памяти | 254 МБ | 1,5 ГБ |

Ответы верны только потому, что нужный вывод сложился на первом круге.
