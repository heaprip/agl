# Ход работ и состояние

Единственный ход работ проекта: всё, чего здесь нет, — не в работе.
Разделы «Сейчас» и «Ждёт автора» печатает хук в начале каждой сессии и
после сжатия контекста. Закончил задачу — обнови «Сейчас» в том же
коммите. Устройство ядра — [model](model.md), решения —
[decisions](decisions.md).

## С чего начинаем

С чистого листа. Код прошлого — метка `legacy-v0`, **не используется**: ни
как материал, ни как эталон для сверки (модель, поправка 11). Приёмка
каждого шага — из спецификации, написанной до кода.

Из прошлого берём только:

- решения 1–43 — обязательны;
- [модель](model.md) с поправками, которые агенты уже нарушали; каждое
  предложение сверяется с ними;
- исходные заметки — замысел: `local/origin/relation-first-system.md` (вне
  git), в метке `docs-pre-cut` — `docs/origin/relation-first-system.md`.

Документы прошлого — в метке `docs-pre-cut` (`docs/archive/` и др.):
открываются только по прямому слову автора.

### Ф1. Спецификация фундамента

Описание ядра-машины (р. 29) до кода, прогоном на бумаге. Результат —
`docs/spec.md`; файл появится, когда начнётся работа над Ф1.
Спецификация пишется заново целиком по [модели](model.md). Черновик — в
метке `docs-pre-cut`, `docs/spec/foundation.md`: только справочно, не
эталон и не основа для правки. Устарело в нём
против решений 32–34: §4.1 (роды осей «порта / цепи / закона» вместо родов
р. 33); §5.3–5.4 (разность и сумма без рода «ось законов»); §8.2–8.5
(куски как значения порта семейства внутри одного мира, притирка как
замкнутость под встречами, постоянная — таблица встреч); §15.3 (мир всех
отношений как мир с кусками, против р. 34).

Что описать:

1. **Вхождение отношения** — единственная форма факта: идентичность и
   порты «роль → сущность»; отношение об отношении — то же вхождение
   (р. 10, 17).
2. **Координаты сущности** — точные положения с динамической глубиной;
   вширь — новые оси, вглубь — вставка между соседями без перенумерации;
   точные операции — по роду оси (р. 33); первые оси — из
   примитивных отношений, следующие — законы, выведенные ядром (р. 26).
   Конъюнкция признаков и композиция отношений — разные операции
   (требование плана; спорит с H85 — разобрать в спецификации).
3. **Плоскость** — набор условий по осям с нестрогой границей (р. 15, 27,
   41); противоречие — только на пересечении.
4. **Основание** — строгое или отменяемое, с опровергателем; совпадение
   результатов не склеивает сущности (р. 17, 36 п. 3).
5. **Вопрос** — сущность с частями: дано, найти, условия, цель, чего
   нельзя, когда готово; ответ — карта ветвей по плоскостям (р. 25).
6. **Без чисел мира** (р. 28): что ядро умеет над координатами как машина
   и чего не знает как понятий.
7. **Машина** (р. 29): состояние, операции, запрос — ответ; детерминизм от
   входа и seed (р. 18).

Прогоны на бумаге — два мира:

- **родство**: мать, отец, дед; «мать − родитель», «родитель ∘ родитель»;
  ось «поколение» выводится как закон, а не дана;
- **материнские структуры** (Ф4): неотобранные проекции (р. 32; мир всех
  отношений — место выбора, поводов в нём нет, р. 34); ядро само
  закрепляет эквивалентность и порядок как законы без имени.

Открытые вопросы, которые спецификация обязана разобрать (без выбора
стороны заранее):

- операции построения: в архиве контракта —
  `Primitive / Glue / Hide / Reify / Restrict`, в коде прошлого —
  `Derive / Metaedge`; какие нужны машине;
- связь осей координат сущности (р. 26) с плоскостью — частично отвечено
  р. 41 (условия по осям); разобрать полностью.

В спецификации же — **приёмка Ф2–Ф4**: что должно выйти на этих мирах,
записано до кода.

**Приёмка Ф1:** проверка agl-auditor по модели (с поправками) и решениям;
слово автора.

### Ф2. Ядро-машина

Реализация Ф1: вхождения, порты, координаты, плоскости, основания, вопрос.
Новый модуль — сначала строка в [реестре](modules.md).

**Приёмка:** прогоны мира родства из спецификации выполняются машиной так,
как записано на бумаге; детерминизм — перестановка входа и seed дают
побайтно тот же отчёт.

### Ф3. Закрепление как рост базиса

Выведенный закон становится осью; новое положение встаёт без
перенумерации. На родстве: «поколение» как закон композиции.

**Приёмка** — из спецификации.

### Ф4. Материнские структуры по пути Бурбаки

Маршрут задаёт путь Бурбаки: сначала структуры порядка и эквивалентности,
затем алгебраические (действие), затем топологические (окрестность).
Маршрут — слово автора (2026-10-27): он выбирает, *какую* структуру ядро
должно получить следующей; содержание каждой структуры ядро выводит само,
без имён и без списка свойств (поправки 3, 4).

Мир — неотобранный (поправка 6), без ручного выбора состава. Мир всех
отношений на малом множестве — место для выбора структуры, поводов в нём
нет (р. 34): куски — проекции одного понятия (р. 32); откуда их брать без
отбора — открыто (H84, H94). Механизм заметности (р. 31) должен сам закрепить
эквивалентность, порядок, затем действие; контроль — те же проекции с
разрушенной структурой.

**Приёмка** — из спецификации, до кода; закреплённое сверяется со
звёздами Бурбаки только снаружи.

Прежний мир устойчивости (цикл из четырёх точек) снят: он отобран руками,
и механизм под него подогнался (третья проверка Ф1). Устойчивость как
сохранение отношения при отображении ожидается на этом пути как одна из
структур и понадобится вехе Ф5.
