# Killer test: identity отдельно от extent

Статус: обязательная приёмка следующего общего фундамента. Это спецификация
теста, не выбранная реализация типов.

## Что он должен убить

Тест обязан падать у реализации, которая:

- считает сущностью её конечный объём;
- объединяет разные пути построения после совпадения результатов;
- не позволяет отношению стать endpoint следующего отношения;
- теряет контекст или основания при композиции;
- переписывает историю после снятия основания;
- выдаёт канонизацию запроса за identity предметной сущности.

## Минимальный мир

Никакой физики, λ-термов и предметных имён. Есть два контекста:

- `p`: малый конечный мир с носителем `{0, 1}`;
- `q`: расширенный мир `{0, 1, 2}`, restriction которого на `{0, 1}` даёт
  `p`.

Две конструкции создаются разными путями:

```text
a = Glue(a_left, a_right, ports_a)
b = Glue(b_left, b_right, ports_b)
```

Их проекции заданы так:

```text
extent(a, p) = {(0,0), (1,1)}
extent(b, p) = {(0,0), (1,1)}

extent(a, q) = {(0,0), (1,1), (2,2)}
extent(b, q) = {(0,0), (1,1)}
```

Равенство в `p` — отдельное доказуемое утверждение `EqualAt(a,b,p)`. Оно не
сливает IDs и не утверждает равенство в `q`.

## Минимальный публичный контракт

Имена типов могут измениться, но тесту нужны эквиваленты:

```text
Entity {
    id: EntityId,
    intension: Intension,
    bases: [EvidenceId],
}

Projection {
    entity: EntityId,
    context: ContextId,
    extent: ExactRelation,
    evidence: EvidenceId,
}

Metaedge {
    id: EntityId,
    relation: EntityId,
    ports: [(Role, EntityId)],
    context: ContextId,
    evidence: EvidenceId,
}

Evidence {
    id: EvidenceId,
    premises: [EvidenceId],
    operation: Operation,
    strength: strict | defeasible,
}
```

`ExactRelation` может быть плотным или разреженным, но представление не
участвует в identity.

## Обязательные assertions

1. `a.id != b.id` и `a.intension != b.intension`.
2. `extent(a,p) == extent(b,p)`.
3. Индекс по extent возвращает `[a,b]`, а не один произвольно выбранный ID.
4. Два метаребра используют `a` и `b` как разные endpoints; запрос видит оба.
5. `EqualAt(a,b,p)` имеет собственное основание и не создаёт глобального
   equality/congruence.
6. `extent(a,q) != extent(b,q)`; отчёт показывает `(2,2)` как минимальный
   контрпример.
7. Restriction обеих проекций из `q` в `p` даёт записанные проекции в `p`.
   Если это не выполняется, документация не имеет права говорить presheaf.
8. Снятие основания пути `a` инвалидирует только зависящие от него projection,
   `EqualAt` и метаребро. `b` остаётся; старые записи остаются в истории с
   новым статусом, а не удаляются.
9. Перестановка входных фактов и повторный запуск дают побайтно одинаковый
   отчёт.
10. CQ-core, e-graph или иной оптимизатор может объединить планы вычисления,
    но после него пункты 1–9 всё ещё выполняются.

## Форма реализации тестов

Первый уровень — `tests/identity_extent.rs`, только через публичный Rust API.
До появления first-class relation reference DSL не надо притворяться, что
`.agl` уже выражает этот контракт.

Второй уровень — маленький наивный reference evaluator в самом тесте. Он
перебирает конечные кортежи и сверяет projections с оптимизированным
исполнителем. Сеть, часы и внешние solver'ы запрещены.

Третий уровень — property/regression tests:

- все перестановки порядка исходных записей;
- плотное и разреженное представление exact relation;
- снятие каждого основания по одному;
- сериализация и replay одного и того же журнала.

Отдельный differential experiment сравнивает соответствующие фрагменты с
CQ/regular-logic и ErgoAI. Он не является unit test и не делает внешнюю
систему источником identity agl.

## Не является прохождением

- два разных Rust-объекта без участия в метаребре;
- равенство только на одном конечном наборе;
- два provenance-текста без машинной зависимости;
- флаг `anchored` без повторного использования и отзыва;
- прохождение λ β-reduction;
- специальный код, знающий имена `a`, `b`, `p` или `q`.

После прохождения этого теста следующий физический вариант использует две
intensions эффекта Джанибекова — линеаризацию и геометрическое пересечение
инвариантов — но не расширяет сам фундамент под физику.
