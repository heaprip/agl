# PoC v0: что реализовано и какая выбрана семантика

**Реализация.** Устаревает при смене стека. Ядро, которое здесь исполняется, —
решение 17. Детерминизм и симуляционное тестирование — решение 18.

## Запуск

```sh
cargo run -- cases/*.agl          # прогон казусов: PASS/FAIL по каждому запросу
cargo run -- -v cases/les-justes.agl   # с объяснениями
cargo test                        # казусы, линтер, симуляционные тесты (500 seed)
AGL_SIM_SEEDS=200000 cargo test --release --test sim
AGL_SEED=2551 cargo test --test sim    # повторить один seed
```

Зависимостей нет: только стандартная библиотека.

## Нотация

```text
axis NAME                          value AXIS VALUE [in PARENT]
overlap AXIS A B                   plane NAME = SPEC
normative_axis AXIS                normative PRED
relation PRED(role, ...)           gap PRED KIND [resolved_by AXIS]
fact ID: LITERAL @ SPEC [STATUS]
rule ID strict|defeasible @ SPEC: LITERAL <- LIT, LIT, ...
defeats WINNER LOSER
unique REL(role) by (key, key, ...)
status MOST_TRUSTED > ... > LEAST_TRUSTED
forbid LITERAL @ SPEC
include RELATIVE/PATH.agl          # подставляется на месте; номера строк — в развёрнутом тексте
query LITERAL @ SPEC [situate CONTEXT] [expect yes|no|unknown|conflict|gap]
concept NAME(role: ?v, ...) @ SPEC: ATOM, ..., ?a != ?b
word LANG WORD = CONCEPT
cover REL(role) | REL(role) ...
compare NAME @ SPEC vs NAME @ SPEC [expect same|below|above|apart|not_below|unknown]
```

В теле правила, кроме атомов, могут стоять:

- сравнения `?a < ?b` и присваивание `?v = EXPR`, где EXPR строится из
  `+ - * / ^` и скобок;
- агрегаты `?v = sum(EXPR) over (ATOM, ...)`, а также `count`, `min`, `max`.

Числа могут нести единицы: `9.81[m/s^2]`, `-16.7[kJ/mol]`, `760[mmHg]`. Значения
хранятся в СИ.

- `SPEC` — сумма имён плоскостей и `axis:value` через `+`. Пустой `SPEC` означает
  плоскость без ограничений.
- Отрицание — `¬` или `~`.
- Правило продолжается на следующей строке, пока строка кончается на `,` или
  `<-`.

## Семантика

**Плоскость** — набор ограничений по осям.

- Значения оси образуют дерево: значение лежит внутри своих предков.
- Соседние значения не пересекаются, если между ними (или их предками) не
  объявлено `overlap`.
- Пересечение перекрывающихся значений — составное `a∩b`.

Это подмножество RCC-8:

| Отношение RCC-8 | Как выражается |
| --- | --- |
| eq | одно и то же значение |
| tpp / ntpp | вложение, без различия касания |
| po | `overlap` |
| dc / ec | соседи, без различия касания |

**Видимость.** Факт или правило видны в контексте `c`, если `c` лежит внутри
их плоскости. Это и есть наследование по вложению из казуса с газообменом.

**Вывод** — неподвижная точка и послойное разрешение конфликтов, как в
defeasible logic (условия +∂/−∂; эталон — `tests/oracle.rs`, H48):

1. Считается всё, что выводится, в том числе одновременно `p` и `¬p`.
2. Строгость и ранги читаются по всему замыканию, а не в раунде, когда правило
   впервые сработало. Вывод строг, если строги правило и все посылки; факты
   строги.
3. Атомы размечаются слоями. Вывод **применим**, если все его посылки приняты,
   и **жив**, если ни одна не отвергнута.
   - Атом без противника принят, когда у него есть применимый вывод.
   - Атом с противником принят, когда его применимые выводы побеждают все
     живые выводы противника. Он проиграл, когда даже все его живые выводы не
     побеждают применимые выводы противника. Пока исход зависит от
     неразмеченных атомов, сторона ждёт.
   - Атом отвергнут, когда у него не осталось живых выводов, или когда его
     держит только петля без основания.
4. Сторона побеждает по первому сработавшему правилу:
   1. строгое бьёт отменяемое;
   2. более надёжная сторона той же силы (ранги, см. «Доверие»);
   3. `defeats`, **командное поражение**: каждый вывод противника побит
      каким-то своим. Выводы, которые опираются на собственный атом, не в
      счёт;
   4. более узкая плоскость (специфичность: исключение для личинок звонцов).

   Порядок 2–3 — открытый вопрос автора (В3 разбора).
5. Обе стороны могут проиграть. Строгое против строгого при равных рангах —
   `Hard`, иначе `Unresolved`; конфликт попадает в отчёт.
6. Проигравшие блокируются, и неподвижная точка пересчитывается без них: так
   исчезают их следствия и обновляются агрегаты.

Конфликты, которые опираются друг на друга по кругу, решаются вместе, по всем
живым выводам. `unknown` называет посылки, с которыми атом упал.

**Отличие от DL.** Следствия строгого противоречия блокируются: DL их
сохраняет. Эталон такие программы пропускает.

**Поиск противоречий.** Контексты — все плоскости, которые используются, и все
непустые пересечения любого их числа: замыкание до неподвижной точки, не
больше 4096 контекстов. На пределе отчёт получает ошибку: молчать о
непроверенных пересечениях нельзя. Конфликт показывается в самом широком
контексте, где он виден. Конфликт в непересекающихся плоскостях не возникает
по построению. Имя пересечения нормализовано: часть, которая содержит другую,
отбрасывается (`gestation∩law` и `bio` дают `gestation∩law`).

**«Есть → должно»** (линтер). Предикат, объявленный `normative`, может стоять в
голове правила или в факте только в плоскости с нормативной осью (`view`).
Ветка — это нормативная посылка.

**Размерности** (решение 23). У каждого числа есть показатели по базовым
единицам. Ядро своих единиц не знает: величины и единицы объявляются в
данных, СИ — в `cases/lib/si.agl`:

```
quantity length m            # базовая величина и её единица
unit km = 1e3 m              # необязательный множитель, затем единица
unit N = m kg s^-2
```

Объявления читаются до остального текста и в любом порядке: единица может
ссылаться на объявленную ниже. Число с необъявленной единицей — ошибка
разбора. Размерность печатается по алфавиту базовых единиц (`kg m^2 s^-2`).
Файлы с единицами подключают библиотеку в конце (`include lib/si.agl`),
чтобы номера их строк не сдвигались.

- Сложение, вычитание и сравнение величин разных размерностей — ошибка
  вычисления. Она попадает в отчёт и проваливает проверку. Исключение одно:
  ноль сравним с любой размерностью.
- Показатель степени безразмерен. Нецелая степень размерной величины — ошибка.

**Агрегаты.**

- Агрегат сворачивает **различные решения** своего `over` при текущей
  привязке, в каноническом порядке. Поэтому даже сумма с плавающей точкой не
  зависит от порядка утверждений.
- Группирующие переменные — те, которые агрегат делит с головой и с другими
  литералами. Переменные внутри `over` локальны.
- Правило с агрегатом стоит в страте строго выше отношений, по которым оно
  агрегирует. Цикл через агрегат — ошибка линтера (`aggregate-cycle`).
- Пустая сумма — 0, пустой `count` — 0. Пустые `min` и `max` не дают решения.

**Порядок тела не важен.** Тело — конъюнкция. Перед вычислением оно
переупорядочивается:

1. атомы;
2. сравнения и присваивания — как только связаны их переменные;
3. агрегаты — как только связаны их группирующие переменные.

**Доверие (статусы).** `status measurement > textbook > llm_proposal` задаёт
ранги.

- Ранг факта — ранг его статуса. Статусы, которых нет в списке, получают 0.
- Ранг вывода — ранг самой слабой его посылки: правило не надёжнее худшего, на
  чём стоит.
- Ранг атома — ранг его лучшего вывода, сначала по силе: у строгого атома это
  лучший строгий вывод. Ранг строгого вывода берётся только по строгим
  выводам посылок.
- Если спорят стороны одной силы (обе строгие или обе отменяемые), побеждает
  более надёжная. Ранги сравниваются только среди выводов этой силы, иначе
  отменяемый вывод «одолжил» бы доверие строгому. Эту ошибку симуляция нашла
  на уровне конфликта; уровнем глубже, в ранге строгого вывода, её нашёл
  разбор (К1) и подтвердил эталон.
- Строгий против строгого при равных рангах — по-прежнему `Hard`.
- Без объявления `status` все ранги равны, и поведение прежнее.

**Запреты.** `forbid LITERAL @ SPEC` — ограничение целостности: вывести
совпадающий атом значит нарушить ограничение (`Violation`). Если статусы в
опоре нарушения различаются, в отчёт попадают наименее надёжные факты (`blame`).
Так ствол отвергает кандидатов: несбалансированная реакция от LLM нарушает
`forbid ¬balanced(...)`, и виноватыми названы её факты `[llm_proposal]`. Для
единственности так же: значение с меньшим рангом попадает в `blame`.

**Неполный состав** ядро отдельно не различает. Это выражается агрегатами:
число участников с известной формулой равно числу всех участников.

**Плоскость, выводимая из данных (`situate`).** Запрос может задавать не
плоскость, а контекст: `query … @ situate everest_sprint`.

1. Ядро вычисляет в плоскости запроса атомы `situated(context, axis, value)`
   для этого контекста.
2. Сужает плоскость найденными значениями и повторяет, пока плоскость меняется.
   Сужение только открывает новые правила, и каждая ось фиксируется не больше
   одного раза, поэтому процесс останавливается.
3. Если контекст попадает в непересекающиеся значения одной оси, ответ —
   `conflict`.
4. Если в итоговой плоскости не выводится какое-то `situated`, по которому
   сужали, ответ тоже `conflict`: плоскость подрывает сама себя. Новые
   правила, которые открывает сужение, могут быть отменяющими, так что
   сужение не монотонно (В2 разбора).
5. Запрос отвечается в итоговой плоскости. Основания `situated` идут в начале
   объяснения: цепочка проходит от данных к плоскости и дальше к ответу.

**Отсутствие в основаниях.** Если агрегат не нашёл ни одного решения, в посылках
стоит `∅ none in this context: …` — что искали и не нашли. Рассуждение от
отсутствия видно явно.

**Единственность.** `unique REL(role) by (keys)` разрешает при одинаковых
значениях `keys` не больше одного значения `role`. Нарушение — конфликт вида
`Uniqueness`, с источниками обеих сторон. Так ловится абсурд Гоббса: при
тождестве по критерию нарушения нет, при схлопывании в одно тождество оно есть.

**Пробел.** На запрос о предикате, для которого объявлен `gap ... resolved_by
AXIS`, в контексте без этой оси приходит ответ `gap`, а не `unknown`.

**Ответ на запрос:** `yes`, `no` (выведено отрицание), `conflict`, `gap` или
`unknown`. Открытый мир: «не выведено» не значит «ложно».

## Рефлексия, этап R1: диагноз

Команда `agl --diagnose FILE.agl`, модуль `src/reflect.rs`. Диагноз ничего не
меняет. Удаление правила в нём — проба («что, если бы его не было?»), а не
предложение.

**Цели диагноза:**

- несбывшиеся ожидания: `WrongAnswer`, если вывелось не то, и `Missing`, если не
  вывелось ничего;
- конфликты, найденные поиском (`Conflict`).

Расхождение непересекающихся плоскостей, например моральных веток, сюда не
попадает: конфликтом оно не является.

**Что сообщается:**

- **опора** — все правила, на которых держится результат;
- **виновники** — минимальные (до двух правил) наборы, без которых цель
  снимается и ни одно ожидание не становится хуже. «Хуже» значит: сбывшееся
  перестаёт сбываться, или несбывшееся получает противоположный определённый
  ответ. Учитель — все запросы с `expect`;
- **если виновника нет** — какие удаления сняли бы цель и какие ожидания (по
  строкам) они ломают. Это сигнал, что нужна перестройка плоскостей, а не
  удаление (этап R2);
- **соотношение плоскостей**: плоскость правила — сам контекст, содержит его,
  не пересекается с ним, вложена в него или перекрывает его. Отдельно — «правила
  в одной плоскости: специфичность их не разделит»;
- **для `Missing`** — для каждого правила с нужной головой: почему не видно, или
  какой атом тела не сопоставился.

Пример: правило и исключение из него лежат в одной плоскости Insecta. Удалить
можно любое из них, но удаление ломает либо саранчу, либо личинку. Диагноз так и
говорит и отмечает общую плоскость. Это ровно та ситуация, для которой R2 должен
предложить промежуточную плоскость.

На казусах из `cases/` диагноз находит только схлопывание Гоббса. Виновника он
не называет: убрать `collapse` значит сломать ожидания в строках 68 и 69, которые
этот абсурд и требуют.

## Рефлексия, этап R2: предложения

Команда `agl --propose FILE.agl`, модуль `src/propose.rs`. По диагнозу
порождаются небольшие структурные изменения:

| Операция | Что делает |
| --- | --- |
| `defeats` | объявляет вытеснение между конфликтующими правилами. Если тело победителя включает все условия проигравшего, это отмечается как специфичность по условию |
| перенос правила | переносит правило в более узкую существующую плоскость |
| промежуточное значение | вставляет значение между предком и подмножеством его детей и переносит туда правило |

Каждое изменение применяется к копии программы и проверяется целиком.
Принимается, только если сбывается больше ожиданий и ни одно не становится хуже.
Ранжирование: больше сбывшихся, меньше изменений, затем канонический порядок.

На выходе — патч в нотации `.agl` (строки `-` и `+`). Программа не меняется.
Если нужные плоскости не соседи по дереву, система сообщает, что
промежуточного значения не хватит и может понадобиться новая ось.

Приёмка — `cases/reflection/two-exceptions.agl`. Исключение для звонцов и
веснянок записано на весь таксон. Рефлексия предлагает промежуточное значение
над ними, сбывшихся ожиданий становится 4 из 4 вместо 0. Седьмой инвариант
симуляции: предложения не делают ни одно ожидание хуже и не зависят от порядка
утверждений.

## Обучение: теоретическое обобщение по шаблону

Команда `agl --learn REL FILE.agl`, модуль `src/learn.rs`. Учебная задача —
отношение `REL` и его примеры (запросы с `expect`). Запросы с пометкой
`heldout` при подборе не используются, по ним гипотеза проверяется потом.

**Шаблон `subset`:** `REL(s) ⇐ всё x, для которого R(s, x), имеет P(x)`. Для
отрицания: есть R-связанное x без P. Кандидаты R и P берутся только из
отношений, которые уже есть у программы.

Гипотеза должна объяснить все обучающие примеры. Ранжирование — по отложенным.
Результат — правила-предложения, программа не меняется.

Приёмка — `cases/learning/viability.agl`. Из 32 кандидатов обучению на
бескислородной плоскости отвечает ровно один: «всё потребляемое доступно в
среде». На отложенных ожиданиях — 6 из 6, включая контексты с `situate`.
С одним положительным примером обучению отвечают 20 гипотез, и выбор делают
только отложенные. Слабость: нужные понятия («потребляет», «доступно») были в
словаре, потому что их туда записал помощник.

## Понятия: разложение рядом с выводом

H42, H44; казус — [родство](../cases/kinship.md), модуль `src/concept.rs`,
отчёт — `agl --concepts FILE`.

**Понятие** задаётся необходимым и достаточным условием:

```text
concept mother(ego: ?e, alter: ?a) @: parent(ego: ?e, alter: ?a), female(person: ?a)
```

Тело — положительные атомы и `?a != ?b`, без чисел. Несколько `concept` с одним
именем — смыслы, их объединение. Смысл виден в плоскости так же, как правило.
Атом тела может быть другим понятием. Отношения, которые не понятия, — простые.

**Узнавание.** Каждый смысл компилируется в строгое правило `ИМЯ.k`, и ядро
узнаёт понятие в данных обычным выводом. Номер `k` — по канонической форме
смысла, а не по порядку утверждений.

**Раскрытие.** Понятия в теле заменяются их смыслами, уровень за уровнем, до
простых отношений. Понятие через само себя — ошибка: рекурсивное (предок)
записывается правилом. Итог — объединение конъюнктивных запросов с
неравенствами. Нормальная форма — их ядра (core) без смыслов, которые покрыты
другими. Переменные названы так, чтобы форма не зависела от порядка атомов.

**Сравнение по определениям.** `A ⊑ B`, если при любых фактах каждый ответ A —
ответ B. Это вложение конъюнктивных запросов (Чандра и Мерлин, 1977), с
неравенствами — по Клагу (1988). Проверка идёт по каноническим мирам каждого
смысла A: по одному миру на каждый способ отождествить его переменные, который
не нарушает его неравенств.

- **Покрытие** `cover female(person) | male(person)`: каждый элемент мира,
  который не входит ни в одну альтернативу, по очереди помещается в каждую.
  Ветвление ленивое: ветка кончается, как только B выполняется. Без покрытия
  неверно «родитель = мать ∪ отец»: пол может быть не записан.
- **Плоскости.** Простое отношение читается в плоскости: узкая плоскость
  видит больше фактов. Атом B в контексте `c2` может совпасть с атомом A в
  контексте `c1`, только если `c2` лежит внутри `c1`.
- **С правилами.** Если B — отношение, которое выводят правила, каждый мир A
  записывается как факты, и ядро выводит. Миры, где нарушен `forbid`,
  отбрасываются как невозможные. Миры отождествляют переменные и с
  константами правил и `forbid`, иначе правило `?a != adam` на `adam` не
  проверяется. Можно показать только «ниже» (`below`), иначе `not_below` с
  контрпримером. `below` точно только для монотонных правил: строгих, с
  положительными посылками и с `=`/`!=` между символами. Если правила для B
  агрегируют, сравнивают, вычисляют, отменяемы или отрицают, а контрпримера
  среди канонических миров нет, вердикт — `unknown` с причиной: в большем
  мире вывод может пропасть.
- Вердикт `compare`: `same`, `below`, `above`, `apart`. Объяснение — нормальные
  формы и контрпример: мир, где A есть, а B нет.
- **Каноническая форма** смысла: переменные головы названы по ролям,
  остальные — `?x1`, `?x2`… в именовании с наименьшим текстом. Если роль сама
  называется как нумерованная переменная (`x1`), префикс удлиняется (`x_1`).
  Больше 7 переменных вне головы — перебор именований не делается,
  переменные нумеруются по первому появлению в атомах, отсортированных как
  записаны. Форма тогда не зависит от порядка атомов, но зависит от имён
  переменных.

**Общий род** двух смыслов — наименьшее общее обобщение (Плоткин, 1970):
произведение запросов, сведённое к ядру. Считается, только если связывает все
роли головы. Отчёт ищет его для соседей — прямых частных случаев одного
понятия.

**Отчёт `--concepts`** по каждой плоскости с особыми определениями:

- раскрытие по уровням;
- одинаковые по определению понятия;
- прямые частные случаи;
- объединения `C = A ∪ B`;
- общий род, в том числе безымянный;
- пробелы языков — понятие, у которого в одном языке слово есть, а в другом
  нет.

**Цена.** Отождествлений переменных — число Белла, покрытие умножает миры.
Предел — 8 переменных в смысле, дальше — ошибка «слишком много». Отчёт по 43
понятиям родства — около 1 с.

**Проверка** — `tests/concept.rs`. На случайных понятиях вывод «A ⊑ B»
сверяется с вычислением ядра на случайных фактах, а контрпример, записанный
как факты, должен дать A без B. Отдельно проверяется, что казус родства не
зависит от порядка утверждений и атомов.

## Где верно и что с чем связано (H52)

`--where АТОМ` — где утверждение верно: в каких контекстах выводится атом,
его отрицание или конфликт между ними. Переменные в атоме допустимы: ответ —
по каждому подходящему атому. Контексты — те же, что у поиска противоречий:
используемые плоскости, все их пересечения и корень. Ответ точен для любой
плоскости: видимое в плоскости зависит только от содержащих её используемых
плоскостей, и самая широкая плоскость с тем же набором — один из контекстов
([сверка с пучками](../review/2026-10-24-sheaves.md), п. 2). Нарушения
`unique` атом не отменяют и остаются в отчёте о конфликтах.

```sh
cargo run --release -- --where "mother(ego: mira, alter: ?a)" cases/kinship.agl
```

`--implications` — что с чем ходит вместе. Вычисленные контексты читаются как
формальный контекст (Вилле, 1982): объект — контекст со значениями ролей,
признак — отношение с теми же ролями. Импликация A → B верна, если у каждого
объекта с A есть B ([словарь](../glossary.md#закономерности)). Показываются:

- отношения с одинаковыми объектами (на данных, не по определению);
- импликации без исключений, без следующих по транзитивности: для импликаций с
  одной посылкой это и есть канонический базис;
- почти-импликации (не меньше 3 объектов, не меньше 75% выполняется) с
  исключениями по контекстам.

На родстве до прогона ожидалось: «мать → родитель» нарушается только в
плоскостях вынашивания и только на матерях по рождению. Так и вышло (Лев и
Тамара, Мира и Вера), тест `tests/extent.rs`. Попутно видно различие данных и
определений: на данных `uncle = mothers_brother`, потому что мужей тёть в
данных нет, а по определениям «дядя» шире.

Чего нет: импликаций с несколькими посылками (полного базиса Дюкена — Гига) и
поправки на множественные проверки в `--implications`.

Синтетика на тысячах плоскостей (`examples/planes_noise.rs`,
[разбор](../review/2026-10-24-planes-noise.md)): без поправки случайные
«закономерности без исключений» растут с числом плоскостей (26 на 10 000 при
20 индивидах в плоскости, 149 на 1000 при 6); поправка Бенджамини — Хохберга
держит их около нуля ценой четверти настоящих. Ради опыта ускорено замыкание
пересечений и видимость (`eval::Visibility`): 5000 плоскостей — 67 → 4 с,
вывод не изменился.

## Приёмка по memote

Тест `tests/memote.rs`, казусы `cases/memote/`, загрузчик `tools/memote_ref.py`
(H38). Модель e_coli_core из BiGG (95 реакций, 72 метаболита) и 28 мутантов от
seed. Мутации: убрать участника, сменить коэффициент или заряд, стереть формулу
или заряд, сделать реакцию необратимой, удалить реакцию, обмен, всех
производителей или потребителей метаболита. Есть и метаморфная: реакция,
записанная задом наперёд, — та же реакция, вердикты не меняются.

memote 0.17.0 считает вердикты своими функциями; они записаны в казусы как
ожидания. Правила `cases/memote/rules.agl` пишутся руками и повторяют
определения memote:

- баланс масс и заряда — только для внутренних реакций. «Реакция должна
  сходиться» — отменяемое правило по умолчанию; граничные реакции и биомасса —
  исключения через `defeats`;
- сирота, тупик, отсоединённый метаболит — через агрегаты, с учётом границ
  потока: обратимая реакция и производит, и потребляет.

Итог: 29 вариантов, совпадение поштучное. Строк `query` около 13 000, но
мутанты почти целиком повторяют исходную модель: различных вердиктов около 460
у модели и 57, которые меняют мутации. Тест проверяет, что нотация выражает
определения memote (правила написаны по его исходникам), а не подтверждает ядро
независимо. У теста есть зубы: каждая из шести поломок правил (убрать исключение для биомассы, не
снимать сироту обменом, забыть реакции «только назад», считать сбалансированной
реакцию без формулы или заряда, сменить определение граничной) даёт от 3 до
1634 расхождений.

Не переведено то, что требует линейного программирования:
стехиометрическая согласованность без формул, циклы, производящие энергию,
заблокированные реакции, производство биомассы.

**Масштаб.** Первый прогон не уложился в 10 минут на одну модель: ядро
вычисляло неподвижную точку заново на каждый запрос. Теперь результат
вычисления в плоскости переиспользуется поиском конфликтов и всеми запросами
этой плоскости (`Evals` в `src/check.rs`). Вычисление — чистая функция программы
и плоскости, поэтому семантика не меняется. На модель уходило около 1.2 с
(после смены семантики DL — 2.1 с).

**Скорость, 2026-10-24.** Пять правок без смены вывода: вывод всех казусов и
отчёт `--concepts` совпадают байт в байт, эталон DL — 0 расхождений на 50 000
seed.

1. Запросы с `situate` вычисляли программу заново, мимо `Evals`.
2. Сопоставление атома ищет кандидатов по индексу «отношение, роль, символ» и
   копирует привязку только для подходящих.
3. `founded` (опоры спора без самого атома) — один раз на ключ за решение; для
   атома не на цикле все выводы обоснованы без полного прохода.
4. Каноническая форма понятия перебирает имена без построения запросов.
5. Тест понятий считает нормальную форму один раз на понятие
   (`concept::witness_of`).

Модель memote — 0.1 с, весь `cargo test --release` — около 20 с,
`AGL_SIM_SEEDS=20000` для `tests/sim.rs` — 15 с.

## Детерминизм

- Только `BTreeMap` и `BTreeSet`. `HashMap` с его случайным при каждом
  запуске ключом хеша не используется нигде.
- Нет часов, потоков и глобального генератора случайных чисел. Вся случайность
  тестов идёт от явного seed (SplitMix64, `src/sim.rs`).
- Целые степени — через `powi`. Он детерминирован и не зависит от libm.
  Дробные идут через `powf` и могут различаться на разных платформах; казусы
  их не используют.
- Объяснение выбирается канонически: строгое, затем факт, затем по источнику
  и посылкам. Посылки — упорядоченное множество.
- Контексты при поиске конфликтов сортируются. В отчёт попадает каждый
  различный конфликт: из самых широких контекстов, где он виден, —
  канонически наименьший.

## Симуляционные тесты (`tests/sim.rs`)

Генератор строит по seed случайную программу на маленьком словаре, чтобы
выводы и конфликты действительно встречались. Инварианты:

1. **Тот же seed — тот же отчёт**, байт в байт.
2. **Порядок утверждений не важен.** Факты, правила, запросы и литералы тела
   перемешиваются, а отчёт с объяснениями не меняется.
3. **Видимый факт не опрокидывается отменяемым правилом.**
4. **Факт в непересекающейся плоскости ничего не меняет.**

Шестой инвариант — диагноз детерминирован и не зависит от порядка утверждений.
Пятый инвариант (`real_cases_do_not_depend_on_statement_order`) перемешивает
настоящие казусы из `cases/`.

Прогоны нашли три настоящие зависимости от порядка:

1. контекст конфликта;
2. порядок посылок в объяснении;
3. **семантика агрегата**: агрегат, переставленный раньше связывающих его
   атомов, суммировал по всем реакциям.

Все три исправлены, последняя — планировщиком тела. Четвёртую, ошибку рангов,
см. в «Доверии». Инварианты держатся на 20 000 seed (проверено 2026-10-24,
после послойного разрешения конфликтов); 200 000 проверялись до статусов,
`forbid` и понятий.

## Эталон (`tests/oracle.rs`)

Симуляционные инварианты метаморфные: они ловят зависимость от порядка, но не
неверный ответ, если он детерминирован. Правильность сверяет эталон —
медленный вычислитель defeasible logic по определениям +Δ/+∂ (Antoniou,
Billington, Governatori, Maher 2001), написанный независимо от ядра: на
заземлённых правилах, без плоскостей и агрегатов (H48).

- Отличия от учебного DL названы в шапке файла: отказ по обоснованности (петля
  без основания ложна) и ранги в строгом слое.
- Генератор `gen_flat_program`: тело до 3 атомов, строгие цепочки глубины 3–4
  с отменяемым обходом и противником.
- Сверяются **все** выводы ядра в корне, не только запросы. Два режима: без
  статусов и со статусами.
- Пропускаются, с подсчётом, программы, где документированная семантика ядра
  выходит за определения: следствия строгого противоречия, отменяемый конфликт
  при статусах (порядок ранга и `defeats` — вопрос автора) и литералы, которые
  определения оставляют нерешёнными.
- Отдельный тест проверяет, что эталон верно отвечает на воспроизведения
  разбора b1, b2, b4, b5.

На старом ядре — 44 и 18 расхождений на 5000 seed; сейчас — 0 на 50 000 в обоих
режимах.

## Чего нет

- Различия tpp и ntpp, ec и dc.
- Пробелов, кроме `gap` на предикат. Нет условий снятия для других типов.
- `models` как отношения ядра.
- Отображения в удобных единицах: значения печатаются в СИ (`3.15e-5 m^3 s^-1`
  вместо 1.89 л/мин).
- Различия «состав неполон» и «элемента нет». В гексокиназе отсутствие
  `composition` для элемента считается нулём: это замкнутое допущение о составе,
  а не открытый мир.
- Логарифмов и других трансцендентных функций (ΔG = ΔG°′ + RT ln Q): ради
  детерминизма их нет.
- Возврата заблокированных при потере противника (см. приближение выше).
- Отрицания в определениях понятий: «отчим — муж матери, но не отец» не
  выразить. Сравнение двух понятий учитывает `cover`, но не `forbid` и не
  правила: невозможные миры (человек — сам себе родитель) отсекаются только при
  сравнении с правилами.
