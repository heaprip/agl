# PoC v0: что реализовано и какая выбрана семантика

**Реализация.** Устаревает при смене стека. Ядро, которое здесь исполняется, —
решение 17. Детерминизм и симуляционное тестирование — решение 18.

## Запуск

```sh
cargo run -- cases/*.agl          # прогон казусов: PASS/FAIL по каждому запросу
cargo run -- -v cases/les-justes.agl   # с объяснениями
cargo test                        # казусы, линтер, симуляционные тесты (500 seed)
AGL_SIM_SEEDS=200000 cargo test --release --test sim
AGL_SEED=2551 cargo test --test sim    # повторить один seed
```

Зависимостей нет: только стандартная библиотека.

## Нотация

```text
axis NAME                          value AXIS VALUE [in PARENT]
overlap AXIS A B                   plane NAME = SPEC
normative_axis AXIS                normative PRED
relation PRED(role, ...)           gap PRED KIND [resolved_by AXIS]
fact ID: LITERAL @ SPEC [STATUS]
rule ID strict|defeasible @ SPEC: LITERAL <- LIT, LIT, ...
defeats WINNER LOSER
unique REL(role) by (key, key, ...)
status MOST_TRUSTED > ... > LEAST_TRUSTED
forbid LITERAL @ SPEC
include RELATIVE/PATH.agl          # подставляется на месте; номера строк — в развёрнутом тексте
query LITERAL @ SPEC [situate CONTEXT] [expect yes|no|unknown|conflict|gap]
```

В теле правила, кроме атомов, могут стоять:

- сравнения `?a < ?b` и присваивание `?v = EXPR`, где EXPR строится из
  `+ - * / ^` и скобок;
- агрегаты `?v = sum(EXPR) over (ATOM, ...)`, а также `count`, `min`, `max`.

Числа могут нести единицы: `9.81[m/s^2]`, `-16.7[kJ/mol]`, `760[mmHg]`. Значения
хранятся в СИ.

- `SPEC` — сумма имён плоскостей и `axis:value` через `+`. Пустой `SPEC` означает
  плоскость без ограничений.
- Отрицание — `¬` или `~`.
- Правило продолжается на следующей строке, пока строка кончается на `,` или
  `<-`.

## Семантика

**Плоскость** — набор ограничений по осям.

- Значения оси образуют дерево: значение лежит внутри своих предков.
- Соседние значения не пересекаются, если между ними (или их предками) не
  объявлено `overlap`.
- Пересечение перекрывающихся значений — составное `a∩b`.

Это подмножество RCC-8:

| Отношение RCC-8 | Как выражается |
| --- | --- |
| eq | одно и то же значение |
| tpp / ntpp | вложение, без различия касания |
| po | `overlap` |
| dc / ec | соседи, без различия касания |

**Видимость.** Факт или правило видны в контексте `c`, если `c` лежит внутри
их плоскости. Это и есть наследование по вложению из казуса с газообменом.

**Вывод** — наивная неподвижная точка:

1. Считается всё, что выводится, в том числе одновременно `p` и `¬p`.
2. Для каждой такой пары конфликт разрешается по порядку:
   1. строгое бьёт отменяемое (вывод строг, только если строги правило и все
      посылки; факты строги);
   2. объявленное `defeats`;
   3. более узкая плоскость (специфичность: исключение для личинок звонцов).
3. Проигравшие блокируются, и неподвижная точка пересчитывается без них.
4. Строгое против строгого — `Hard`, настоящее противоречие. Если ни одно
   правило не сработало — `Unresolved`. В обоих случаях блокируются обе
   стороны, и конфликт попадает в отчёт.

**Приближение.** Если сторона, заблокированная из-за конфликта, позже теряет
противника, потому что заблокирована его посылка, она не возвращается. Для PoC
это допустимо, но известно.

**Поиск противоречий.** Контексты — все плоскости, которые используются, и все
непустые попарные пересечения. Конфликт в непересекающихся плоскостях не
возникает по построению.

**«Есть → должно»** (линтер). Предикат, объявленный `normative`, может стоять в
голове правила или в факте только в плоскости с нормативной осью (`view`).
Ветка — это нормативная посылка.

**Размерности.** У каждого числа есть вектор показателей по семи базовым
единицам СИ.

- Сложение, вычитание и сравнение величин разных размерностей — ошибка
  вычисления. Она попадает в отчёт и проваливает проверку. Исключение одно:
  ноль сравним с любой размерностью.
- Показатель степени безразмерен. Нецелая степень размерной величины — ошибка.

**Агрегаты.**

- Агрегат сворачивает **различные решения** своего `over` при текущей
  привязке, в каноническом порядке. Поэтому даже сумма с плавающей точкой не
  зависит от порядка утверждений.
- Группирующие переменные — те, которые агрегат делит с головой и с другими
  литералами. Переменные внутри `over` локальны.
- Правило с агрегатом стоит в страте строго выше отношений, по которым оно
  агрегирует. Цикл через агрегат — ошибка линтера (`aggregate-cycle`).
- Пустая сумма — 0, пустой `count` — 0. Пустые `min` и `max` не дают решения.

**Порядок тела не важен.** Тело — конъюнкция. Перед вычислением оно
переупорядочивается:

1. атомы;
2. сравнения и присваивания — как только связаны их переменные;
3. агрегаты — как только связаны их группирующие переменные.

**Доверие (статусы).** `status measurement > textbook > llm_proposal` задаёт
ранги.

- Ранг факта — ранг его статуса. Статусы, которых нет в списке, получают 0.
- Ранг вывода — ранг самой слабой его посылки: правило не надёжнее худшего, на
  чём стоит.
- Если спорят стороны одной силы (обе строгие или обе отменяемые), побеждает
  более надёжная. Ранги сравниваются только среди выводов этой силы, иначе
  отменяемый вывод «одолжил» бы доверие строгому — эту ошибку нашла симуляция.
- Строгий против строгого при равных рангах — по-прежнему `Hard`.
- Без объявления `status` все ранги равны, и поведение прежнее.

**Запреты.** `forbid LITERAL @ SPEC` — ограничение целостности: вывести
совпадающий атом значит нарушить ограничение (`Violation`). Если статусы в
опоре нарушения различаются, в отчёт попадают наименее надёжные факты (`blame`).
Так ствол отвергает кандидатов: несбалансированная реакция от LLM нарушает
`forbid ¬balanced(...)`, и виноватыми названы её факты `[llm_proposal]`. Для
единственности так же: значение с меньшим рангом попадает в `blame`.

**Неполный состав** ядро отдельно не различает. Это выражается агрегатами:
число участников с известной формулой равно числу всех участников.

**Плоскость, выводимая из данных (`situate`).** Запрос может задавать не
плоскость, а контекст: `query … @ situate everest_sprint`.

1. Ядро вычисляет в плоскости запроса атомы `situated(context, axis, value)`
   для этого контекста.
2. Сужает плоскость найденными значениями и повторяет, пока плоскость меняется.
   Сужение только открывает новые правила, и каждая ось фиксируется не больше
   одного раза, поэтому процесс останавливается.
3. Если контекст попадает в непересекающиеся значения одной оси, ответ —
   `conflict`.
4. Запрос отвечается в итоговой плоскости. Основания `situated` идут в начале
   объяснения: цепочка проходит от данных к плоскости и дальше к ответу.

**Отсутствие в основаниях.** Если агрегат не нашёл ни одного решения, в посылках
стоит `∅ none in this context: …` — что искали и не нашли. Рассуждение от
отсутствия видно явно.

**Единственность.** `unique REL(role) by (keys)` разрешает при одинаковых
значениях `keys` не больше одного значения `role`. Нарушение — конфликт вида
`Uniqueness`, с источниками обеих сторон. Так ловится абсурд Гоббса: при
тождестве по критерию нарушения нет, при схлопывании в одно тождество оно есть.

**Пробел.** На запрос о предикате, для которого объявлен `gap ... resolved_by
AXIS`, в контексте без этой оси приходит ответ `gap`, а не `unknown`.

**Ответ на запрос:** `yes`, `no` (выведено отрицание), `conflict`, `gap` или
`unknown`. Открытый мир: «не выведено» не значит «ложно».

## Рефлексия, этап R1: диагноз

Команда `agl --diagnose FILE.agl`, модуль `src/reflect.rs`. Диагноз ничего не
меняет. Удаление правила в нём — проба («что, если бы его не было?»), а не
предложение.

**Цели диагноза:**

- несбывшиеся ожидания: `WrongAnswer`, если вывелось не то, и `Missing`, если не
  вывелось ничего;
- конфликты, найденные поиском (`Conflict`).

Расхождение непересекающихся плоскостей, например моральных веток, сюда не
попадает: конфликтом оно не является.

**Что сообщается:**

- **опора** — все правила, на которых держится результат;
- **виновники** — минимальные (до двух правил) наборы, без которых цель
  снимается и ни одно ожидание не становится хуже. «Хуже» значит: сбывшееся
  перестаёт сбываться, или несбывшееся получает противоположный определённый
  ответ. Учитель — все запросы с `expect`;
- **если виновника нет** — какие удаления сняли бы цель и какие ожидания (по
  строкам) они ломают. Это сигнал, что нужна перестройка плоскостей, а не
  удаление (этап R2);
- **соотношение плоскостей**: плоскость правила — сам контекст, содержит его,
  не пересекается с ним, вложена в него или перекрывает его. Отдельно — «правила
  в одной плоскости: специфичность их не разделит»;
- **для `Missing`** — для каждого правила с нужной головой: почему не видно, или
  какой атом тела не сопоставился.

Пример: правило и исключение из него лежат в одной плоскости Insecta. Удалить
можно любое из них, но удаление ломает либо саранчу, либо личинку. Диагноз так и
говорит и отмечает общую плоскость. Это ровно та ситуация, для которой R2 должен
предложить промежуточную плоскость.

На казусах из `cases/` диагноз находит только схлопывание Гоббса. Виновника он
не называет: убрать `collapse` значит сломать ожидания в строках 68 и 69, которые
этот абсурд и требуют.

## Рефлексия, этап R2: предложения

Команда `agl --propose FILE.agl`, модуль `src/propose.rs`. По диагнозу
порождаются небольшие структурные изменения:

| Операция | Что делает |
| --- | --- |
| `defeats` | объявляет вытеснение между конфликтующими правилами. Если тело победителя включает все условия проигравшего, это отмечается как специфичность по условию |
| перенос правила | переносит правило в более узкую существующую плоскость |
| промежуточное значение | вставляет значение между предком и подмножеством его детей и переносит туда правило |

Каждое изменение применяется к копии программы и проверяется целиком.
Принимается, только если сбывается больше ожиданий и ни одно не становится хуже.
Ранжирование: больше сбывшихся, меньше изменений, затем канонический порядок.

На выходе — патч в нотации `.agl` (строки `-` и `+`). Программа не меняется.
Если нужные плоскости не соседи по дереву, система сообщает, что
промежуточного значения не хватит и может понадобиться новая ось.

Приёмка — `cases/reflection/two-exceptions.agl`. Исключение для звонцов и
веснянок записано на весь таксон. Рефлексия предлагает промежуточное значение
над ними, сбывшихся ожиданий становится 4 из 4 вместо 0. Седьмой инвариант
симуляции: предложения не делают ни одно ожидание хуже и не зависят от порядка
утверждений.

## Детерминизм

- Только `BTreeMap` и `BTreeSet`. `HashMap` с его случайным при каждом
  запуске ключом хеша не используется нигде.
- Нет часов, потоков и глобального генератора случайных чисел. Вся случайность
  тестов идёт от явного seed (SplitMix64, `src/sim.rs`).
- Целые степени — через `powi`. Он детерминирован и не зависит от libm.
  Дробные идут через `powf` и могут различаться на разных платформах; казусы
  их не используют.
- Объяснение выбирается канонически: строгое, затем факт, затем по источнику
  и посылкам. Посылки — упорядоченное множество.
- Контексты при поиске конфликтов сортируются. В отчёт попадает каждый
  различный конфликт с канонически наименьшим контекстом.

## Симуляционные тесты (`tests/sim.rs`)

Генератор строит по seed случайную программу на маленьком словаре, чтобы
выводы и конфликты действительно встречались. Инварианты:

1. **Тот же seed — тот же отчёт**, байт в байт.
2. **Порядок утверждений не важен.** Факты, правила, запросы и литералы тела
   перемешиваются, а отчёт с объяснениями не меняется.
3. **Видимый факт не опрокидывается отменяемым правилом.**
4. **Факт в непересекающейся плоскости ничего не меняет.**

Шестой инвариант — диагноз детерминирован и не зависит от порядка утверждений.
Пятый инвариант (`real_cases_do_not_depend_on_statement_order`) перемешивает
настоящие казусы из `cases/`.

Прогоны нашли три настоящие зависимости от порядка:

1. контекст конфликта;
2. порядок посылок в объяснении;
3. **семантика агрегата**: агрегат, переставленный раньше связывающих его
   атомов, суммировал по всем реакциям.

Все три исправлены, последняя — планировщиком тела. Сейчас инварианты держатся
на 200 000 seed.

## Чего нет

- Различия tpp и ntpp, ec и dc.
- Пробелов, кроме `gap` на предикат. Нет условий снятия для других типов.
- `models` как отношения ядра.
- Отображения в удобных единицах: значения печатаются в СИ (`3.15e-5 m^3 s^-1`
  вместо 1.89 л/мин).
- Различия «состав неполон» и «элемента нет». В гексокиназе отсутствие
  `composition` для элемента считается нулём: это замкнутое допущение о составе,
  а не открытый мир.
- Логарифмов и других трансцендентных функций (ΔG = ΔG°′ + RT ln Q): ради
  детерминизма их нет.
- Возврата заблокированных при потере противника (см. приближение выше).
