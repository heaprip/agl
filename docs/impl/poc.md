# PoC v0: что реализовано и какая выбрана семантика

**Реализация.** Устаревает при смене стека. Ядро, которое здесь исполняется, —
решение 17. Детерминизм и симуляционное тестирование — решение 18.

## Запуск

```sh
cargo run -- cases/*.agl          # прогон казусов: PASS/FAIL по каждому запросу
cargo run -- -v cases/les-justes.agl   # с объяснениями
cargo test                        # казусы, линтер, симуляционные тесты (500 seed)
AGL_SIM_SEEDS=200000 cargo test --release --test sim
AGL_SEED=2551 cargo test --test sim    # повторить один seed
```

Зависимостей нет: только стандартная библиотека.

## Нотация

```text
axis NAME                          value AXIS VALUE [in PARENT]
overlap AXIS A B                   plane NAME = SPEC
normative_axis AXIS                normative PRED
relation PRED(role, ...)           gap PRED KIND [resolved_by AXIS]
fact ID: LITERAL @ SPEC [STATUS]
rule ID strict|defeasible @ SPEC: LITERAL <- LIT, LIT, ...
defeats WINNER LOSER
query LITERAL @ SPEC [expect yes|no|unknown|conflict|gap]
```

- `SPEC` — сумма имён плоскостей и `axis:value` через `+`. Пустой `SPEC` означает
  плоскость без ограничений.
- Отрицание — `¬` или `~`.
- Правило продолжается на следующей строке, пока строка кончается на `,` или
  `<-`.

## Семантика

**Плоскость** — набор ограничений по осям.

- Значения оси образуют дерево: значение лежит внутри своих предков.
- Соседние значения не пересекаются, если между ними (или их предками) не
  объявлено `overlap`.
- Пересечение перекрывающихся значений — составное `a∩b`.

Это подмножество RCC-8:

| Отношение RCC-8 | Как выражается |
| --- | --- |
| eq | одно и то же значение |
| tpp / ntpp | вложение, без различия касания |
| po | `overlap` |
| dc / ec | соседи, без различия касания |

**Видимость.** Факт или правило видны в контексте `c`, если `c` лежит внутри
их плоскости. Это и есть наследование по вложению из казуса с газообменом.

**Вывод** — наивная неподвижная точка:

1. Считается всё, что выводится, в том числе одновременно `p` и `¬p`.
2. Для каждой такой пары конфликт разрешается по порядку:
   1. строгое бьёт отменяемое (вывод строг, только если строги правило и все
      посылки; факты строги);
   2. объявленное `defeats`;
   3. более узкая плоскость (специфичность: исключение для личинок звонцов).
3. Проигравшие блокируются, и неподвижная точка пересчитывается без них.
4. Строгое против строгого — `Hard`, настоящее противоречие. Если ни одно
   правило не сработало — `Unresolved`. В обоих случаях блокируются обе
   стороны, и конфликт попадает в отчёт.

**Приближение.** Если сторона, заблокированная из-за конфликта, позже теряет
противника, потому что заблокирована его посылка, она не возвращается. Для PoC
это допустимо, но известно.

**Поиск противоречий.** Контексты — все плоскости, которые используются, и все
непустые попарные пересечения. Конфликт в непересекающихся плоскостях не
возникает по построению.

**«Есть → должно»** (линтер). Предикат, объявленный `normative`, может стоять в
голове правила или в факте только в плоскости с нормативной осью (`view`).
Ветка — это нормативная посылка.

**Пробел.** На запрос о предикате, для которого объявлен `gap ... resolved_by
AXIS`, в контексте без этой оси приходит ответ `gap`, а не `unknown`.

**Ответ на запрос:** `yes`, `no` (выведено отрицание), `conflict`, `gap` или
`unknown`. Открытый мир: «не выведено» не значит «ложно».

## Детерминизм

- Только `BTreeMap` и `BTreeSet`. `HashMap` с его случайным при каждом
  запуске ключом хеша не используется нигде.
- Нет часов, потоков и глобального генератора случайных чисел. Вся случайность
  тестов идёт от явного seed (SplitMix64, `src/sim.rs`).
- Целые степени — через `powi`. Он детерминирован и не зависит от libm.
  Дробные идут через `powf` и могут различаться на разных платформах; казусы
  их не используют.
- Объяснение выбирается канонически: строгое, затем факт, затем по источнику
  и посылкам. Посылки — упорядоченное множество.
- Контексты при поиске конфликтов сортируются. В отчёт попадает каждый
  различный конфликт с канонически наименьшим контекстом.

## Симуляционные тесты (`tests/sim.rs`)

Генератор строит по seed случайную программу на маленьком словаре, чтобы
выводы и конфликты действительно встречались. Инварианты:

1. **Тот же seed — тот же отчёт**, байт в байт.
2. **Порядок утверждений не важен.** Факты, правила, запросы и литералы тела
   перемешиваются, а отчёт с объяснениями не меняется.
3. **Видимый факт не опрокидывается отменяемым правилом.**
4. **Факт в непересекающейся плоскости ничего не меняет.**

Первые прогоны нашли две настоящие зависимости от порядка: контекст
конфликта и порядок посылок в объяснении. Обе исправлены. Сейчас инварианты
держатся на 200 000 seed.

## Чего нет

- Агрегации (сумма по участникам) и размерностей. Значит, нет баланса масс
  с резервуарами из казуса с гексокиназой.
- Различия tpp и ntpp, ec и dc.
- Пробелов, кроме `gap` на предикат. Нет условий снятия для других типов.
- `models` как отношения ядра.
- Единственности тождества.
- Возврата заблокированных при потере противника (см. приближение выше).
