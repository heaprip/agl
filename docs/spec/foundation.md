# Спецификация фундамента ядра-машины

Фаза Ф1 [плана](../plan.md). Документ описывает машину до кода: объекты,
операции, инварианты, два прогона на бумаге и приёмку фаз Ф2–Ф4. По нему
пишется ядро; всё, чего здесь нет, ядро не делает. Код Ф2 пишется только
после слова автора об этой спецификации [план, «Фазы»].

Метки у утверждений: [решение N] — [решения](../decisions.md);
[принцип N] — [принципы](../principles.md); [origin §N] —
[исходные заметки](../origin/relation-first-system.md); [помощник] —
предложение помощника, не принятое автором. Все места с меткой [помощник]
собраны в §16 «Вопросы автору».

Источники спецификации — только план, принципы, решения 1–30, исходные
заметки и `now.md`. Архив и код прошлого не открывались [принцип 11].
Операции `Primitive / Glue / Hide / Reify / Restrict` и `Derive / Metaedge`
известны только по именам из плана; их прежнее содержание не читалось, и
разбор в §11.1 опирается на нужды прогонов, а не на прежний текст.

## Главное нерешённое

Машина этой спецификации умеет **представлять** (вхождения, склейка,
точные положения, плоскости, основания, вопрос) и **проверять** (объёмы,
законы в плоскостях, следствия, опровержение). Механизма, которым ядро
**само находит и выделяет** законы и оси — без перебора и без встроенных
образцов, — в спецификации нет:

- оси-законы выводятся встроенным образцом «постоянный сдвиг» (§4.3), а не
  общим механизмом (дыра Д8);
- законы ищутся перебором всех слов до заданной длины (§8.2), сложившаяся
  структура для поиска не используется (дыра Д9);
- среди найденного машина ничего не выделяет: в мире устойчивости нужное
  различие — одно из 113 равноправных разбиений (дыра Д2).

Это одна дыра, а не три. Из-за неё цель Ф4 по этой спецификации не
достигается (§15.3), а «поколение» в Ф3 получается из образца, который на
`parent` даёт ровно поколение. Это главный вопрос автору (§16, вопрос 1).

## 0. Границы и словарь машины

**0.1. Что такое машина.** Процесс с состоянием и набором операций, который
отвечает на запросы и не ставит своих целей [решение 29, решение 16]. Вход —
поток записей двух видов: пакет данных и вопрос. На каждую запись машина
выдаёт отчёт. Состояние — свёртка всех принятых записей (§10).

**0.2. Чего в ядре нет.**

- Чисел мира: количеств, мер, единиц, арифметики как понятий
  [решение 28]. Целые числа есть только внутри представления положений
  (§3) и не образуют ни одного вхождения. Допустимость целого сдвига как
  представления — вопрос автору (§16, вопрос 2).
- Пространственности: высоты, ширины, времени [решение 23]. «Переход» в
  мире устойчивости — обычное отношение, повтор перехода — склейка.
- Выбора геометрии: ни одна операция не берёт «вид представления» как
  параметр [принцип 2].
- Каталога свойств, заданного данными: переместительность,
  функциональность, порядок и т. п. данными не задаются [принцип 3]. В
  самой машине встроенные образцы есть (§4.2, §4.3) — это дыра Д8.
- λ-термов и таблиц как языка ядра [принцип 5, решение 10]. Язык ядра —
  вхождения, склейка, плоскости. Сверка со звёздами — §17.

**0.3. Словарь машины** [помощник]. Короткий явный список
зарезервированных атомов — инструменты машины, а не данные мира. Все
начинаются с `~`; имя данных не может начинаться с `~`.

| Атом | Где используется |
| --- | --- |
| `~glue`, `~part1`, `~part2`, `~port`, `~pair`, `~ident`, `~bind`, `~face`, `~id` | склейка (§2) |
| `~cons`, `~nil` | списки внутри служебных вхождений (§1.6) |
| `~axis.value`, `~axis.shift`, `~axis.law`, `~key`, `~gauge` | оси и ключи (§4) |
| `~plane`, `~bound` | плоскость (§6) |
| `~batch`, `~ground`, `~given`, `~checked`, `~derived`, `~defeasible`, `~defeats` | основания (§7) |
| `~same`, `~not`, `~gap` | отождествление, отрицание, пробел (§7) |
| `~law`, `~sub`, `~holds`, `~fails` | закон (§8) |
| `~question`, `~given-part`, `~find`, `~condition`, `~goal`, `~keep`, `~ready`, `~answer`, `~branch` | вопрос и ответ (§9) |

Роли внутри этих вхождений перечислены там, где вхождение определено.

## 1. Вхождение

**1.1. Что это.** Вхождение — единственная форма факта [решение 10,
решение 17.1; origin §4, §5.1]. Всё, к чему машина может обратиться, —
вхождение: сущность мира, отношение, конструкция, ось, плоскость, основание,
закон, вопрос, ответ.

**1.2. Из чего состоит.** Два вида:

- **атом** — вхождение без портов; задаётся именем (последовательность
  байтов из входа или из словаря машины). Сущности мира (`ann`, `c0`),
  имена отношений (`parent`), имена ролей (`ego`) — атомы;
- **связь** — `kind(role₁: t₁, …, roleₙ: tₙ)`: вид `kind` (вхождение),
  набор портов «роль → цель». Роль — вхождение (обычно атом); цель —
  вхождение или литерал положения (§3). В одной связи роль встречается не
  более одного раза. Порядок портов не значим.

Отношение об отношении — то же вхождение: цель порта может быть связью
[решение 10; origin §4 «отношения первичны», §5.1 «метарёбра»]. Отдельного
объекта «метаребро» нет.

**1.3. Тождество** [помощник]. Вхождение тождественно своей канонической
записи:

- атом записывается своим именем;
- связь записывается как `kind(role: target, …)`, порты упорядочены по
  байтам канонической записи роли; цели записываются рекурсивно; литерал
  положения — в форме §3.2.

Два вхождения с одинаковой записью — одно вхождение. Одно и то же
утверждение из двух источников — одно вхождение с двумя основаниями
(§7.1). Порядок вхождений везде — байтовый порядок канонических записей.
Внутренние номера (плотные индексы для колонок) существуют только внутри
машины и в отчёт не попадают.

**1.4. Вхождения данных и служебные.** Вхождение данных — связь, у которой
есть основание `~given` (пришла в пакете). Служебное вхождение — всё, что
построила машина: склейки, оси, ключи, плоскости, основания, законы,
опровергатели, вопросы, ответы, пробелы. Правила вывода осей (§4.2, §4.3)
смотрят только на вхождения данных, кроме одного названного исключения
(§4.2).

**1.5. Инварианты.**

- И1. Запись вхождения не зависит от порядка, в котором его порты пришли во
  входе.
- И2. Вхождение не меняется после принятия. Новое знание — новые
  вхождения (основания, законы, опровергатели), а не правка старых.
- И3. Совпадение проекций (точек §4, объёмов §2.2) не делает два
  вхождения одним [решение 17]. Отождествление — только вхождение
  `~same` с основанием (§7.2).

**1.6. Множества и последовательности внутри служебных вхождений**
[помощник]. Роль в связи встречается один раз, поэтому набор записывается
списком: `~cons(head: x₁, tail: ~cons(head: x₂, tail: … ~nil))`.

- множество — список, элементы упорядочены по канонической записи;
- последовательность — список в своём порядке; у цикла начало — наименьший
  по записи элемент, направление — к меньшему из двух его соседей по циклу.

**1.7. Почему этот объект.** Без него нет ничего; он и есть relation-first.
Атом — вырожденная связь без портов; сущность — не отдельный объект, а
вхождение, на которое указывают порты.

## 2. Склейка — единственная операция построения

**2.1. Что это** [помощник; разбор альтернатив — §11.1]. Склейка строит
новое отношение из одного или двух уже имеющихся: отождествляет их порты,
привязывает порты к атомам, решает, какие порты остаются открытыми и под
какими ролями. Склейка — вхождение:

```
~glue(~part1: X, ~part2: Y, ~ident: I, ~bind: B, ~face: F)
```

- `X`, `Y` — отношения (имя отношения данных, `~id`, другая склейка);
  `~part2` может отсутствовать;
- порт части `i` — `~port(part: ~part1|~part2, role: r)`, ниже `i.r`;
- `I` — множество `~pair(left: i.r, right: j.s)`: порты отождествлены;
- `B` — множество `~pair(left: i.r, right: a)`: порт привязан к атому `a`;
- `F` — множество `~pair(left: ρ, right: i.r)`, инъективное по `ρ`: открытая
  роль `ρ` результата — порт `i.r`. Ниже пишется `ρ ← i.r`.

Множества — списки §1.6. Порты частей, не достижимые из `F` через `I`,
скрыты.

**2.2. Объём.** Объём отношения в плоскости `P` (§6) — множество кортежей
«роль → цель»:

- для имени отношения данных `K`: кортежи портов всех вхождений вида `K`,
  которые лежат в `P` (статус «внутри» или «охватывает», §6.4);
- для `~id(over: q)` — §2.3;
- для склейки: все кортежи `t` над открытыми ролями, для которых найдутся
  кортежи частей `τ₁ ∈ ext_P(X)`, `τ₂ ∈ ext_P(Y)` такие, что порты из `I`
  равны, порты из `B` равны своим атомам, и `t(ρ) = τᵢ(r)` для каждого
  `ρ ← i.r`. Скрытые порты — «найдётся».

Объём конечен, перечисляется в байтовом порядке кортежей.

**2.3. Тождественное отношение `~id`** [решение 17.3; помощник].
`~id(over: q)` с ролями `from`, `to`, где `q` — вопрос. Носитель — цели
портов букв вопроса `q` (§8.2), лежащих в плоскости:
`ext_P(~id(over: q)) = {(x, x) : x — такая цель}`. Это тождество как
отношение внутри плоскости. Не путать с `~same` (§7.2) — отождествлением
двух сущностей.

**2.4. Производные формы.** Записываются через `~glue`; отдельных операций
не вводят.

| Форма | Склейка |
| --- | --- |
| ориентация `K[p→q]` (прочие порты скрыты) | `~glue(K; F: from ← 1.p, to ← 1.q)` |
| обращение `rev(X)` | `~glue(X; F: from ← 1.to, to ← 1.from)` |
| композиция `X ; Y` | `~glue(X, Y; I: (1.to, 2.from); F: from ← 1.from, to ← 2.to)` |
| конъюнкция `X ∧ Y` | `~glue(X, Y; I: (1.from, 2.from), (1.to, 2.to); F: from ← 1.from, to ← 1.to)` |
| признак на порту | `~glue(X, R; I: (1.ρ, 2.s); B: (2.q, a); F: роли X ← 1.·)` |

Композиция и конъюнкция — разные склейки (одно отождествление против
двух) и разные действия на точках (§5.2) [план Ф1 п. 2]. Слово
`X₁ X₂ … Xₖ` — левоассоциативная композиция `((X₁ ; X₂) ; …) ; Xₖ`;
пустое слово — `~id(over: q)`.

**2.5. Инварианты.**

- И4. Склейка не содержит отрицания: объём монотонен — если
  `ext_P(X) ⊆ ext_P(X′)`, то объём любой склейки с `X` на месте `X′` не
  больше. На этом стоит следствие законов (§8.4).
- И5. Склейки с разной записью — разные вхождения, даже при равном
  объёме и равной точке. Одночленная склейка `~glue(parent; F: …)` — не то
  же вхождение, что атом `parent`.

**2.6. Почему этот объект.** Конструкции нельзя выразить данными: нужно
построить новое отношение из старых. Одна склейка покрывает скрытие портов,
ориентацию, композицию, конъюнкцию и привязку к атому (§11.1). Склейка
сама — вхождение, поэтому «овеществление» отдельной операцией не нужно.

## 3. Положение — точное значение с динамической глубиной

**3.1. Что это** [помощник]. Положение — значение машины, в котором
записано место сущности на оси [решение 26]. Положение — не вхождение и не
число мира: это литерал машины, единственный не-атомный лист, который
может стоять в порту. Почему отдельный объект: над ним нужны точные сумма,
разность, сравнение и вставка между соседями (§3.3), которых у
имён-атомов нет.

**3.2. Запись** [помощник]. Положение `π = (z; f₁, …, fₖ)`:

- `z` — знаковое 64-битное целое (целая часть);
- `f₁ … fₖ` — беззнаковые 64-битные «знаки» дробной части, `k ≥ 0` —
  глубина;
- значение `z + f₁·2⁻⁶⁴ + … + fₖ·2⁻⁶⁴ᵏ`;
- каноническая форма: `fₖ ≠ 0` (хвостовые нули не хранятся).

Это точная двоичная дробь; глубина растёт, когда нужна [решение 26
«динамическая глубина»; принцип 1]. Два положения равны тогда и только
тогда, когда равны их канонические записи.

**3.3. Операции над положениями.** Все точные, без округления.

| Операция | Определение |
| --- | --- |
| сравнение `π < π′` | лексикографически по `(z, f₁, f₂, …)`, недостающие знаки — нули |
| сумма, разность, обратное | поразрядно с переносом; глубина результата — не больше большей из глубин |
| середина `mid(π, π′)` | `(π + π′)/2`; глубина растёт не больше чем на один знак |
| вставка между соседями `π < π′` | новое положение `mid(π, π′)`; существующие положения не трогаются |
| вставка после последнего `π` | `π + 1` (единица целой части) |
| вставка перед первым `π` | `π − 1` |

Умножение положений — только внутри проверки принадлежности плоскости
(§6.3), как промежуточное значение; оно не сохраняется и не выходит
наружу.

**3.4. Колоночная раскладка.** Требование формы данных, а не оптимизация
[план Ф1 п. 2]. Положения одной оси хранятся колонками целых: колонка
носителей (внутренний индекс), колонка опоры (§4.4), колонка `z` (i64),
колонки `f₁ … f_K` (u64). Положение глубины `k < K` имеет нули в колонках
`f_{k+1} … f_K` — это то же значение (§3.2), а не перенумерация.

**3.5. Когда «место кончается»** [помощник]. Три случая:

1. **Глубже принятой раскладки.** Новое положение требует знака `f_{K+1}`.
   Исход — «правка в запасе»: колонка добавляется, у прежних строк в ней
   ноль, их значения не меняются. Перенумерации нет.
2. **Переполнение целой части** (`z` выходит за i64). Исход —
   типизированный пробел `~gap(kind: axis-overflow)` (§7.3); операция не
   выполняется. В мирах Ф2–Ф4 не встречается.
3. **Смысловое**: новое значение нельзя поставить так, чтобы закон оси
   выполнялся (цикл с ненулевым сдвигом, §12.9). Это не нехватка места, а
   опровержение закона: аномалия в плоскости (§7.4). Положения не
   меняются.

**Перестройка** (сжатие глубины, смена опоры, перераспределение
положений) — изменение принятых положений. В Ф2–Ф4 её нет. Если она
понадобится, то только явной операцией, которая создаёт новую ось и
вхождение-соответствие «старое → новое»; старая ось остаётся как была
(§16, вопрос 4).

**3.6. Инварианты.**

- И6. Положение носителя на оси, однажды записанное, не меняется никогда
  (нет перенумерации).
- И7. Ни одна операция машины не порождает вхождение, которое означает
  число, количество или меру [решение 28].

## 4. Ось, ключ, точка

**4.1. Ось.** Ось — вхождение, которое называет закон, по которому
носителям даются положения [решение 26]. Данные не объявляют осей. Виды
осей:

| Вид | Вхождение | Откуда | Порядок |
| --- | --- | --- | --- |
| значения | `~axis.value(rel: R, port: q)` | примитивное отношение данных (§4.2) | нет |
| сдвига | `~axis.shift(rel: R, from: p, to: q)` | образец «каждое вхождение `R` сдвигает на одно и то же» (§4.3) | выведен: направление `R` |
| закона | `~axis.law(law: L, over: α)` | закон, выполненный в части плоскостей семейства (§8.3) | нет |

Неупорядоченное значение — тоже положение на оси; порядок — свойство оси
[решение 26]. У оси значения и оси закона порядок не выведен: машина
хранит положения как целые, но **ни одна операция не использует их
сравнение `<`** на такой оси, только равенство (И8). Первые оси — из
примитивных отношений (оси значения); следующие — законы (оси сдвига и оси
закона) [решение 26]. Оси значения и сдвига выводятся встроенными
образцами, а не общим поиском законов (Д8).

**4.2. Вывод оси значения** [помощник]. Порт `q` отношения данных `R` —
порт значений, если цели, стоящие в `q` вхождений данных `R`, не стоят ни в
каком другом порту ни одного **вхождения данных** (§1.4). Склейки,
привязки `~bind` и прочие служебные вхождения не учитываются. Единственное
исключение — порт `~ground.source` (происхождение утверждения, §7.1): он
проверяется по тому же правилу; другие служебные порты осей не порождают.
Тогда:

- ось `α = ~axis.value(R, q)`;
- значения (атомы в `q`) получают положения: в пакете, где значение
  встретилось впервые, — по байтовому порядку имён, после последнего уже
  занятого (`0, 1, 2, …`);
- каждое вхождение данных `o` вида `R` получает собственный ключ
  `(α, ∅) = pos(o.q)`;
- носитель `e`, стоящий в другом порту `p` отношения `R`, получает
  `(α, ∅) = pos(v)`, если во всех вхождениях `R` с `p = e` значение `q`
  одно и то же (`v`) — отменяемый закон «`p → q` однозначно» с основанием
  `~defeasible`; второе значение для того же `e` — его опровергатель.

Условие «порт значений» тоже отменяемо: если атом-значение появится в
другом порту вхождения данных, основание оси опровергается (аномалия),
положения остаются.

**4.3. Вывод оси сдвига** [помощник, временное решение; дыра Д8]. Это
встроенный образец «потенциал на графе» (§17): машина не находит закон
общим механизмом, а проверяет заранее заложенное свойство. На `parent` он
даёт ровно поколение. Оставлен, чтобы прогон Ф3 был выполним; заменить его
общим механизмом — главный вопрос (§16, вопрос 1).

Кандидат — ориентация `R[p→q]` **отношения данных** `R`, у которой цели
портов `p` и `q` в вхождениях данных пересекаются. Служебные отношения
кандидатами не бывают. Ориентация каноническая: `p` — роль с меньшей
канонической записью. Машина ищет положения носителей такие, что для
каждого вхождения `R` в плоскости `pos(o.q) − pos(o.p) = 1` (единица целой
части; §16, вопрос 2):

1. Носители делятся на связные части по вхождениям `R` (без учёта
   направления).
2. В каждой части опора — носитель с наименьшей канонической записью;
   её положение `0`.
3. Обход в ширину от опоры; у каждого носителя вхождения `R`
   перебираются в байтовом порядке; по `p → q` положение `+1`, по `q → p` —
   `−1`. **Путь-основание** положения носителя — последовательность
   вхождений `R` от опоры до него по дереву обхода.
4. Если вхождение `o` соединяет два уже поставленных носителя с
   несовместимыми положениями — закон в этой части не выполнен.
   Опровергатель — цикл: `o` и пути-основания обоих его концов (без общей
   части путей), записанный как последовательность §1.6.

Если опровергателя нет, ось `A = ~axis.shift(R, p, q)` выведена с
основанием `~defeasible`. Порядок на `A` — направление `R` [решение 26].
Какой конец «плюс» — артефакт канонической ориентации (Д7).

Образец пробуется на каждом кандидате каждого мира. В мире устойчивости он
не проходит ни на одном (§13.3).

**4.4. Опора и калибровка** [помощник]. Строка колонки оси сдвига —
(носитель, опора, положение, путь-основание). Если новые данные связывают
две части с разными опорами, положения не пересчитываются: записывается
вхождение `~gauge(axis: A, from: o₁, to: o₂, by: δ)` — сдвиг между опорами.
Это «правка в запасе» (§3.5). Новый носитель, связанный с уже
поставленным, получает положение по закону оси, путь-основание — путь
соседа плюс связывающее вхождение.

**4.5. Ключ.** `~key(axis: α, at: ρ)`, где `ρ` — одно из:

- `~nil` — собственная координата вхождения (ниже `∅`);
- роль `r` — координата участника в порту `r` («признак на порту»);
- `~pair(left: r, right: s)` — сдвиг между участниками в портах `r` и `s` на
  оси сдвига (ниже `Δ(r→s)`); пишется только для `r < s` в каноническом
  порядке ролей.

**4.6. Точка.** Частичное отображение «ключ → положение». Отсутствие ключа
значит «точка ничего не говорит по этому ключу» (§6.4). Точка вычисляется
относительно плоскости: `point_P(o)`.

**Доступность положения на оси сдвига в плоскости.** Записанное положение
носителя доступно в `P`, если все вхождения его пути-основания лежат в `P`
и в `P` не лежит опровергатель закона этой оси для его части. Иначе в `P`
положение вычисляется заново обходом §4.3 по вхождениям, лежащим в `P`, —
это **положение плоскости**: оно выдаётся в ответе, но не записывается в
колонки [помощник].

| Вхождение | Точка |
| --- | --- |
| атом-носитель | `(α, ∅)` по осям значения (§4.2) и закона (§8.3); `(A, ∅)` по осям сдвига — положение, доступное в `P` |
| вхождение данных `R(r₁: e₁, …)` | собственные `(α, ∅)` по осям значения своих портов и по оси источника (§7.1); для каждого участника `eᵢ` и его ключа `(α, ∅)` — ключ `(α, rᵢ)`; для пар участников с положениями на одной оси сдвига — `(A, Δ(rᵢ→rⱼ)) = pos(eⱼ) − pos(eᵢ)` |
| имя отношения данных `K` (по объёму) | ключи, значение которых одинаково во всех кортежах `ext_P(K)` (точки кортежей — как у вхождения данных, без собственных ключей); пустой объём — пробел `~gap(kind: empty-extension)` |
| склейка (по правилу) | §4.7 |

**4.7. Точка склейки** [помощник]. Вычисляется из точек частей, без
перебора объёма:

1. Порты частей делятся на классы по `I`.
2. Признаки `(α, r)` части переносятся на класс порта `r`; в одном классе
   соединяются конъюнкцией (§5.1); несовместимые — точка `⊥`.
3. Привязка `(i.q, a)` при оси значения `α = ~axis.value(Rᵢ, q)` даёт
   классу каждого другого порта `s` части `i` признак `(α, ∅) = pos(a)`;
   этот шаг стоит на отменяемом законе однозначности `s → q` (§4.2).
4. Сдвиги `(A, Δ(r→s))` частей — рёбра между классами с весом-положением.
5. Для открытых ролей `ρ ← i.r`: признаки класса `r` становятся ключами
   `(α, ρ)`; для пары открытых ролей `ρ₁ < ρ₂` ключ `(A, Δ(ρ₁→ρ₂))` —
   сумма весов вдоль пути между их классами, если путь есть. Если между
   двумя классами есть два пути с разной суммой — точка `⊥`.
6. Признаки скрытых классов в точку не входят.

**Основание точки по правилу** — по слабейшей посылке (§7.1): `~derived`,
если шаги 3–5 не использовали отменяемых законов; `~defeasible`, если
использовали (однозначность §4.2, ось сдвига §4.3).

**Согласованность.** Для склейки с непустым объёмом каждый ключ точки по
правилу есть в точке по объёму с тем же значением. Нарушение — ошибка
машины, кроме случая, когда отменяемый закон, на котором стоит шаг,
опровергнут в `P`; тогда ключ заменяется пробелом. Точка `⊥` по правилу
предсказывает пустой объём; объём проверяется (`~checked`).

**4.8. Инварианты.**

- И8. На оси без выведенного порядка используются только равенство
  положений и подстановка значений (§5.3), но не `<`, не сумма, не
  разность.
- И9. Добавление оси добавляет ключи в точки; существующие ключи и их
  значения не меняются (рост вширь без перенумерации) [решение 26].

## 5. Операции над точками

Все операции точные [решение 26; принцип 1]. Пусть `a`, `b` — точки.

**5.1. Конъюнкция признаков `a ⊓ b`.** Объединение ключей; на общем ключе
значения должны быть равны, иначе `⊥`. Соответствует конъюнкции отношений
(§2.4).

**5.2. Образ композиции.** Для `X ; Y`: признаки на `from` — от `X`, на
`to` — от `Y`, на среднем порту скрываются; сдвиг `Δ(from→to)` = сдвиг `X` +
сдвиг `Y` (§4.7 п. 5). Конъюнкция и композиция различаются:
`parent ∧ parent` даёт точку `parent`, `parent ; parent` — точку со сдвигом
вдвое (§12.6).

**5.3. Разность `a − b`** — смещение `d` [помощник]. По каждому ключу:

| `a` | `b` | `d` |
| --- | --- | --- |
| `x` | `x` (любая ось) | «без изменения» |
| `x` | `y ≠ x`, ось с порядком | `x − y` (положение) |
| `x` | `y ≠ x`, ось без порядка | подстановка `y ↦ x` |
| `x` | нет | добавление `∅ ↦ x` |
| нет | `y` | снятие `y ↦ ∅` |

**5.4. Сумма `a + d`** — приложение смещения. По каждому ключу `d`:
«без изменения» — ключ `a` переносится; положение — сложить (у `a` ключа
нет — пробел `~gap(kind: shift-undefined)`); подстановка `y ↦ x` — у `a`
должно быть `y`, иначе пробел; добавление `∅ ↦ x` — у `a` ключа нет (или уже
`x`), иначе пробел; снятие `y ↦ ∅` — у `a` должно быть `y`. Ключи `a`,
которых нет в `d`, переносятся. Точка понятия-признака `w` с собственным
ключом `(α, ∅)`, перенесённая на порт `ρ`, — `w@ρ` (ключ `(α, ρ)`),
читается как добавление. Так «родитель + женщина@alter = мать» — точная
сумма (§12.5).

**5.5. Сдвиг-аналогия** `a : b :: c : ?` — `c + (b − a)`.

**5.6. Расстояние `dist(a, b)`** — точка, не одно значение: по общему
ключу оси с порядком — `|x − y|`; оси без порядка — «равны» / «различны»;
ключ только у одной точки — «несравнимо». Свернуть расстояние машина может
только в проверке плоскости (§6.3).

**5.7. Вложение `a ⊑ b`** («`a` частнее `b`»): каждый ключ `b` есть в `a`
с тем же значением. Вложение точек — проекция; вложение объёмов
`ext(X) ⊆ ext(Y)` — проверка; машина сообщает оба и не выводит одно из
другого.

**5.8. Реализация `realize(d)`** [помощник]. Вход — точка или смещение.
Смещение сначала приводится к **цели**: ключи «без изменения» и сдвиги,
равные нулю, отбрасываются; добавления `∅ ↦ x` и подстановки `y ↦ x` дают
ключ со значением `x`; ненулевой сдвиг остаётся; снятие — пробел
`~gap(kind: realize-ambiguous)`. Роли цели — роли, названные в её ключах.
Машина выдаёт:

- (а) все вхождения состояния, у которых точка равна цели **и** множество
  открытых ролей равно ролям цели;
- (б1) если в цели только признаки: каноническая склейка — для каждого
  признака `(α, r)` с `α = ~axis.value(R, q)` и значением `v` — часть `R`
  с привязкой `q = v` и открытой ролью `r ← `носитель `R` (порт, по
  которому однозначен `q`); несколько признаков — склейки, соединённые по
  `I` в порядке ролей;
- (б2) если в цели один сдвиг `Δ(r→s) = k` единиц по оси
  `~axis.shift(R, p, q)` (`k` — ненулевое целое) и признаки на `r`, `s`:
  слово из `k` ориентаций `R[p→q]` (при `k < 0` — `|k|` обращений);
  начало слова получает роль `r`, конец — роль `s`; признаки ставятся на
  соответствующий конец, как в (б1).

Дробный сдвиг, несколько сдвигов, сдвиг вместе с признаками на скрытых
ролях — пробел `~gap(kind: realize-ambiguous)` с перечислением (а). Каноническая
склейка — отдельное вхождение (И5), даже если (а) уже выдало вхождение с
тем же объёмом.

## 6. Плоскость

**6.1. Что это.** Плоскость — окрестность в том же пространстве точек, в
котором лежат понятия, сущности и утверждения [решение 27, решение 15].
Не кусок разбиения: плоскости перекрываются и вкладываются.

Плоскость — атом-имя `p` (из вопроса) и ограничения
`~bound(plane: p, key: K, center: π, inner: π_in, outer: π_out)`, по одному
на ключ [помощник]. Для ключа оси без порядка допуски не используются
(пишутся нулём): условие — равенство центру. Ключи без ограничения
плоскостью не ограничены. Плоскость без ограничений — `W`, всё состояние.
Две плоскости с разными именами и одинаковыми ограничениями — разные
вхождения (И3).

**6.2. Нестрогая граница.** Принадлежность трёхзначна: внутри, на границе,
снаружи [решение 27]. Граница — не ошибка, а отдельная ветвь ответа
(§9.3).

**6.3. Проверка точки `x`** [помощник; §16, вопрос 5].

1. Ключи оси без порядка: если у `x` ключ есть и значение ≠ центру —
   снаружи.
2. Ключи оси с порядком: `S_in = Σ (dₖ/ρ_in,ₖ)²`, `S_out = Σ (dₖ/ρ_out,ₖ)²`,
   `dₖ = |xₖ − centerₖ|`; при допуске `0` слагаемое — `0`, если `dₖ = 0`, и
   «больше 1» иначе. `S_out > 1` — снаружи; `S_in < 1` — внутри; иначе — на
   границе. Сравнение — умножением на общий знаменатель, без деления.
3. Ключи плоскости, которых у `x` нет, — статус «охватывает» (§6.4).

С одним ключом оси с порядком проверка — отрезок с нестрогими концами; с
несколькими — эллипсоид. Миры Ф2–Ф4 используют только плоскости, в которых
не больше одного ключа оси с порядком, и от правила свёртки не зависят.

**6.4. Статусы и что где лежит** [помощник; §16, вопрос 5].

- Вхождения данных, атомы-носители, имена отношений и склейки: «внутри»,
  «на границе», «охватывает» (у точки нет ключа, которым ограничена
  плоскость: вхождение ничего не говорит об этой оси), «снаружи».
- **Служебные вхождения** (основания, опровергатели, законы, оси, ключи,
  плоскости, вопросы, ответы, пробелы, списки `~cons`) собственных точек не
  имеют и «охватывать» не могут. Служебное вхождение лежит в `P` тогда и
  только тогда, когда в `P` лежат («внутри» или «охватывает») все вхождения
  данных, на которые оно указывает портами — прямо или через другие
  служебные вхождения и списки. Не указывающее ни на одно вхождение данных
  (ось, закон о склейках) ни в какой плоскости не лежит; его действие в
  плоскости определяется проверкой в ней (§8).

Ограничение объёма плоскостью (§2.2) берёт вхождения со статусами
«внутри» и «охватывает»; вхождения «на границе» дают отдельную ветвь
(§9.3).

**6.5. Пересечение и вложение.**

- Пересечение `P ∩ Q`: точка должна пройти обе проверки; на общем ключе оси
  без порядка с разными центрами пересечение пусто.
- Вложение `P ⊆ Q` машина проверяет **по объёму**: каждое вхождение
  состояния, лежащее «внутри» `P`, лежит «внутри» `Q` [помощник].
  Геометрическое вложение окрестностей не вычисляется (Д5).

**6.6. Где ищется противоречие.** Противоречие и аномалия ищутся только
внутри плоскости: среди вхождений, которые в ней лежат (§7.4). Набор
участников виден в плоскости, только если все участники в ней лежат, — то
есть в пересечении плоскостей, содержащих каждого участника [решение 15].
Опровергатель — служебное вхождение, указывающее на участников; по §6.4 он
лежит ровно там же.

**6.7. Почему не отдельный «контекст».** Источник, мир-отображение и т. п.
— оси значения (§4.2, §7.1), плоскость по ним — окрестность в общем
пространстве (§11.2).

## 7. Основание, тождество, отрицание, пробел; противоречие и аномалия

**7.1. Основание** [решение 17.6]. Связь

```
~ground(claim: o, kind: k, by: b, source: s)
```

- `kind` — `~given` (дано во входе), `~checked` (проверено перебором объёма
  в конечной плоскости — строго для её текущего содержимого), `~derived`
  (следует по правилу машины из строгих посылок), `~defeasible` (опирается
  хотя бы на один отменяемый закон: выполнено на всём, что есть, может быть
  опровергнуто новыми данными);
- `by` — путь построения: вхождение правила, вопроса или пакета
  `~batch(source: s, at: π)`, где `π` — положение записи в журнале (§10.1);
- `source` — только у `~given`: имя источника пакета.

**Правило слабейшей посылки** [помощник]: основание вывода — `~defeasible`,
если хотя бы одна посылка отменяемая; иначе `~derived`. Применяется ко всем
выводам машины (точки по правилу, следствия, предсказания пустоты).

Опровергатель — `~defeats(claim: o, by: w)`, где `w` — вхождение-контрпример
или список §1.6. Отменяемое основание с опровергателем, лежащим в `P`
(§6.4), в `P` не действует; в остальных плоскостях действует.

Порт `~ground.source` — порт значений (§4.2), поэтому у вхождений данных
есть ось источника `~axis.value(~ground, source)` и плоскости источников
(§12.2).

**7.2. Отождествление.** `~same(a: x, b: y, plane: P)` с основанием — внутри
`P` объём считается с `x` и `y` как одной целью [решение 17.3]. Совпадение
точек или объёмов отождествления не создаёт (И3). В мирах Ф2–Ф4 `~same` не
возникает.

**7.3. Типизированный пробел** `~gap(kind: …, at: …)` [решение 17.7] —
результат, которого нет, с причиной: `empty-extension`, `shift-undefined`,
`realize-ambiguous`, `axis-overflow`, `incompatible` (точка `⊥`),
`defeated` (закон опровергнут в плоскости), `not-functional`. Пробел —
вхождение отчёта, а не ошибка машины.

**7.4. Противоречие и аномалия.** В плоскости `P`:

- **противоречие** — в `P` лежат и `o`, и `~not(o)` [решение 17.2];
- **аномалия** — отменяемый закон имеет в `P` опровергатель (§4.2, §4.3,
  §8.5).

Отчёт о каждом: участники (по правилам §4.3 п. 4 и §1.6) и плоскости
вопроса, в которых лежат все участники (§6.6). Противоречие не
останавливает машину и не распространяется за пределы этих плоскостей
[origin §7 «локализуется»].

**7.5. `holds(claim, plane, status)`** [решение 17.5] — вычисляемое
отношение: статус в плоскости — `~holds` со строгим или отменяемым
основанием, `~defeated`, `~contradicted`, «на границе», пробел.

## 8. Закон и закрепление

**8.1. Закон** [помощник] — вхождение `~law(left: X, right: Y, rel: ~sub)`:
«объём `X` содержится в объёме `Y`». Выполнение проверяется в каждой
плоскости отдельно, основание `~checked`. Равенство — два закона. Ось
сдвига (§4.3) и однозначность порта (§4.2) — законы-образцы со своей
процедурой проверки и основанием `~defeasible`.

**8.2. Поиск законов** [помощник; дыра Д9]. Это **перебор**: все слова до
длины `n` и все пары слов. Сложившаяся структура (уже найденные законы,
совпадения объёмов) для поиска не используется [вразрез с принципом 8].
По вопросу (§9) с частями «дано» (отношения), «условия» (семейство
плоскостей) и «когда готово» (предел `n`):

1. Буквы: все ориентации `R[p→q]` данных отношений по парам различных
   портов, не являющихся портами значений (§4.2); прочие порты скрыты.
2. Слова длины `0 … n` над буквами (§2.4); слово длины 0 —
   `~id(over: q)`.
3. Для каждой упорядоченной пары различных слов `(X, Y)` и каждой
   плоскости семейства — проверка `ext_P(X) ⊆ ext_P(Y)`.
4. Ответ: законы, выполненные во всех плоскостях семейства; не выполненные
   ни в одной; и **разбиения** — для каждого множества плоскостей, на
   котором выполнен хотя бы один закон, но не все плоскости, — это
   множество и все законы с ним. Законы с одинаковым множеством не
   склеиваются (И3).
5. Для плоскостей, где закон не выполнен, — свидетель: наименьший по
   канонической записи кортеж `ext_P(X) \ ext_P(Y)`.

Имени у найденного закона нет; его запись — пара слов. Выделения среди
найденного нет (Д2).

**8.3. Ось закона.** Если семейство плоскостей — плоскости по значениям
оси значения `α`, закон `L` с разбиением даёт ось `~axis.law(L, α)`:
значения `α` получают положения атомов `~holds` / `~fails`; ось без
порядка. Вхождения данных с ключом `(α, ∅)` получают ключ
`(~axis.law(L, α), ρ)` через участника в порту `ρ`.

**8.4. Следствие закона** [помощник]. Правила машины; основание — по
слабейшей посылке (§7.1):

- транзитивность: из `X ⊆ Y` и `Y ⊆ Z` в `P` — `X ⊆ Z` в `P`;
- монотонность склейки (И4): из `X ⊆ Y` в `P` — `C[X] ⊆ C[Y]` в `P` для
  склейки-контекста `C`, названной вопросом.

**8.5. Закрепление** [помощник; §16, вопрос 6]. Операция `anchor`, которую
вызывает вопрос [решение 29]: выведенный закон (ось сдвига §4.3 или ось
закона §8.3) становится осью состояния. Записываются вхождение оси, его
основание и колонки положений (с путями-основаниями для оси сдвига).
Существующие оси, положения и точки не меняются (И6, И9). Автоматического
порога закрепления нет.

**Проверка закона оси сдвига после закрепления.** При каждом новом пакете
и в каждой плоскости вопроса закон проверяется так: для каждого вхождения
`R`, лежащего в `P`, у которого оба конца имеют положения, доступные в `P`
(§4.6), — равенство сдвига единице. Нарушение даёт опровергатель: цикл из
этого вхождения и путей-оснований концов (§4.3 п. 4). Концы без доступного
положения ставятся обходом в `P` (положения плоскости, §4.6). Новый
носитель, связанный с поставленным, получает записанное положение
(§4.4), если связывающее вхождение не нарушает закон ни с одним уже
записанным положением.

## 9. Вопрос и ответ

**9.1. Вопрос** — сущность метаграфа с частями [решение 25]: атом-имя
вопроса `q` и связи-части, указывающие на него:

| Часть | Связь | Что содержит |
| --- | --- | --- |
| дано | `~given-part(question: q, item: X)` | отношения, конструкции, точки, законы, на которые опирается вопрос |
| найти | `~find(question: q, what: F)` | вид искомого (§9.2) и аргументы |
| условия | `~condition(question: q, plane: P)` | плоскости ответа; семейство — `~condition(question: q, family: α)`, плоскости по значениям оси `α` |
| цель | `~goal(question: q, test: G)` | чем проверяется ответ (например, «точка равна `d`») |
| чего нельзя | `~keep(question: q, item: K)` | что ответ не меняет; всегда — принятые данные и записанные положения |
| когда готово | `~ready(question: q, bound: π)` | предел работы — литерал положения: длина слова |

Предел — ресурс машины, а не число мира: он ограничивает построение и не
порождает вхождений-чисел (И7). Выбор предела в Ф4 — §13.4, Д9.

**9.2. Виды искомого.** Другого машина не ищет.

| `what` | Ответ |
| --- | --- |
| `ext(X)` | объём `X` в каждой плоскости |
| `point(X)` | точка `X` (по правилу и по объёму) с основанием |
| `diff`, `sum`, `shift`, `dist`, `nest` | §5 |
| `realize(d)` | §5.8 |
| `members(P, V)` | для каждого вхождения из множества `V` — статус относительно `P` (§6.4). `V` задаётся частью «дано»; по умолчанию — все имена отношений данных и все склейки состояния |
| `axes` | вывод осей значения и сдвига (§4.2, §4.3) |
| `laws` | поиск законов (§8.2) |
| `consequence(L, C)` | следствие закона в контексте (§8.4) |
| `anchor(A)` | закрепление (§8.5) |
| `holds(o)` | статус в плоскостях (§7.5) |

**9.3. Ответ — карта ветвей по плоскостям** [решение 25]. Вхождение
`~answer(question: q)` и ветви `~branch(answer: a, planes: S, result: r)`
(`S` — список §1.6) с основаниями. Плоскости, в которых результат одинаков, —
одна ветвь; различающиеся — разные ветви. Если в плоскости есть
вхождения «на границе», результат считается без них и с ними; если
результаты различаются — две ветви с пометкой. Противоречия и аномалии
плоскости — часть её ветви.

## 10. Машина

**10.1. Состояние.** Журнал записей (пакеты и вопросы в порядке
поступления; у каждой записи — положение в журнале, «после последнего»,
§3.3) и его свёртка: множество вхождений и колонки положений осей.
Состояние восстанавливается прогоном журнала с нуля.

**10.2. Записи входа.**

- **пакет**: имя источника и множество вхождений данных. Машина принимает
  вхождения, записывает основания `~given`, выводит оси значения (§4.2) для
  новых портов значений, ставит положения новым значениям и носителям
  закреплённых осей, проверяет закреплённые и отменяемые законы (§8.5) и
  записывает опровергатели;
- **вопрос**: части §9.1; машина выполняет искомое и записывает ответ.

**10.3. Отчёт.** На каждую запись — отчёт: канонический текст, строки в
байтовом порядке внутри разделов. Разделы: принятое, оси, положения (для
осей сдвига — записанные, относительно опоры части, и отдельно положения
плоскостей; для осей без порядка — имя значения, а не положение), ответ
(ветви), основания, пробелы, противоречия и аномалии. Положения
печатаются как точная двоичная дробь (`+2`, `-1`, `+3/2`). Внутренние
индексы, адреса, время в отчёт не попадают. Точная грамматика отчёта
дописывается в этот раздел до кода Ф2 (Д6).

**10.4. Детерминизм** [решение 18].

- Д-1. Один журнал и любой seed дают побайтно один и тот же отчёт. В
  Ф2–Ф4 у машины нет случайных выборов; seed принимается и на результат не
  влияет.
- Д-2. Перестановка вхождений внутри пакета и портов внутри вхождения не
  меняет отчёт побайтно (И1; канонический порядок везде).
- Д-3 [помощник; §16, вопрос 4]. Разбиение данных на пакеты может менять
  историю (опоры, положения значений, пути-основания), но не ответы,
  которые от калибровки не зависят: объёмы, сдвиги, законы, разбиения,
  статусы.
- Без коллекций с недетерминированным порядком, без часов, без потоков
  [принцип 8].

**10.5. Операции машины** (полный список): принять пакет; ответить на
вопрос; внутри — склейка и объём (§2), вывод осей (§4.2–4.3), точка и
операции над точками (§4.6–5.8), проверка плоскости (§6), основания и
опровержение (§7), поиск законов, следствие, закрепление и проверка
закреплённого (§8).

## 11. Разбор открытых вопросов плана

### 11.1. Какие операции построения нужны машине

Варианты по именам из плана: (А) `Primitive / Glue / Hide / Reify /
Restrict`; (Б) `Derive / Metaedge`; (В) одна склейка, остальное — её
частные случаи или свойства формы вхождения.

Что нужно прогонам (§12–13): ввести данные; скрыть порт; отождествить
порты; привязать порт к атому; переименовать открытые роли; ограничить
плоскостью; обратиться к конструкции как к сущности.

| Имя | В этой спецификации |
| --- | --- |
| `Primitive` | приём пакета (§10.2): вхождения данных с основанием `~given` |
| `Glue` | `~glue` (§2) |
| `Hide` | порт, не названный в `~face` (§2.1) |
| `Restrict` | объём в плоскости `ext_P` (§2.2): плоскость — параметр вычисления |
| `Reify` | не нужен: склейка уже вхождение (§2.6) |
| `Derive` | вычисление объёма, вывод осей и законов — операции машины (§10.5) |
| `Metaedge` | не операция: связь, порт которой указывает на связь (§1.2) |

Последствия (А): пять операций, три — частные случаи склейки; риск, что
`Reify` создаст второй вид сущности. (Б): `Derive` смешивает построение и
вычисление. (В): одна операция; всё построенное — вхождение.

**Позиция [помощник]:** (В) (§16, вопрос 7).

### 11.2. Оси координат сущности и контекстные оси плоскости

Варианты: (А) одно пространство: «контекст» (источник, мир-отображение) —
ось значения от отношения о вхождении, плоскость — окрестность по ней;
(Б) два пространства: точки понятий отдельно, контексты — именованные
подграфы со своими осями.

Последствия (А): плоскость источника и плоскость «женщина на порту alter»
одного устройства; пересечение плоскостей разных видов определено;
решение 27 «в том же пространстве» выполнено буквально. (Б): две операции
пересечения и мост между пространствами.

**Позиция [помощник]:** (А) (§16, вопрос 8).

## 12. Прогон на бумаге: родство

Только объекты и операции §1–10. Имена конструкций (`mother`, `gp`) —
подписи для читателя; в машине это записи склеек.

### 12.1. Мир

Пакет 1, источник `s1`. Роли: `parent(ego: ребёнок, alter: родитель)`,
`sex(who: …, value: …)`. Два примитивных отношения [план Ф1].

```
parent(ego: cat, alter: ann)    parent(ego: cat, alter: bob)
parent(ego: dan, alter: ann)    parent(ego: dan, alter: bob)
parent(ego: fay, alter: cat)    parent(ego: gus, alter: dan)
parent(ego: gus, alter: eve)
sex(who: ann, value: f)   sex(who: bob, value: m)   sex(who: cat, value: f)
sex(who: dan, value: m)   sex(who: eve, value: f)   sex(who: fay, value: f)
sex(who: gus, value: m)
```

Ни «мать», ни «дед», ни «поколение» в данных нет.

### 12.2. Приём пакета (§10.2)

1. 14 вхождений данных, у каждого `~ground(claim: o, kind: ~given,
   source: s1, by: ~batch(source: s1, at: …))`.
2. Оси значения (§4.2), только по вхождениям данных:
   - `sex.value`: цели `f`, `m` больше нигде не стоят → ось
     `S = ~axis.value(sex, value)`; положения `f ↦ 0`, `m ↦ 1` (порядок не
     выведен, И8);
   - `sex.who`, `parent.ego`, `parent.alter`: цели стоят в других портах →
     не порты значений;
   - `~ground.source` (исключение §4.2): цель `s1` только там → ось
     источника `Src = ~axis.value(~ground, source)`. Прочие порты `~ground`
     осей не порождают.
3. Однозначность `sex: who → value`: у каждого из семи носителей одно
   значение → `(S, ∅)`: `ann, cat, eve, fay ↦ f`; `bob, dan, gus ↦ m`.
   Основание `~defeasible`.
4. Вхождения `parent` получают ключи участников: например,
   `parent(ego: cat, alter: ann)` — `(S, ego) = f`, `(S, alter) = f`,
   `(Src, ∅) = s1`.

### 12.3. «Мать», «дед» — склейки и объёмы (Ф2)

```
mother  = ~glue(parent, sex; I: (1.alter, 2.who); B: (2.value, f);
                F: ego ← 1.ego, alter ← 1.alter)
mother′ = ~glue(sex, parent; I: (1.who, 2.alter); B: (1.value, f);
                F: ego ← 2.ego, alter ← 2.alter)          # части в другом порядке
father  = mother с B: (2.value, m)
gp      = ~glue(parent, parent; I: (1.alter, 2.ego);
                F: ego ← 1.ego, alter ← 2.alter)          # parent ; parent
gf      = ~glue(gp, sex; I: (1.alter, 2.who); B: (2.value, m);
                F: ego ← 1.ego, alter ← 1.alter)
gm      = то же с B: (2.value, f)
pp      = parent ∧ parent    (склейка §2.4 с ролями ego, alter)
pg      = parent ∧ gp
```

Привязка `B: (2.value, f)` — служебное вхождение; на ось `S` она не влияет
(§4.2).

Объёмы в `W` (§2.2), проверка вручную:

| Конструкция | Объём `(ego, alter)` |
| --- | --- |
| `mother`, `mother′` | (cat, ann), (dan, ann), (fay, cat), (gus, eve) |
| `father` | (cat, bob), (dan, bob), (gus, dan) |
| `gp` | (fay, ann), (fay, bob), (gus, ann), (gus, bob) |
| `gf` | (fay, bob), (gus, bob) |
| `gm` | (fay, ann), (gus, ann) |
| `pp` | семь кортежей `parent` |
| `pg` | пусто |

`gp`: из `(gus, eve)` продолжения нет — у `eve` нет вхождения в `ego`.
Основание каждого объёма — `~checked` в `W` с путём построения.

### 12.4. Точки без оси сдвига (Ф2)

- `point(parent)` по объёму: `(S, ego)` и `(S, alter)` не постоянны → `{}`.
  `point(sex)` по объёму: `(S, who)` не постоянен → `{}`.
- `point(mother)` по правилу §4.7: привязка `2.value = f` даёт классу
  `2.who = 1.alter` признак `(S, ∅) = f` → роль `alter`:
  `{(S, alter): f}`, основание `~defeasible` (шаг 3 стоит на однозначности
  `sex`). По объёму: альтеры `ann, ann, cat, eve` — все `f` → то же.
- `point(mother′) = point(mother)`; объёмы равны; это два вхождения с
  пометкой «совпадение проекций», не отождествлены (И3, И5).
- `point(father) = {(S, alter): m}`; `point(gp) = {}`;
  `point(gf) = {(S, alter): m}`; `point(gm) = {(S, alter): f}`;
  `point(pp) = {}`; `point(pg) = {}` по правилу (сдвиговых осей нет),
  по объёму — пробел `empty-extension`.

### 12.5. «Мать − родитель» (Ф2)

`diff(mother, parent)` (§5.3): ключ `(S, alter)` есть только у `mother` →
`d = {(S, alter): ∅ ↦ f}`.

`realize(d)` (§5.8): цель `{(S, alter): f}`, роли цели `{alter}`.
(а) — вхождений с этой точкой и ролями `{alter}` в состоянии нет (`mother`
имеет роли `{ego, alter}`); (б1) — `~glue(sex; B: (1.value, f);
F: alter ← 1.who)`: «на порту `alter` стоит носитель со значением `f` оси
`S`» — «женщина», перенесённая на порт `alter`. Основание `~defeasible`.

Обратно: `sum(parent, d)` = `{(S, alter): f}` = `point(mother)` — точная
сумма «родитель + женщина@alter = мать» (§5.4). Вложение:
`point(mother) ⊑ point(parent)`; объёмы: `ext(mother) ⊆ ext(parent)` —
`~checked`.

### 12.6. Ось «поколение» из образца (Ф3)

Вопрос `axes` в `W` (§4.3; образец, Д8). Кандидаты — ориентации отношений
данных с пересекающимися целями портов:

### 12.7. Операции над точками после закрепления (Ф3)

- `diff(mother, parent) = {Δ: без изменения, (S, alter): ∅ ↦ f}`;
  `realize` — та же склейка (б1), что в §12.5.
- `diff(gp, parent) = {Δ: +1}`; `realize`: цель `{Δ: +1}`, роли
  `{alter, ego}`; (а) — `parent` и `pp` (обе с этой точкой и ролями);
  (б2) — одночленная склейка `~glue(parent; F: alter ← 1.alter,
  ego ← 1.ego)` (слово из одной ориентации, роли по §5.8) — отдельное
  вхождение, не атом `parent` (И5).
- `shift(father, mother, gf)` = `gf + (mother − father)`:
  `mother − father = {Δ: без изменения, (S, alter): m ↦ f}`;
  `gf + … = {Δ: +2, (S, alter): f}`. `realize`: (а) `gm`; (б2) слово
  `parent[alter→ego] parent[alter→ego]`, начало — роль `alter`, конец —

  (gus, ann). Оба выдаются, не отождествляются (И3).
- `dist(mother, gf) = {Δ: 1, (S, alter): различны}`.
- `nest`: `gm ⊑ gp`, `mother ⊑ parent`, `mother ⋢ gp` (`Δ` различен).

## 13. Прогон на бумаге: устойчивость

### 13.1. Мир

Точки `c0, c1, c2, c3`. Соседство — цикл: `nb(a: cᵢ, b: cⱼ)` для
`j = i ± 1 (mod 4)`, восемь вхождений. **Соседство отобрано руками**: цикл
из четырёх — заданный мир (§16, вопрос 13). Переход — **все** отображения
четырёх точек в себя, без отбора [принцип 6]: 256 отображений; каждое —
атом `tXYZW` (`T(c0)=cX`, …), имя — только подпись. Вхождения
`step(map: t, from: cᵢ, to: cⱼ)`, по четыре на отображение — 1024. Мир
порождается загрузчиком в `tools/`; ядро ничего не знает о «цикле» и
«отображении».

### 13.2. Приём пакета

- Порты значений: `step.map` (цели `t…` больше нигде) → ось
  `Map = ~axis.value(step, map)`, 256 положений. `step.from`, `step.to`,
  `nb.a`, `nb.b` — не порты значений.
- У каждого вхождения `step` собственный ключ `(Map, ∅)`; у `nb` его нет.
- Точки `cᵢ` стоят в `from`/`to` вхождений с разными значениями `map` →
  однозначности нет, ключа `(Map, ∅)` у точек нет
  (`~gap(kind: not-functional)`).
- Плоскости-отображения: `Pₜ = {(Map, ∅): t}`. В `Pₜ` «внутри» — четыре
  вхождения `step` с `map = t`; «охватывает» — восемь `nb`; прочие `step` —
  «снаружи».

### 13.3. Образец оси сдвига не проходит

Кандидаты: `step[from→to]`, `nb[a→b]`. В каждой `Pₜ`:

- `step`: у отображения конечного множества в себя есть цикл или
  неподвижная точка; обход встречает вхождение, замыкающее цикл с
  ненулевой суммой → опровергатель;
- `nb`: `nb(c0, c1)` и `nb(c1, c0)` — цикл длины 2 с суммой `+2`.

Ось сдвига не появляется ни в одной плоскости.

### 13.4. Поиск законов (Ф4)

Вопрос: дано `nb`, `step`; условия — семейство по оси `Map`; когда готово —
слова длины ≤ 3; найти — `laws`.

**Почему предел 3.** Честно: закон «соседи остаются соседями» записывается
словом длины 3 (`U N T`), и предел выбран так, чтобы этот известный ответ
попал в перебор. Довода изнутри машины для числа 3 нет (Д9; §16, вопрос 13).

Буквы: `N = nb[a→b]`, `M = nb[b→a]`, `T = step[from→to]`,
`U = step[to→from]`. Слов длины 0–3: `1 + 4 + 16 + 64 = 85`; пустое —
`~id(over: q)` над `{c0, c1, c2, c3}`. Упорядоченных пар различных слов —
`85 · 84 = 7140`, каждая — в 256 плоскостях.

Пример, `t1230` (`T(cᵢ) = cᵢ₊₁`): `ext(U N T) = {(T x, T y) : nb(x, y)}` —
все восемь пар соседей → `U N T ⊆ N` выполнен. В `t0000`:
`ext(U N T) = {(c0, c0)}` → `U N T ⊆ N` не выполнен, свидетель `(c0, c0)`;
`U N T ⊆ ~id` выполнен. В `t0101` все пары соседей переходят в соседей →
выполнен.

Результат (сверено вычислением вне ядра):

| Что | Пар слов |
| --- | --- |
| выполнены во всех 256 плоскостях | 375 |
| не выполнены ни в одной | 1140 |
| разбивают семейство | 5625 |
| различных множеств плоскостей среди разбивающих | 113 |

Три из 113 разбиений:

| Закон | Где выполнен | Плоскостей | Законов с тем же множеством |
| --- | --- | --- | --- |
| `L1: U N T ⊆ N` | `T(cᵢ₊₁)` — сосед `T(cᵢ)` для всех `i` | 32 | 264 |
| `L2: U N T ⊆ N N` | образы соседей совпадают или противоположны | 32 | 74 |
| `L0: U N T ⊆ ~id` | все соседи сливаются (постоянные отображения) | 4 | 70 |

Вне ядра `L1` читается как «соседи остаются соседями». В ядре у `L1` имени
нет: это пара слов, и **машина её не выделяет** — она одно из 113
разбиений, выданных в каноническом порядке. Между разбиениями ядро
сообщает вложения по объёму: `L1` и `L2` не пересекаются; `L0` вложено в
`L2`.

### 13.5. «Остаются» — следствие (Ф4)

Вопрос `consequence(L1, C)` с контекстом `C[X] = U X T`, названным
вопросом:

1. монотонность: `U N T ⊆ N` ⇒ `U (U N T) T ⊆ U N T`;
2. транзитивность с `L1`: `U U N T T ⊆ N`.

Посылки строгие (`~checked` в плоскости, правила машины) → основание
`~derived` в каждой из 32 плоскостей `L1`. Проверка вне ядра: на всех 32
отображениях `T∘T` удовлетворяет `L1`. Выделения это не даёт: хотя бы один
закон, сохраняющийся при такой подстановке, есть в 57 разбиениях из 113.

### 13.6. Закрепление закона без имени (Ф4)

`anchor(~axis.law(L1, Map))`: 256 атомов `t…` получают `~holds` (32) /
`~fails` (224); ось без порядка. Вхождения `step` получают ключ
`(~axis.law(L1, Map), map)`. Ключи `Map` не меняются. Закрепляет `L1`
вопрос, который его назвал; сама машина `L1` не выбирала.

## 14. Дыры, найденные прогонами

- **Д1. Вставка вглубь не нужна ни одному миру.** Положения встают «после»
  или «перед»; середина (§3.3) по смыслу не вызывается. В Ф2–Ф4 вставка
  проверяется только на уровне машины (§15.1 п. 10). Предложение мира, где
  она нужна, — H77.
- **Д2. Выделения среди найденного нет.** Машина находит 113 разбиений и
  не выделяет ни одного; «соседи остаются соседями» — одно из них. Цель Ф4
  не достигается (§15.3). Часть «Главного нерешённого».
- **Д3. Порог закрепления.** Закон становится осью только по вопросу
  `anchor`.
- **Д4. Утверждение из нескольких источников.** По §1.3 это одно вхождение
  с двумя основаниями; `~ground: claim → source` неоднозначен, ключа
  `(Src, ∅)` нет — вхождение «охватывает» все плоскости источников,
  включая те, где его не было. В мирах Ф2–Ф4 не встречается.
- **Д5. Вложение плоскостей как окрестностей** не вычисляется, только по
  объёму (§6.5).
- **Д6. Грамматика отчёта** задана разделами (§10.3), но не побайтно;
  дописать до кода Ф2.
- **Д7. Знак оси сдвига** — от байтового порядка имён ролей (§4.3).
- **Д8. Оси-законы выводятся встроенными образцами, а не общим
  механизмом.** Ось сдвига (§4.3) — заложенный образец «потенциал на
  графе», который на `parent` даёт ровно поколение; ось значения (§4.2) —
  образец «функциональная зависимость». Это перечень свойств, встроенный в
  машину [вразрез с принципом 3]. Оставлен как временное решение
  [помощник]. Часть «Главного нерешённого».
- **Д9. Поиск законов — перебор.** Все слова до длины `n`, все пары;
  сложившаяся структура для отбора не используется [вразрез с принципом 8
  и вступлением принципов]. Предел `n = 3` в Ф4 выбран под известный ответ
  (§13.4). Часть «Главного нерешённого».

**Провал Ф3:** ось «поколение» или «уровень» во входе; любое изменение
записанного положения или пути-основания; опровержение, видимое в `W1`
или `W2`; записанные положения, использованные в `W2`; отличие от п. 1–8.

### 15.3. Ф4 — мир устойчивости

**Цель Ф4 по плану:** ядро **находит и выделяет** различие
«соседи остаются соседями / разбегаются» как закон без имени.

**Ожидаемый результат по этой спецификации — провал цели.** Машина
находит закон `U N T ⊆ N` среди 113 разбиений, но не выделяет его (Д2,
«Главное нерешённое»). Ф4 не может быть принята, пока автор не решит
вопрос 1 §16 и спецификация не получит механизм выделения; тогда критерий
цели запишется заново: «отчёт выделяет разбиение п. 3 без называния его
вопросом».

Пункты ниже проверяют механику, а не цель; их выполнение Ф4 не
принимает.

Вход — мир §13.1 (порождён загрузчиком, с MANIFEST хешей) и вопросы
§13.4–13.6.

1. Выведена ось `~axis.value(step, map)`; осей сдвига нет; для каждого
   кандидата в каждой плоскости — опровергатель.
2. Поиск законов: 85 слов; пар, выполненных везде — 375; нигде — 1140;
   разбивающих — 5625; различных множеств плоскостей — 113.
3. Есть разбиение с законом `U N T ⊆ N`: ровно 32 отображения, у которых
   `T(cᵢ₊₁)` — сосед `T(cᵢ)` для всех `i`; законов с этим множеством — 264.
4. Разбиения `U N T ⊆ N N` (32 плоскости, 74 закона) и `U N T ⊆ ~id`
   (4 плоскости, 70 законов); первое не пересекается с разбиением п. 3,
   второе вложено в первое.
5. Для каждого из 224 отображений вне п. 3 — свидетель закона
   `U N T ⊆ N`: наименьший кортеж `ext(U N T) \ ext(N)`.
6. `consequence(L1, U·T)`: `U U N T T ⊆ N` с основанием `~derived` в 32
   плоскостях.
7. `anchor` оси закона: 32 `~holds`, 224 `~fails`; ключи `Map` не
   изменились.
8. В отчёте нет имени закона, кроме записи пары слов.
9. Детерминизм: перестановка 1032 вхождений и seed — отчёт побайтно один.

**Провал механики Ф4:** закон или разбиение, заданные во входе; отбор
отображений во входе; отличие от п. 1–9; вывод, опирающийся на
«расстояние» или «время» как понятие ядра.

## 16. Вопросы автору

**Главный вопрос.**

1. **Механизм, которым ядро само находит и выделяет законы и оси**
   («Главное нерешённое»; Д2, Д8, Д9 — одна дыра). Сейчас: оси — из
   встроенных образцов; законы — перебор слов до предела; выделения нет.
   Варианты, которые видит помощник: (а) мерило по уже сложившейся
   структуре — размер записи, число совпадающих законов, вложенность
   разбиений (H78); (б) сжатие: закон выделен, если через него короче
   записываются другие найденные законы; (в) оставить выделение
   спрашивающему (тогда цель Ф4 из плана переписать). *Позиция
   [помощник]:* (б) ближе всего к закреплению как «точке опоры», но не
   проработан; до решения автора Ф4 по цели не принимается, а Ф2–Ф3 можно
   строить на образцах как на временных.

**Представление.**

2. **Целый сдвиг и длина слова.** Ось сдвига ставит «+1 за вхождение», а
   `realize(k)` строит слово из `k` букв — это счёт длины композиции
   целыми. Допустимо ли это как представление машины (решение 26:
   «координаты — представление машины») или это число мира (решение 28)?
   *Позиция:* допустимо как представление — целое не становится
   вхождением, а `realize` выдаёт слово, не число; но граница тонкая:
   если отчёт начнёт сравнивать «на сколько дальше», это уже счёт.
3. **Запись положения** (§3.1–3.2): двоичная дробь с 64-битными знаками.
   *Позиция:* так; точна, допускает колонки и вставку между соседями.
4. **Перестройка и разбиение на пакеты** (§3.5, §4.4, §10.4 Д-3): запись
   положений зависит от истории; побайтной одинаковости при разном
   разбиении на пакеты нет. *Позиция:* так; перестройка — только явной
   операцией вне Ф2–Ф4.
5. **Плоскость** (§6.1, §6.3–6.5): эллипсоид с двумя допусками; ключа
   нет — «охватывает»; служебные вхождения лежат по опоре на данные;
   вложение — по объёму. *Позиция:* так; миры Ф2–Ф4 от свёртки ключей не
   зависят.

**Устройство машины.**

6. **Закрепление** (§8.5): только по вопросу `anchor`; закон оси сдвига
   после закрепления проверяется по записанным положениям, доступным в
   плоскости, иначе — по положениям плоскости. *Позиция:* так.
7. **Операции построения** (§2, §11.1): одна склейка. Содержание прежних
   `Primitive / … / Metaedge` не читалось; нужен ли их смысл сверх §2 —
   решить автору.
8. **Одно пространство** для осей понятий и контекстов (§11.2). *Позиция:*
   одно.
9. **Словарь машины и записи служебных структур** (§0.3, §1.6, §2.1, §6.1,
   §9.1): атомы `~…`, списки `~cons`, ограничения `~bound`, тождественное
   отношение `~id` отдельно от отождествления `~same`. *Позиция:* так.
10. **Тождество вхождения по записи** (§1.3) и утверждение из нескольких
    источников (Д4). *Позиция:* одна запись — одно вхождение; правило
    плоскостей источников для Д4 дописать до Ф3.
11. **Точка склейки по правилу и слабейшая посылка** (§4.7, §7.1),
    разность и реализация (§5.3, §5.8), закон как включение и правила
    следствия (§8.1, §8.4). *Позиция:* так.

**Миры и приёмка.**

12. **Вставка вглубь не проверяется мирами** (Д1). Добавить третий мир
    (H77)? *Позиция:* добавить.
13. **Отбор в мире устойчивости.** Соседство — цикл из четырёх — отобрано
    руками; предел длины слова `n = 3` выбран под известный ответ (§13.4).
    Переходы — все 256, без отбора. *Позиция:* соседство оставить как
    заданный мир, но проверить на нескольких циклах и на неотобранном
    соседстве; предел обосновывать изнутри машины, когда будет механизм
    вопроса 1.

## 17. Звёзды: с чем сверено и чем машина отличается

Звёзды — только сверка [принцип 4, принцип 5]. Для каждой — чем машина
отличается или что пока не отличается.

| Звезда | Где похоже | Чем отличается / что пока не отличается |
| --- | --- | --- |
| Конъюнктивный запрос | `~glue`: отождествление портов, привязка к константам, скрытые переменные (§2) | Склейка — вхождение, у неё есть точка и законы о ней; объём зависит от плоскости. По вычислению объёма **пока не отличается**. |
| Исчисление отношений Тарского | композиция, обращение, конъюнкция, законы как включения слов (§2.4, §8) | Нет дополнения и объединения, законы — по плоскостям, а не тождества алгебры. Поиск законов перебором слов — **не отличается** от перебора тождеств исчисления (Д9). |
| Функциональная зависимость | ось значения: «`p → q` однозначно» (§4.2) | Зависимость даёт ось и положения, отменяема, локализуется в плоскости. Сам критерий — **встроенный образец** (Д8). |
| Потенциал на графе | ось сдвига (§4.3) | Положения записываются без перенумерации, с путями-основаниями; опровержение локально. Сам образец — **заложен**, не выведен (Д8). |
| Таблицы | объём — множество кортежей (§2.2) | Таблица — только способ перечислить объём для отчёта; язык ядра — склейки, а не операции над таблицами. По перечислению **не отличается**. |
| Дробная индексация | вставка между соседями (§3.3) | Положение складывается и вычитается точно, а не только сравнивается. |
| Эллипсоид | проверка плоскости (§6.3) | Нестрогая граница, «охватывает», служебные вхождения по опоре. Форма свёртки — вопрос 5. |
| λ-исчисление | — | Не используется: нет термов, подстановки в тело, редукции [решение 10]. |
