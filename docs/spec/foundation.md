# Спецификация фундамента ядра-машины

Фаза Ф1 [плана](../plan.md). Документ описывает машину до кода: объекты,
операции, инварианты, два прогона на бумаге и приёмку фаз Ф2–Ф4. По нему
пишется ядро; всё, чего здесь нет, ядро не делает. Код Ф2 пишется только
после слова автора об этой спецификации [план, «Фазы»].

Метки у утверждений: [решение N] — [решения](../decisions.md);
[принцип N] — [принципы](../principles.md); [origin §N] —
[исходные заметки](../origin/relation-first-system.md); [помощник] —
предложение помощника, не принятое автором. Все места с меткой [помощник]
собраны в §16 «Вопросы автору».

Источники спецификации — только план, принципы, решения 1–31, исходные
заметки и `now.md`. Архив и код прошлого не открывались [принцип 11].
Операции `Primitive / Glue / Hide / Reify / Restrict` и `Derive / Metaedge`
известны только по именам из плана; их прежнее содержание не читалось, и
разбор в §11.1 опирается на нужды прогонов, а не на прежний текст.

## Что решено решением 31 и что осталось

Решение 31 задаёт, как ядро само находит и выделяет законы и оси: поиск
идёт от сгущений уже сложившегося; закон заметен, если сшивает сложившиеся
структуры и выдерживает притирку независимых кусков мира; порог
«закреплено» вычисляется из правил мира. В этой спецификации это механизм
заметности (§8.2). Он один для всех осей-законов и для законов мира.

Что механизм даёт на бумаге (числа сверены вычислением вне ядра):

- в мире родства «поколение» выходит как ось-цепь самоприложения
  `parent`, без встроенного образца (§12.4);
- в мире устойчивости из 64 кандидатов, порождённых от единственного
  сгущения, закрепляются 35 законов на шести множествах отображений; среди
  них — «соседи остаются соседями» (§13.4). Прежний перебор давал 113
  равноправных разбиений;
- в мирах той же формы без структуры (контроль) не закрепляется ничего,
  кроме двух объяснимых случаев, где перемешивание случайно восстановило
  структуру (§13.6).

Что осталось открытым (§14, §16):

- машина выделяет **шесть** вложенных законов, а не один; «соседи
  остаются соседями» — один из шести. Выделить ровно его можно только целью
  извне (Д2 сужена, вопрос 1);
- набор форм сшивки (одно приложение с каждой стороны сгущения) и три
  исхода самоприложения (цепь, возврат, классы) — выбор помощника; они
  читаются как исходы одной операции, но остаётся риск, что это
  замаскированный перечень (Д8 сужена, вопросы 4–6);
- механизм составлен, когда ответ мира устойчивости был уже известен; от
  подгонки защищают только контрольные миры (Д11) [принцип 4].

## 0. Границы и словарь машины

**0.1. Что такое машина.** Процесс с состоянием и набором операций, который
отвечает на запросы и не ставит своих целей [решение 29, решение 16]. Вход —
поток записей двух видов: пакет данных и вопрос. На каждую запись машина
выдаёт отчёт. Состояние — свёртка всех принятых записей (§10).

**0.2. Чего в ядре нет.**

- Чисел мира: количеств, мер, единиц, арифметики как понятий
  [решение 28]. Целые числа есть только внутри представления положений
  (§3) и не образуют ни одного вхождения (вопрос 7).
- Пространственности: высоты, ширины, времени [решение 23]. «Переход» в
  мире устойчивости — обычное отношение, повтор перехода — склейка.
- Выбора геометрии: ни одна операция не берёт «вид представления» как
  параметр [принцип 2].
- Каталога свойств: свойства не задаются данными и не проверяются
  отдельными образцами; оси и законы получаются одним механизмом (§8.2)
  [принцип 3, решение 31].
- Перебора всех выражений до заданной длины [решение 31, принцип 8].
- λ-термов и таблиц как языка ядра [принцип 5, решение 10]. Сверка со
  звёздами — §17.

**0.3. Словарь машины** [помощник]. Короткий явный список
зарезервированных атомов — инструменты машины, а не данные мира. Все
начинаются с `~`; имя данных не может начинаться с `~`.

| Атом | Где используется |
| --- | --- |
| `~glue`, `~part1`, `~part2`, `~port`, `~pair`, `~ident`, `~bind`, `~face`, `~id` | склейка (§2) |
| `~cons`, `~nil` | списки внутри служебных вхождений (§1.6) |
| `~axis.port`, `~axis.class`, `~axis.chain`, `~axis.law`, `~key`, `~gauge` | оси и ключи (§4) |
| `~plane`, `~bound` | плоскость (§6) |
| `~batch`, `~ground`, `~given`, `~checked`, `~derived`, `~defeasible`, `~defeats` | основания (§7) |
| `~same`, `~not`, `~gap` | отождествление, отрицание, пробел (§7) |
| `~law`, `~sub`, `~holds`, `~fails` | закон (§8) |
| `~question`, `~given-part`, `~find`, `~condition`, `~goal`, `~keep`, `~ready`, `~answer`, `~branch` | вопрос и ответ (§9) |

## 1. Вхождение

**1.1. Что это.** Вхождение — единственная форма факта [решение 10,
решение 17.1; origin §4, §5.1]. Всё, к чему машина может обратиться, —
вхождение: сущность мира, отношение, конструкция, ось, плоскость, основание,
закон, вопрос, ответ.

**1.2. Из чего состоит.** Два вида:

- **атом** — вхождение без портов; задаётся именем (последовательность
  байтов из входа или из словаря машины). Сущности мира (`ann`, `c0`),
  имена отношений (`parent`), имена ролей (`ego`) — атомы;
- **связь** — `kind(role₁: t₁, …, roleₙ: tₙ)`: вид `kind` (вхождение),
  набор портов «роль → цель». Роль — вхождение (обычно атом); цель —
  вхождение или литерал положения (§3). В одной связи роль встречается не
  более одного раза. Порядок портов не значим.

Отношение об отношении — то же вхождение: цель порта может быть связью
[решение 10; origin §4, §5.1 «метарёбра»]. Отдельного объекта «метаребро»
нет.

**1.3. Тождество** [помощник]. Вхождение тождественно своей канонической
записи: атом — именем; связь — `kind(role: target, …)` с портами,
упорядоченными по байтам канонической записи роли; цели — рекурсивно;
литерал положения — в форме §3.2. Две одинаковые записи — одно вхождение.
Одно и то же утверждение из двух источников — одно вхождение с двумя
основаниями (§7.1). Два одинаковых события из одного источника — тоже одно
вхождение; если мир различает два события, он даёт им различающий порт
(например, атом события) [решение 17.1; вопрос 15]. Порядок вхождений
везде — байтовый порядок записей. Внутренние номера (плотные индексы для
колонок) в отчёт не попадают.

**1.4. Вхождения данных и служебные.** Вхождение данных — связь с
основанием `~given` (пришла в пакете). Служебное вхождение — всё, что
построила машина: склейки, оси, ключи, плоскости, основания, законы,
опровергатели, вопросы, ответы, пробелы. Механизм заметности (§8.2) смотрит
только на отношения данных; единственное исключение — пара портов
`~ground: claim → source` (§7.1).

**1.5. Инварианты.**

- И1. Запись вхождения не зависит от порядка, в котором его порты пришли во
  входе.
- И2. Вхождение не меняется после принятия. Новое знание — новые
  вхождения, а не правка старых.
- И3. Совпадение проекций (точек §4, объёмов §2.2) не делает два
  вхождения одним [решение 17]. Отождествление — только `~same` с
  основанием (§7.2).

**1.6. Множества и последовательности внутри служебных вхождений**
[помощник]. Роль в связи встречается один раз, поэтому набор записывается
списком `~cons(head: x₁, tail: ~cons(head: x₂, tail: … ~nil))`: множество
— элементы по канонической записи; последовательность — в своём порядке.
У пути — от начала к концу; у пары путей (опровергатель, §8.5) — сначала
более короткий, при равной длине — меньший по записи.

**1.7. Почему этот объект.** Без него нет ничего; он и есть relation-first.

## 2. Склейка — единственная операция построения

**2.1. Что это** [помощник; §11.1]. Склейка строит новое отношение из
одного или двух имеющихся: отождествляет порты, привязывает порты к атомам,
решает, какие порты открыты и под какими ролями. Склейка — вхождение:

```
~glue(~part1: X, ~part2: Y, ~ident: I, ~bind: B, ~face: F)
```

- `X`, `Y` — отношения (имя отношения данных, `~id`, другая склейка);
  `~part2` может отсутствовать;
- порт части — `~port(part: ~part1|~part2, role: r)`, ниже `i.r`;
- `I` — множество `~pair(left: i.r, right: j.s)`: порты отождествлены;
- `B` — множество `~pair(left: i.r, right: a)`: порт привязан к атому `a`;
- `F` — множество `~pair(left: ρ, right: i.r)`, инъективное по `ρ`: открытая
  роль `ρ` — порт `i.r`. Ниже пишется `ρ ← i.r`.

Множества — списки §1.6. Порты частей, не достижимые из `F` через `I`,
скрыты.

**2.2. Объём.** Объём отношения в плоскости `P` (§6) — множество кортежей
«роль → цель»:

- для имени отношения данных `K`: кортежи портов вхождений вида `K`,
  которые лежат в `P` (статус «внутри» или «охватывает», §6.4);
- для `~id(over: C)` — §2.3;
- для склейки: кортежи `t` над открытыми ролями, для которых найдутся
  кортежи частей `τ₁ ∈ ext_P(X)`, `τ₂ ∈ ext_P(Y)` с равными портами из `I`,
  портами из `B`, равными своим атомам, и `t(ρ) = τᵢ(r)` для `ρ ← i.r`.

Объём конечен, перечисляется в байтовом порядке кортежей.

**2.3. Тождественное отношение `~id`** [решение 17.3; помощник].
`~id(over: C)` с ролями `from`, `to`; `C` — отношение, на целях портов
которого берётся тождество (носитель). `ext_P(~id(over: C)) = {(x, x)}` для
всех целей портов `C`, лежащих в `P`. Не путать с `~same` (§7.2) —
отождествлением двух сущностей.

**2.4. Производные формы.** Записываются через `~glue`; отдельных операций
не вводят.

| Форма | Склейка |
| --- | --- |
| ориентация `K[p→q]` (прочие порты скрыты) | `~glue(K; F: from ← 1.p, to ← 1.q)` |
| обращение `X⁻` | `~glue(X; F: from ← 1.to, to ← 1.from)` |
| приложение (композиция) `X ; Y` | `~glue(X, Y; I: (1.to, 2.from); F: from ← 1.from, to ← 2.to)` |
| конъюнкция `X ∧ Y` | `~glue(X, Y; I: (1.from, 2.from), (1.to, 2.to); F: from ← 1.from, to ← 1.to)` |
| признак на порту | `~glue(X, R; I: (1.ρ, 2.s); B: (2.q, a); F: роли X ← 1.·)` |

Приложение и конъюнкция — разные склейки и разные действия на точках
(§5.2) [план Ф1 п. 2]. Запись `X₁ X₂ … Xₖ` — левоассоциативное приложение
`((X₁ ; X₂) ; …) ; Xₖ`; `Xᵏ` — `X` приложенное к себе `k` раз.

**2.5. Инварианты.**

- И4. Склейка не содержит отрицания: объём монотонен.
- И5. Склейки с разной записью — разные вхождения, даже при равном объёме
  и равной точке. Одночленная склейка `~glue(parent; F: …)` — не то же
  вхождение, что атом `parent`.

**2.6. Почему этот объект.** Конструкции нельзя выразить данными. Одна
склейка покрывает скрытие портов, ориентацию, приложение, конъюнкцию и
привязку к атому (§11.1). Склейка — вхождение, поэтому «овеществление»
отдельной операцией не нужно.

## 3. Положение — точное значение с динамической глубиной

**3.1. Что это** [помощник]. Положение — значение машины, в котором
записано место сущности на оси [решение 26]. Положение — не вхождение и не
число мира: это литерал машины, единственный не-атомный лист, который может
стоять в порту. Над ним нужны точные сумма, разность, сравнение и вставка
между соседями (§3.3), которых у атомов нет.

**3.2. Запись** [помощник]. Положение `π = (z; f₁, …, fₖ)`: `z` —
знаковое 64-битное целое; `f₁ … fₖ` — беззнаковые 64-битные «знаки»
дробной части, `k ≥ 0` — глубина; значение `z + f₁·2⁻⁶⁴ + … + fₖ·2⁻⁶⁴ᵏ`;
каноническая форма — `fₖ ≠ 0`. Точная двоичная дробь; глубина растёт,
когда нужна [решение 26; принцип 1].

**3.3. Операции над положениями.** Все точные.

| Операция | Определение |
| --- | --- |
| сравнение `π < π′` | лексикографически по `(z, f₁, f₂, …)`, недостающие знаки — нули |
| сумма, разность, обратное | поразрядно с переносом |
| середина `mid(π, π′)` | `(π + π′)/2`; глубина растёт не больше чем на один знак |
| вставка между соседями `π < π′` | `mid(π, π′)`; существующие положения не трогаются |
| вставка после последнего `π` | `π + 1` |
| вставка перед первым `π` | `π − 1` |

Умножение — только внутри проверки плоскости (§6.3), как промежуточное
значение; не сохраняется и не выходит наружу.

**3.4. Колоночная раскладка.** Требование формы данных, а не оптимизация
[план Ф1 п. 2]. Положения одной оси — колонки целых: носитель (внутренний
индекс), опора (§4.4), `z` (i64), `f₁ … f_K` (u64). Положение глубины
`k < K` имеет нули в колонках `f_{k+1} … f_K` — то же значение.

**3.5. Когда «место кончается»** [помощник].

1. **Глубже раскладки.** Нужен знак `f_{K+1}` — «правка в запасе»:
   колонка добавляется, у прежних строк в ней ноль, значения не меняются.
2. **Переполнение целой части** — пробел `~gap(kind: axis-overflow)`;
   операция не выполняется. В мирах Ф2–Ф4 не встречается.
3. **Смысловое**: новое значение нельзя поставить, не нарушив закон оси
   (§12.8). Это опровержение закона — аномалия в плоскости (§7.4);
   положения не меняются.

**Перестройка** (сжатие глубины, смена опоры) меняет принятые положения;
в Ф2–Ф4 её нет. Если понадобится — только явной операцией, которая создаёт
новую ось и вхождение-соответствие «старое → новое» (вопрос 9).

**3.6. Инварианты.**

- И6. Записанное положение носителя на оси не меняется никогда (нет
  перенумерации).
- И7. Ни одна операция не порождает вхождение, которое означает число,
  количество или меру [решение 28].

## 4. Ось, ключ, точка

**4.1. Ось.** Ось — вхождение, которое называет закон, по которому
носителям даются положения [решение 26]. Данные осей не объявляют.

| Вид | Вхождение | Откуда | Порядок |
| --- | --- | --- | --- |
| порта | `~axis.port(rel: R, port: q)` | представление: цели порта `q` отношения данных (§4.2) | нет |
| классов | `~axis.class(rel: R, from: p, to: q)` | механизм: самоприложение `X ; X⁻` возвращается сразу (§8.2, исход «классы») | нет |
| цепи | `~axis.chain(rel: R, from: p, to: q)` | механизм: самоприложение `X, X², …` идёт без возврата (§8.2, исход «цепь») | выведен: направление `X` |
| закона | `~axis.law(law: L, over: q)` | механизм: заметный закон над семейством кусков (§8.2) | нет |

Ось порта — представление машины, а не закон: она лишь даёт целям порта
положения. Все остальные оси выводит один механизм §8.2 [решение 26,
решение 31]. Неупорядоченное значение — тоже положение на оси; порядок —
свойство оси (у цепи — направление приложения). На оси без порядка
используется только равенство положений (И8).

**4.2. Ось порта** [помощник]. Для каждого порта `q` каждого отношения
данных `R` и для порта `~ground.source` — ось `~axis.port(R, q)`. Цели
порта получают положения в пакете, где появились впервые: по байтовому
порядку имён, после последнего занятого. Вхождение данных `o` вида `R`
получает собственный ключ `(~axis.port(R, q), ∅) = pos(o.q)`.

**4.3. Метки классов на носителях.** Если механизм нашёл у ориентации
`X = R[p→q]` исход «классы» и вдобавок `X⁻ ; X ⊆ ~id` (значение в `q`
через носителя возвращается к себе), каждый класс помечен одним значением
`q`: носитель `e` в порту `p` получает ключ
`(~axis.port(R, q), ∅) = pos(значение)`. Основание — `~defeasible`
(закон механизма). Без метки классы дают отдельную ось
`~axis.class(R, p, q)`; положение класса — по наименьшему по записи члену,
в порядке первого появления.

**4.4. Проекция оси цепи на носителей** [помощник]. Ось цепи
`A = ~axis.chain(R, p, q)` ставит понятиям положения по числу шагов
приложения (`X` — `+1`, `X²` — `+2`, `X⁻` — `−1`; вопрос 7). Носители
получают положения так, чтобы каждое вхождение `R` сдвигало от `p` к `q`
на `+1`:

1. Связные части носителей по вхождениям `R`.
2. Опора части — носитель с наименьшей записью, положение `0`.
3. Обход в ширину от опоры; у носителя вхождения `R` — в байтовом
   порядке; по `p → q` — `+1`, по `q → p` — `−1`. **Путь-основание**
   положения — последовательность вхождений от опоры по дереву обхода.
4. Если вхождение соединяет двух поставленных носителей несовместимо,
   проекция в этой части не проходит; это то же нарушение, что ловит
   закон цепи (§8.5), и записывается его опровергателем.

Строка колонки — (носитель, опора, положение, путь-основание). Связь двух
частей новыми данными записывается вхождением
`~gauge(axis: A, from: o₁, to: o₂, by: δ)` без пересчёта — «правка в
запасе». Знак «плюс» — артефакт канонической ориентации (Д7).

**4.5. Ключ.** `~key(axis: α, at: ρ)`, где `ρ` — `~nil` (собственная
координата, ниже `∅`), роль `r` (координата участника в порту `r`) или
`~pair(left: r, right: s)` (сдвиг между участниками на оси цепи, ниже
`Δ(r→s)`, только для `r < s` по записи ролей).

**4.6. Точка.** Частичное отображение «ключ → положение»; отсутствие
ключа — «ничего не говорит об этой оси» (§6.4). Точка считается в
плоскости: `point_P(o)`.

| Вхождение | Точка |
| --- | --- |
| атом-носитель | ключи `(α, ∅)` по осям портов (метки классов, §4.3), классов, закона; `(A, ∅)` по осям цепи — положение, доступное в `P` |
| вхождение данных `R(r₁: e₁, …)` | собственные ключи осей портов (§4.2) и метка источника (§7.1); для участника `eᵢ` и его ключа `(α, ∅)` — ключ `(α, rᵢ)`; для пары участников с положениями на одной оси цепи — `(A, Δ(rᵢ→rⱼ)) = pos(eⱼ) − pos(eᵢ)` |
| имя отношения данных `K` | **по объёму**: ключи, постоянные во всех кортежах `ext_P(K)` (кортежи без собственных ключей); пустой объём — пробел `empty-extension` |
| склейка | **по правилу** §4.7 |

Для статуса в плоскости (§6.4) берётся та же точка: у имени — по объёму, у
склейки — по правилу, у атома и вхождения данных — своя.

**Порядок вычисления в плоскости `P`** [помощник]. (1) Вхождения данных,
лежащие в `P`. (2) Законы механизма в `P` и их опровергатели по этим
вхождениям (§8.5) — без использования положений. (3) Для частей, где закон
цепи опровергнут в `P`, положения — пробел `defeated`. (4) В остальных
частях записанное положение доступно, если весь его путь-основание лежит в
`P`. (5) Недоступные ставятся обходом §4.4 по вхождениям из `P` — это
**положения плоскости**, они выдаются, но не записываются. Шаг 5 не может
встретить нарушение, которое пропустил шаг 2: он работает на тех же
вхождениях. Круга между доступностью и опровержением нет: опровержение
считается раньше и без положений.

**4.7. Точка склейки** [помощник]. Из точек частей, без перебора объёма:

1. Порты частей делятся на классы по `I`.
2. Признаки `(α, r)` части — на класс порта `r`; в классе — конъюнкция
   (§5.1); несовместимые — точка `⊥`.
3. Привязка `(i.q, a)`: если у части `i` ось порта `q` помечает классы
   (§4.3), классу каждого другого порта `s` части — признак
   `(~axis.port(Rᵢ, q), ∅) = pos(a)`.
4. Сдвиги `(A, Δ(r→s))` частей — рёбра между классами.
5. Для открытых ролей `ρ ← i.r`: признаки класса `r` — ключи `(α, ρ)`;
   для `ρ₁ < ρ₂` — `(A, Δ(ρ₁→ρ₂))` = сумма вдоль пути между классами; два
   пути с разной суммой — `⊥`.
6. Признаки скрытых классов в точку не входят.

Основание — по слабейшей посылке (§7.1). Для склейки с непустым объёмом
каждый ключ по правилу есть в точке по объёму с тем же значением;
нарушение — ошибка машины, кроме случая, когда закон, на котором стоит
шаг, опровергнут в `P` (тогда ключ — пробел). `⊥` предсказывает пустой
объём; объём проверяется.

**4.8. Инварианты.**

- И8. На оси без порядка — только равенство и подстановка (§5.3).
- И9. Новая ось добавляет ключи; существующие ключи и значения не
  меняются (рост вширь без перенумерации) [решение 26].

## 5. Операции над точками

Все точные [решение 26; принцип 1].

**5.1. Конъюнкция признаков `a ⊓ b`.** Объединение ключей; на общем ключе
значения равны, иначе `⊥`.

**5.2. Образ приложения.** Для `X ; Y`: признаки на `from` — от `X`, на
`to` — от `Y`, средний порт скрыт; `Δ(from→to)` = сдвиг `X` + сдвиг `Y`.
`parent ∧ parent` даёт точку `parent`, `parent ; parent` — сдвиг вдвое
(§12.5).

**5.3. Разность `a − b`** [помощник].

| `a` | `b` | `d` |
| --- | --- | --- |
| `x` | `x` | «без изменения» |
| `x` | `y ≠ x`, ось с порядком | `x − y` |
| `x` | `y ≠ x`, ось без порядка | подстановка `y ↦ x` |
| `x` | нет | добавление `∅ ↦ x` |
| нет | `y` | снятие `y ↦ ∅` |

**5.4. Сумма `a + d`.** «Без изменения» — ключ переносится; положение —
сложить (у `a` ключа нет — пробел `shift-undefined`); подстановка `y ↦ x` —
у `a` должно быть `y`; добавление `∅ ↦ x` — у `a` ключа нет или уже `x`;
снятие — у `a` должно быть `y`; иначе пробел. Ключи `a` вне `d`
переносятся. Признак `w` с ключом `(α, ∅)`, перенесённый на порт `ρ`, —
`w@ρ` (ключ `(α, ρ)`). Так «родитель + женщина@alter = мать» — точная
сумма (§12.5).

**5.5. Сдвиг-аналогия** `a : b :: c : ?` — `c + (b − a)`.

**5.6. Расстояние** — точка: по общему ключу оси с порядком `|x − y|`; без
порядка — «равны» / «различны»; ключ у одной точки — «несравнимо».

**5.7. Вложение `a ⊑ b`** — каждый ключ `b` есть в `a` с тем же значением.
Вложение точек — проекция; вложение объёмов — проверка; машина сообщает
оба.

**5.8. Реализация `realize(d)`** [помощник]. Смещение приводится к
**цели**: «без изменения» и нулевые сдвиги отбрасываются; добавления и
подстановки дают ключ со значением `x`; снятие — пробел
`realize-ambiguous`. Роли цели — роли её ключей. Машина выдаёт:

- (а) вхождения состояния с точкой, равной цели, **и** с открытыми
  ролями, равными ролям цели;
- (б1) только признаки: для каждого признака `(~axis.port(R, q), r) = v` —
  часть `R` с привязкой `q = v` и ролью `r ← ` носитель (порт, классы
  которого помечены `q`, §4.3); несколько признаков — части, соединённые по
  `I` в порядке ролей;
- (б2) один сдвиг `Δ(r→s) = k` по оси цепи `~axis.chain(R, p, q)` (`k` —
  ненулевое целое) и признаки на `r`, `s`: слово из `k` ориентаций `R[p→q]`
  (при `k < 0` — `|k|` обращений), начало — роль `r`, конец — роль `s`,
  признаки — на соответствующий конец, как в (б1).

Иное — пробел `realize-ambiguous` с перечислением (а). Каноническая
склейка — отдельное вхождение (И5).

## 6. Плоскость

**6.1. Что это.** Плоскость — окрестность в том же пространстве точек, в
котором лежат понятия, сущности и утверждения [решение 27, решение 15].
Плоскости перекрываются и вкладываются. Плоскость — атом-имя `p` и
ограничения `~bound(plane: p, key: K, center: π, inner: π_in, outer: π_out)`,
по одному на ключ [помощник]. Для ключа оси без порядка допуски пишутся
нулём, условие — равенство центру. `W` — плоскость без ограничений. Разные
имена при одинаковых ограничениях — разные плоскости (И3).

**6.2. Нестрогая граница.** Внутри, на границе, снаружи [решение 27];
граница — отдельная ветвь ответа (§9.3).

**6.3. Проверка точки `x`** [помощник; вопрос 10].

1. Ключи оси без порядка: ключ есть и значение ≠ центру — снаружи.
2. Ключи оси с порядком: `S_in = Σ (dₖ/ρ_in,ₖ)²`, `S_out = Σ (dₖ/ρ_out,ₖ)²`,
   `dₖ = |xₖ − centerₖ|`; при допуске `0` слагаемое — `0` при `dₖ = 0`, иначе
   «больше 1». `S_out > 1` — снаружи; `S_in < 1` — внутри; иначе — на
   границе. Сравнение — умножением на общий знаменатель.
3. Ключа плоскости у `x` нет — «охватывает» (§6.4).

Миры Ф2–Ф4 используют плоскости не больше чем с одним ключом оси с
порядком и от правила свёртки не зависят.

**6.4. Статусы и что где лежит** [помощник; вопрос 10].

- Вхождения данных, атомы, имена отношений, склейки: «внутри», «на
  границе», «охватывает» (ключа плоскости у точки нет), «снаружи».
- **Служебные вхождения** собственных точек не имеют и «охватывать» не
  могут. Служебное вхождение лежит в `P`, если в `P` лежат все вхождения
  данных, на которые оно указывает — прямо или через другие служебные
  вхождения и списки. Не указывающее ни на одно вхождение данных (ось,
  закон о склейках) в плоскостях не лежит; его действие в плоскости
  определяется проверкой в ней (§8.5).

Объём в плоскости берёт «внутри» и «охватывает»; «на границе» — отдельная
ветвь.

**6.5. Пересечение и вложение.** Пересечение — точка проходит обе
проверки. Вложение `P ⊆ Q` — **по объёму**: всё, что «внутри» `P`, «внутри»
`Q` [помощник]; геометрическое вложение не вычисляется (Д5).

**6.6. Где ищется противоречие.** Только внутри плоскости, среди
вхождений, которые в ней лежат (§7.4). Набор участников виден в плоскости,
только если в ней лежат все участники, — в пересечении плоскостей,
содержащих каждого [решение 15]. Опровергатель указывает на участников и по
§6.4 лежит ровно там же.

**6.7.** Источник, отображение и т. п. — оси портов (§4.2); отдельного
«контекста» нет (§11.2).

## 7. Основание, тождество, отрицание, пробел; противоречие и аномалия

**7.1. Основание** [решение 17.6]. `~ground(claim: o, kind: k, by: b,
source: s)`:

- `kind` — `~given` (дано во входе), `~checked` (проверено перебором
  объёма в конечной плоскости — строго для её содержимого), `~derived`
  (по правилу машины из строгих посылок), `~defeasible` (опирается хотя бы
  на один закон механизма: выполнено на всём, что есть, может быть
  опровергнуто новыми данными);
- `by` — путь построения: вхождение правила, вопроса или пакета
  `~batch(source: s, at: π)` (`π` — положение записи в журнале, §10.1);
- `source` — только у `~given`.

**Правило слабейшей посылки** [помощник]: основание вывода —
`~defeasible`, если хотя бы одна посылка отменяемая; иначе `~derived`.

**Метка источника.** Пара портов `~ground[claim → source]` — единственная
служебная, к которой применяется механизм (§1.4). Если исход «классы» с
`X⁻ ; X ⊆ ~id` (каждое утверждение — из одного источника), вхождения
данных получают ключ `(~axis.port(~ground, source), ∅)` — отменяемо
[помощник; вопрос 14]. Другие порты `~ground` (`kind`, `by`) механизм не
рассматривает, поэтому «вид основания → источник» законом не становится.

Опровергатель — `~defeats(claim: o, by: w)`, `w` — контрпример или список
§1.6. Отменяемое основание с опровергателем, лежащим в `P` (§6.4), в `P` не
действует.

**7.2. Отождествление.** `~same(a: x, b: y, plane: P)` с основанием — в `P`
объём считается с `x` и `y` как одной целью [решение 17.3]. Совпадение
точек или объёмов его не создаёт (И3). В мирах Ф2–Ф4 не возникает.

**7.3. Типизированный пробел** `~gap(kind: …, at: …)` [решение 17.7]:
`empty-extension`, `shift-undefined`, `realize-ambiguous`, `axis-overflow`,
`incompatible` (точка `⊥`), `defeated`, `not-functional`,
`pieces-do-not-fit` (§8.2 шаг 5). Пробел — вхождение отчёта, а не ошибка.

**7.4. Противоречие и аномалия.** В `P`: противоречие — лежат `o` и
`~not(o)` [решение 17.2]; аномалия — закон механизма имеет в `P`
опровергатель (§8.5). Отчёт: участники и плоскости вопроса, где лежат все
участники (§6.6). Противоречие не распространяется за их пределы
[origin §7].

**7.5. `holds(claim, plane, status)`** [решение 17.5] — вычисляемое
отношение: `~holds` со строгим или отменяемым основанием, `~defeated`,
`~contradicted`, «на границе», пробел.

## 8. Закон, заметность, закрепление

**8.1. Закон** [помощник] — вхождение `~law(left: X, right: Y, rel: ~sub)`:
«объём `X` содержится в объёме `Y`». Выполнение проверяется в каждом куске
отдельно, основание `~checked`. Исходы самоприложения (§8.2 шаг 2) — тоже
законы, записанные включениями: цепь — `Xᵃ ∧ Xᵇ ⊆ ∅` при `a ≠ b` и
`Xᵃ ∧ ~id ⊆ ∅`; классы — `E ; E ⊆ E`, `E⁻ ⊆ E`, `~id ⊆ E` для `E = X ; X⁻`;
возврат — `Xᵏ ⊆ X` и `X ⊆ Xᵏ`.

**8.2. Механизм заметности** [решение 31; конкретные шаги — помощник,
вопросы 2–6]. Вызывается вопросом `salient` (§9.2) над отношениями «дано»
и, если вопрос задаёт, над семейством кусков. Шаги:

1. **Структуры.** Ориентации `R[p→q]` отношений данных по парам различных
   портов, кроме порта, задающего семейство кусков (он постоянен внутри
   куска), и их обращения. Ориентации с равным объёмом во всех кусках
   записываются законом равенства и дальше идут одной структурой (по
   меньшей записи).

2. **Сгущения: самоприложение.** Для каждой структуры `X` машина
   прикладывает её к себе — `X, X², X³, …` — пока очередное приложение не
   даст пустой объём или уже бывший член; и считает `E = X ; X⁻`. Предел
   — сам мир: конечный мир всегда приходит к пустому или к повтору, длина
   семейства — **постоянная мира для `X`** (§8.4). Исходы — чтения одной
   операции, а не отдельные проверки:
   - **цепь**: семейство кончается пустым, в нём не меньше двух членов
     (структура встречает сама себя), члены попарно не пересекаются и не
     пересекаются с `~id` → ось цепи `~axis.chain(R, p, q)` (§4.4);
   - **возврат**: `Xᵏ = X` при некотором `k > 1` → `X` — **сгущение**:
     структура, которая воспроизводит себя; её семейство `F(X)` —
     сложившиеся структуры, от которых идёт поиск законов (шаг 3);
   - **классы**: `E ; E = E`, `E⁻ = E`, `~id ⊆ E` на носителях порта `p`, и
     классов не меньше двух → ось классов или метки (§4.3);
   - иначе — ничего.

   Если вопрос задаёт семейство кусков, самоприложение считается в каждом
   куске; сгущением считается только структура, семейство которой
   одинаково во всех кусках (она «сложилась» независимо от куска).

3. **Сшивка.** Для каждого сгущения `C` с семейством `F(C)` и каждой
   другой структуры `S` (из другого отношения данных) машина прикладывает
   `S` к портам членов семейства: формы `A C′ B`, где `C′ ∈ F(C)`,
   `A ∈ {S, S⁻, —}`, `B ∈ {S, S⁻, —}`, не оба `—`; и сравнивает результат с
   членами `F(C)`: законы `A C′ B ⊆ Y` и `Y ⊆ A C′ B`, `Y ∈ F(C)`. Закон
   сшивает две сложившиеся структуры: `S` и семейство сгущения. Других
   выражений машина не строит; предела длины нет — длина задана
   семейством `F(C)`, то есть миром.

4. **Притирка.** Для каждого закона — множество кусков `H`, где он
   выполнен. Кусок — плоскость семейства (если вопрос его задаёт). Закон
   притёрт, если:
   - **куски прикладываются друг к другу внутри мира**: для любых кусков
     `A`, `B` семейства приложение «сначала `A`, потом `B`» (склейка
     переходов двух кусков) по объёму равно переходу некоторого куска
     семейства — это правило самого мира, проверяется один раз для
     семейства;
   - **закон переживает приложение**: для `A, B ∈ H` кусок «`A`, потом `B`»
     тоже в `H` (в том числе `A`, потом `A` — повтор перехода);
   - **три независимые плиты**: в `H` есть три куска, попарно не лежащие в
     семействах самоприложения друг друга (ни один не получается из другого
     повтором);
   - `H` — не все куски и не пусто (иначе это закон всего мира, а не
     различие; такие законы сообщаются отдельно).

   Без семейства кусков притирка — исходы шага 2: члены семейства
   самоприложения — куски одного мира, приложенные друг к другу.

5. **Порог «закреплено» — постоянная мира** (§8.4). Закон закрепляется
   автоматически, если шаги 2–4 пройдены целиком — до конца семейства
   самоприложения и для всех пар кусков. Назначенного числа нет. Если
   куски семейства не прикладываются друг к другу внутри мира (первое
   условие шага 4), постоянная не определена: машина ничего не
   закрепляет и пишет пробел `pieces-do-not-fit`.

6. **Отчёт.** Закреплённые законы группируются по множеству `H`; между
   множествами — вложения по объёму. Имён нет; всё закреплённое
   показывается, похоже оно на известное понятие или нет [решение 31].
   Машина не сравнивает найденное с известными понятиями.

**8.3. Ось закона.** Закреплённый закон над семейством кусков по оси порта
`q` даёт ось `~axis.law(L, q)`: куски получают `~holds` / `~fails`; ось без
порядка. Вхождения данных получают ключ `(~axis.law(L, q), ρ)` через
участника в порту `ρ`.

**8.4. Постоянная мира** [помощник; вопрос 5]. Для структуры `X` — длина
её семейства самоприложения до пустого или повтора; для семейства кусков —
глубина, на которой приложение кусков друг к другу перестаёт давать новые
куски (в мире всех отображений — 1: любое приложение двух кусков — снова
кусок). Обе величины — свойства мира; машина их не назначает, а достигает.
Проверка до постоянной — полная: дальше мир повторяется.

**8.5. Проверка закреплённого при новых данных.** При каждом новом пакете
и в каждой плоскости вопроса машина заново считает исходы шага 2 по
вхождениям, лежащим в плоскости (§4.6, шаг 2). Для цепи нарушение —
пара носителей `(x, y)`, связанная приложением разной длины (`Xᵃ ∧ Xᵇ ≠ ∅`)
или с собой (`Xᵃ ∧ ~id ≠ ∅`); опровергатель — наименьшая по записи такая
пара и два её пути (по одному наименьшему пути каждой длины), записанные
по §1.6. Новые носители, связанные с поставленными без нарушения,
получают записанные положения (§4.4); новые члены семейства — положения
«после последнего». Существующие записи не меняются (И6, И9).

## 10. Машина

**10.1. Состояние.** Журнал записей (пакеты и вопросы; у записи —
положение в журнале «после последнего») и его свёртка: вхождения и колонки
положений. Состояние восстанавливается прогоном журнала с нуля.

**10.2. Записи входа.**

- **пакет**: имя источника и множество вхождений данных. Машина
  принимает вхождения, пишет основания `~given`, ставит положения новым
  целям осей портов, проверяет закреплённые законы (§8.5), пишет
  опровергатели и новые положения;
- **вопрос**: части §9.1; машина выполняет искомое и пишет ответ.

**10.3. Отчёт.** На каждую запись — канонический текст, строки в байтовом
порядке внутри разделов: принятое, оси, положения (записанные — от опоры
части; положения плоскостей — отдельно; на осях без порядка — имя значения
или класса, а не положение), ответ (ветви), основания, пробелы,
противоречия и аномалии. Положения — точная двоичная дробь (`+2`, `-1`,
`+3/2`). Внутренние индексы, адреса, время не печатаются. Точная грамматика
дописывается сюда до кода Ф2 (Д6).

**10.4. Детерминизм** [решение 18].

- Д-1. Один журнал и любой seed — побайтно один отчёт. Случайных выборов у
  машины нет; seed на результат не влияет. Контрольные миры (§13.6)
  порождает загрузчик в `tools/` со своими seed, не машина.
- Д-2. Перестановка вхождений внутри пакета и портов внутри вхождения не
  меняет отчёт побайтно.
- Д-3 [помощник; вопрос 9]. Разбиение данных на пакеты может менять
  историю (опоры, положения целей, пути-основания), но не ответы, не
  зависящие от калибровки: объёмы, сдвиги, законы, множества кусков,
  статусы.
- Без коллекций с недетерминированным порядком, часов, потоков
  [принцип 8].

**10.5. Операции машины** (полный список): принять пакет; ответить на
вопрос; внутри — склейка и объём (§2), оси портов (§4.2), проекция цепи
(§4.4), точка и операции над точками (§4.6–5.8), проверка плоскости (§6),
основания и опровержение (§7), механизм заметности, закрепление и проверка
закреплённого (§8).

## 11. Разбор открытых вопросов плана

### 11.1. Какие операции построения нужны машине

Варианты по именам из плана: (А) `Primitive / Glue / Hide / Reify /
Restrict`; (Б) `Derive / Metaedge`; (В) одна склейка, остальное — её
случаи или свойства формы вхождения.

| Имя | В этой спецификации |
| --- | --- |
| `Primitive` | приём пакета (§10.2) |
| `Glue` | `~glue` (§2) |
| `Hide` | порт, не названный в `~face` |
| `Restrict` | объём в плоскости `ext_P`: плоскость — параметр вычисления |
| `Reify` | не нужен: склейка уже вхождение |
| `Derive` | вычисление объёма и механизм заметности — операции машины |
| `Metaedge` | не операция: связь, порт которой указывает на связь |

Последствия (А): пять операций, три — частные случаи склейки; риск, что
`Reify` создаст второй вид сущности. (Б): `Derive` смешивает построение и
вычисление. (В): одна операция; всё построенное — вхождение.
**Позиция [помощник]:** (В) (вопрос 11).

### 11.2. Оси координат сущности и контекстные оси плоскости

(А) одно пространство: источник, отображение — оси портов, плоскость —
окрестность по ним; (Б) два пространства: понятия отдельно, контексты —
именованные подграфы. (А) выполняет решение 27 буквально и даёт одно
пересечение плоскостей; (Б) требует моста. **Позиция [помощник]:** (А)
(вопрос 12).

### 12.3. Заметность в мире родства (Ф2)

Вопрос `salient`, дано — `parent`, `sex`; семейства кусков нет.

**Шаг 1.** Структуры: `P = parent[alter→ego]` (от родителя к ребёнку),

`G = ~ground[claim→source]` (§7.1).

**Шаг 2.** Самоприложение:

| Структура | Семейство | Исход |
| --- | --- | --- |
| `P` | `P` — 7 пар; `P²` — (ann, fay), (ann, gus), (bob, fay), (bob, gus); `P³` — пусто | **цепь**: два члена, `P ∧ P² = ∅`, `P ∧ ~id = ∅`, `P² ∧ ~id = ∅` → ось цепи `A = ~axis.chain(parent, alter, ego)`; постоянная мира для `P` — два члена |
| `P⁻` | то же в обратную сторону | та же ось, обращённая; отдельной оси нет |
| `E₁ = P ; P⁻` | пары родителей с общим ребёнком | **классы** {ann, bob}, {cat}, {dan, eve} → `~axis.class(parent, alter, ego)` |
| `E₂ = P⁻ ; P` | пары детей с общим родителем | **классы** {cat, dan}, {fay}, {gus} → `~axis.class(parent, ego, alter)` |
| `X` | `X² = ∅` | один член — не цепь (структура себя не встречает) |
| `E₃ = X ; X⁻` | пары носителей с одним значением | **классы** {ann, cat, eve, fay}, {bob, dan, gus}; `X⁻ ; X = {(f, f), (m, m)} ⊆ ~id` → классы помечены значениями: носители получают `(~axis.port(sex, value), ∅)`: `ann, cat, eve, fay ↦ f`; `bob, dan, gus ↦ m` (§4.3). Ниже эта ось — `S` |
| `G ; G⁻` | утверждения с одним источником | **классы** с меткой: каждое утверждение — из `s1` → ключ `(Src, ∅) = s1`, `Src = ~axis.port(~ground, source)` |

Сгущений (исход «возврат») нет, поэтому шага 3 в этом мире нет. Все оси
закреплены (шаг 5): семейства пройдены до конца. Основание —
`~defeasible`. Две оси классов (`E₁`, `E₂`) — закреплённое, которое
машина показывает без имени; читателю они видны как «пары родителей» и
«братья-сёстры», машине — нет.

**Проекция `A` на носителей** (§4.4): одна часть {ann, bob, cat, dan, eve,
fay, gus}, опора `ann ↦ 0`; обход по записям `parent(alter: …, ego: …)` в
байтовом порядке:

| Носитель | Положение | Путь-основание |
| --- | --- | --- |
| ann | 0 | — |
| cat | +1 | parent(cat, ann) |
| dan | +1 | parent(dan, ann) |
| bob | 0 | parent(cat, ann), parent(cat, bob) |
| fay | +2 | parent(cat, ann), parent(fay, cat) |
| gus | +2 | parent(dan, ann), parent(gus, dan) |
| eve | +1 | parent(dan, ann), parent(gus, dan), parent(gus, eve) |

`parent(dan, bob)`: `dan +1`, `bob 0` — совместимо.

### 12.4. «Поколение» — закон приложения

Ось `A` получена не образцом «постоянный сдвиг», а исходом самоприложения
`P`: `P` встречает сама себя (через `cat`, `dan`), `P²` — новая структура,
не совпадающая ни с `P`, ни с тождеством, `P³` пуст. Положения понятий на
`A` — число шагов приложения: `P ↦ +1`, `P² ↦ +2`, `P⁻ ↦ −1`; закон
приложения «`Pᵃ ; Pᵇ = Pᵃ⁺ᵇ`» и есть сумма на оси [решение 26]. Тот же шаг на
переходе мира устойчивости не даёт цепи (§13.3).

### 12.5. Склейки, объёмы, точки (Ф2)

```

mother′ = ~glue(sex, parent; I: (1.who, 2.alter); B: (1.value, f);
```

Основания объёмов — `~checked`; точек склеек — `~defeasible` (стоят на

### 12.6. Операции над точками (Ф2)

- `diff(mother, parent) = {Δ: без изменения, (S, alter): ∅ ↦ f}`.
  `realize`: цель `{(S, alter): f}`, роли `{alter}`; (а) — нет вхождений с
  этими ролями; (б1) — `~glue(sex; B: (1.value, f); F: alter ← 1.who)`:
  «женщина», перенесённая на порт `alter`. `sum(parent, d) =
  point(mother)` — «родитель + женщина@alter = мать».
- `diff(gp, parent) = {Δ: +1}`; `realize`: (а) — `parent`, `pp`; (б2) —
  одночленная склейка `~glue(parent; F: alter ← 1.alter, ego ← 1.ego)`

- `shift(father, mother, gf)`: `mother − father = {Δ: без изменения,
  (S, alter): m ↦ f}`; `gf + … = {Δ: +2, (S, alter): f}`; `realize`: (а) —

- `dist(mother, gf) = {Δ: 1, (S, alter): различны}`;
  `nest`: `gm ⊑ gp`, `mother ⊑ parent`, `mother ⋢ gp`.

## 13. Прогон на бумаге: устойчивость и контроль

Все числа сверены вычислением вне ядра (скрипт помощника, ограниченный по
памяти и времени; это проверка бумаги, не часть машины).

### 13.1. Мир

Точки `c0 … c3`. Соседство — цикл: `nb(a: cᵢ, b: cⱼ)`, `j = i ± 1 (mod 4)`,
восемь вхождений. **Соседство задано руками** (вопрос 18). Переход — все
256 отображений точек в себя, без отбора [принцип 6]: атомы `tXYZW`
(`T(c0) = cX`, …), вхождения `step(map: t, from: cᵢ, to: cⱼ)` — 1024.
Порождается загрузчиком в `tools/`.

### 13.2. Приём пакета

Оси портов `nb.a`, `nb.b`, `step.map`, `step.from`, `step.to`. Вопрос
`salient`: дано — `nb`, `step`; семейство кусков — `~axis.port(step, map)`:
кусок `t` — плоскость `{(~axis.port(step, map), ∅): t}`; в ней «внутри» —
четыре вхождения `step` куска, «охватывают» — восемь `nb`.

### 13.3. Шаги 1–2: структуры и сгущения

- Структуры: `N = nb[a→b]`; `nb[b→a]` равна `N` по объёму во всех кусках →
  закон равенства, одна структура. `T = step[from→to]`, `U = T⁻` (порт `map`
  задаёт семейство и в структуры не входит).
- `N`: `N² = ~id ∪ {противоположные}`, `N³ = N` → **возврат**: `N` —
  сгущение, `F(N) = {N, N²}`, одинаково во всех кусках; постоянная мира для
  `N` — два члена.
- `N ; N⁻ = N²`: `E ; E = E`, симметрично, содержит `~id` → **классы**
  {c0, c2}, {c1, c3} → `~axis.class(nb, a, b)`, без имени.
- `T`: семейство самоприложения разное в разных кусках (у каждого
  отображения свой цикл или неподвижная точка) → не сгущение; цепи нет ни
  в одном куске (каждое семейство приходит к повтору, а не к пустому).

### 13.4. Шаги 3–5: сшивка, притирка, закрепление (Ф4)

**Сшивка.** `C′ ∈ {N, N²}`, формы `A C′ B` с `A, B ∈ {T, U, —}` (8 форм),
`Y ∈ {N, N²}`, два направления: `2 · 8 · 2 · 2 = 64` закона-кандидата.
Других выражений нет.

**Выполнение по кускам.** Во всех 256 кусках — 0 кандидатов; ни в одном —
13; разбивают семейство — 51.

**Притирка.** Куски прикладываются друг к другу внутри мира: «сначала
`tA`, потом `tB`» — снова одно из 256 отображений (постоянная мира для
семейства — 1). Из 51 разбивающего кандидата проходят «переживает
приложение» и «три независимые плиты» 35 законов; множеств `H` — шесть:

| `H` (кусков) | Законов | Представитель | Вне ядра читается как |
| --- | --- | --- | --- |
| 4 | 4 | `U N ⊇ N` | симметрии цикла, оставляющие каждую точку на месте или переводящие в противоположную |
| 8 | 6 | `U N T ⊇ N` | симметрии цикла (повороты и отражения) |
| 16 | 12 | `U N ⊆ N` | каждая точка остаётся на месте или переходит в противоположную |
| **32** | **7** | **`U N T ⊆ N`** | **соседи остаются соседями** |
| 32 | 3 | `U N T ⊆ N²` | образы соседей совпадают или противоположны |
| 64 | 3 | `T N U ⊆ N` | несоседи не становятся соседями |

Законы множества «соседи остаются соседями»: `U N T ⊆ N`, `U N U ⊆ N`,
`T N T ⊆ N`, `N ⊆ T N U`, `U N² U ⊆ N²`, `T N² T ⊆ N²`, `T N² U ⊆ N²`.
Вложения по объёму: 4 ⊂ 8 ⊂ 32ˢ ⊂ 64; 4 ⊂ 16 ⊂ 32ˢ; 32ᵖ ⊂ 64 (ˢ — «соседи
остаются», ᵖ — «совпадают или противоположны»). Пример трёх независимых
плит для `U N T ⊆ N`: `t0101`, `t0103`, `t0121`.

**Повтор перехода** входит в притирку: `tA`, потом `tA` — тоже кусок, и он
в `H`. Отдельного вывода следствия не нужно.

**Закрепление.** Все шесть законов закрепляются (шаг 5); каждый даёт ось
закона `~axis.law(L, step.map)`; для «соседи остаются соседями» — 32
`~holds`, 224 `~fails`. Ключи осей портов не меняются. Свидетель для
куска вне `H` — наименьший кортеж `ext(U N T) \ ext(N)`.

**Что это значит для цели Ф4.** Машина выделяет «соседи остаются
соседями» — закрепляет, без имени, — но вместе с пятью другими законами
того же мира. Ровно один закон не выделяется (Д2, вопрос 1).

### 13.5. Сравнение с прежним перебором

Перебор всех слов длины ≤ 3 над четырьмя буквами (85 слов, 7140 пар)
давал 5625 разбивающих законов на 113 множествах кусков без выделения.
Механизм §8.2 строит 64 кандидата от одного сгущения и закрепляет 35 на 6
множествах. Предела длины нет: длины слов (до 4) заданы семейством `F(N)`.

### 13.6. Контроль от псевдо-закрепления [принцип 6]

Миры той же формы, порождённые загрузчиком с seed 1–20 (машина их не
различает от настоящего):

- **Контроль А** — перемешаны и концы `nb`, и цели `to` всех 1024 `step`:
  в 20 из 20 миров куски не прикладываются друг к другу внутри мира
  (приложение двух отображений часто не совпадает ни с одним куском) →
  постоянная не определена → **не закреплено ничего**, пробел
  `pieces-do-not-fit`.
- **Контроль Б** — перемешаны только концы `nb`, переходы — все 256: в 18
  из 20 миров `N′` не возвращается к себе (нет сгущения) → **не
  закреплено ничего**. В двух мирах сгущение есть, и оба объяснимы:
  seed 20 — перемешивание восстановило ровно цикл (`N′ = N`), закреплены
  те же 6 множеств; seed 5 — `N′` = «та же точка или противоположная»

## 16. Вопросы автору

Коротко: что выбирается и что изменится при другом выборе. У каждого —
позиция помощника.

**Механизм заметности (решение 31)**

1. **Шесть законов или один.** Машина закрепляет шесть законов мира
   устойчивости; «соседи остаются соседями» — один из них. Если цель Ф4 —
   ровно один, нужен ещё один шаг отбора, и его трудно придумать, не зная
   ответа. *Позиция:* шесть — честный результат, все шесть — настоящие
   законы этого мира; цель Ф4 считать выполненной, если среди
   закреплённого есть искомый.
2. **Что такое независимый кусок.** Сейчас: плоскость семейства (одно
   отображение), а без семейства — шаг самоприложения. Другой выбор
   (например, половины наблюдений) дал бы другие проверки. *Позиция:*
   оставить так.
3. **Три плиты.** Закон должен выполняться хотя бы на трёх кусках, ни один
   из которых не получается из другого повтором. Без этого условия
   закрепились бы законы, держащиеся на одном куске. *Позиция:* оставить
   три — это прямое прочтение «трёх плит».
4. **С чего начинается поиск.** Сейчас: структура, которая воспроизводит
   себя (возвращается к себе), и к ней прикладывается другая структура по
   одному разу с каждой стороны. Больше приложений — больше кандидатов и
   ближе к перебору. *Позиция:* по одному разу; повтор уже проверяется
   притиркой.
5. **Постоянная мира.** Сейчас: сколько шагов самоприложения мир делает
   до повтора или пустоты, и прикладываются ли куски друг к другу внутри
   мира. Иначе пришлось бы назначать число. *Позиция:* так.
6. **Три исхода самоприложения** (цепь — ось с порядком, классы — ось без
   порядка, возврат — сгущение). Это одна операция и три её результата, но
   их выбрал помощник. *Позиция:* оставить; если появится четвёртый исход —
   добавлять только по слову автора.

**Представление**

7. **Целые шаги.** Ось цепи ставит «+1 за шаг», реализация строит слово из
   `k` букв — это счёт шагов. Если это «число мира», ось цепи надо хранить
   иначе. *Позиция:* это представление машины: целое не становится
   вхождением; но сравнивать «на сколько дальше» в ответах нельзя.
8. **Запись положения** — точная двоичная дробь с 64-битными знаками.
   Другая запись изменила бы раскладку, но не смысл. *Позиция:* так.
9. **Разбиение данных на пакеты.** Записанные положения зависят от того,
   в каком порядке пришли пакеты; ответы — нет. Требовать одинаковых
   записей — значит перенумеровывать. *Позиция:* одинаковы ответы, не
   записи; перестройка — только явной операцией.
10. **Плоскость.** Несколько ключей сворачиваются «эллипсоидом»; если у
    вхождения нет ключа плоскости, оно её «охватывает»; служебные
    вхождения лежат там же, где данные, на которые они указывают.
    *Позиция:* так; миры Ф2–Ф4 от свёртки не зависят.

**Устройство машины**

11. **Одна операция построения — склейка** вместо пяти прежних имён.
    Содержание прежних операций в архиве не читалось. *Позиция:* одной
    достаточно для обоих миров; открывать ли архив, чтобы сверить, —
    решение автора.
12. **Одно пространство для понятий и контекстов** (источник, отображение
    — такие же оси). Иначе понадобились бы два вида пересечения плоскостей.
    *Позиция:* одно.
13. **Закрытый список вопросов и правило ветвей ответа** (§9.2–9.3).
    Новое искомое — правка спецификации. *Позиция:* так.
14. **Метка источника** — единственный служебный закон, к которому
    применяется механизм; утверждение из двух источников пока не
    размещается (Д4). *Позиция:* дописать правило до Ф3, если такие данные
    появятся.
15. **Тождество по записи.** Две одинаковые записи — одно вхождение, даже
    если это два одинаковых события из одного источника; чтобы различать
    события, мир даёт им различающий порт. *Позиция:* так; иначе вывод
    зависел бы от порядка входа.
16. **Точка склейки считается по правилу**, а не по объёму; основание
    вывода — по слабейшей посылке. *Позиция:* так.
17. **Разность, сумма и реализация** (§5.3–5.8): подстановка на осях без
    порядка, реализация выдаёт и найденные, и построенные склейки.
    *Позиция:* так.

**Миры и приёмка**

18. **Миры заданы руками.** Состав семьи в мире родства и цикл из четырёх
    точек в мире устойчивости выбраны помощником; механизм составлен при
    известном ответе (Д11). *Позиция:* до приёмки Ф4 прогнать механизм
    на мирах, которых помощник не видел (другие циклы, неотобранное
    соседство, другая семья).
19. **Вставка вглубь не проверяется мирами** (Д1). *Позиция:* добавить
    третий мир (H77).

## 17. Звёзды: с чем сверено и чем машина отличается

Звёзды — только сверка [принцип 4, принцип 5].

| Звезда | Где похоже | Чем отличается / что пока не отличается |
| --- | --- | --- |
| Конъюнктивный запрос | `~glue` (§2) | Склейка — вхождение с точкой и законами; объём зависит от плоскости. По вычислению объёма **не отличается**. |
| Исчисление отношений Тарского | приложение, обращение, конъюнкция, включения (§2.4, §8.1) | Нет дополнения и объединения; законы — по кускам, а не тождества алгебры; поиск идёт от сгущений, а не по алгебре. |
| Степени отношения, «индекс и период» | самоприложение `X, X², …` до повтора (§8.2 шаг 2) | Используется не для вычисления периода, а как чтение исхода (цепь, возврат, классы) и как постоянная мира. |
| Разбиение по ядру отображения / функциональная зависимость | исход «классы» и метки (§4.3) | Это исход общего шага, а не отдельная проверка; отменяем и локализуется. |
| Потенциал на графе | проекция цепи на носителей (§4.4) | Ось берётся из самоприложения, проекция лишь ставит носителей; опровержение — нарушение цепи, локально. |
| Эндоморфизмы графа, моноид | `U N T ⊆ N`, замкнутость `H` под приложением (§8.2 шаги 3–4) | Машина не знает понятия «эндоморфизм»; формы сшивки общие для любого сгущения. Замкнутость **не отличается** от замкнутости подмоноида. |
| Метод трёх плит (Уитворт) | условие трёх независимых кусков | Плиты — куски мира, «ровно» — закон; плоскость эталона нет. |
| Перекрёстная проверка, перестановочный тест | контрольные миры §13.6 | Только в приёмке; машина не перемешивает и порог по контролю не считает. |
| Таблицы | объём — множество кортежей | Только способ перечислить объём. |
| Дробная индексация | вставка между соседями (§3.3) | Положение складывается и вычитается точно. |
| Эллипсоид | проверка плоскости (§6.3) | Нестрогая граница, «охватывает», служебные вхождения по опоре. |
| λ-исчисление | — | Не используется [решение 10]. |
